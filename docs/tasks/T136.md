# T136 書類の紙を作ったあとの見直し（刷る前に、おかしい所を一覧にして直せるように）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T101・T111・T120・T131 の頼み文と進み、評価の 3 回目の報告 docs/progress/eval-r3-findings.md、docs/DECISIONS.md「書類」、lib/forms（紙を作る所・原本に重ねた紙・確かめの画面）、lib/claude（askJson・仮名化の門・用途とモデル・1 日の上限）、tools/eval/forms を読む。

## 意図（なぜこの作業か）

AI で欄を読み、台帳の値を置いた紙（元の様式の上に値を置く紙 T86、原本の枠の紙 T101）は、そのまま刷ると字の重なり・空いた欄・違う欄への書き込みが残ることがある（評価の 3 回目の実在の様式で見えた）。紙を 1 回作ったら見直しを通し、ケアマネが刷る前に直せるようにする。

見直しで直せそうな所が見つかったら、まず今の紙を画面に出し、その欄に「再考中」の印を付けて、その欄だけを自動でもう 1 回やり直す（読み取り・置き方をその欄に絞る）。やり直したあとにもう一度見直し、それでも残った所だけをケアマネの見直しの一覧に出す。やり直しの前と後は記録に残す。

## 作る物

1. **決まりの見直し**（コード、AI なし）。紙の画面を開くたびに数える:
   - 置けなかった欄（場所の無い欄の値）、台帳に値が無くて空いた欄
   - 印刷の字との重なり（置いた字どうし、選ぶ欄の □、印刷の字の位置があればその字）、枠からのはみ出し、字の大きさが下限
   - 別紙の印と中身の食い違い
   - 本人の署名・同意の欄（ケアマネが埋めない所）に字が入った、本人が書く欄の残り
   - 同じ値が 2 つの欄に入った
   - 日付の形（元号の □ と年月日の部品がある欄に 1 つの字で置いた、元号と年月日の範囲）
   - 紙に伏字・仮の言い方（（氏名）（町名）（電話）など）が出ている
   - T133（同時に動く）が紙の置き方と「重なり」「台帳あり空欄」の数を作っている。その結果を読む 1 つの関数にする（docs/progress/t133.md を読み、無ければ自分の関数を作って取り込みでそろえる）
2. **AI の見直し**（絵を見る）: 刷る紙の頁の絵を Claude に見せ、置いた値の一覧（欄の名前と値）と見比べて「違う欄に入っている・読めない・欄の名前と中身が合わない・伏字が出ている」を挙げてもらう。
   - 名前・住所・電話・生年月日は絵の上で黒く塗ってから送る（今の取り込みの塗りの仕組みを使う。塗れなければ送らない）。値の一覧も仮名化の門を通す
   - 塗った欄は台帳の本当の値で置いてある前提で、決まりの見直しの側で確かめる。AI には塗った欄を「空いている」「読めない」と挙げさせない（挙げても使わない）
   - 答えは決まった形（欄・どこが・なぜ）に縛り、医療の判断を書かせない
   - モデルは費用と待ちを見て選び（用途の表に足す）、1 日の上限に数える。紙を作るたびに自動で回すか、ボタンで回すかは、費用の見込みを数えて決め、docs/DECISIONS.md に案として
3. **再考**（自動のやり直し）: 見直しで直せそうな所（違う欄・置けなかった・重なり・はみ出し・日付の部品）は、その欄に「再考中」の印を付け、その欄だけを読み直して置き直し、もう一度見直す。回数の上限は 2 回ほどで、費用を数えて決める。やり直しの前と後（欄・何が変わったか）を記録に残す。直した欄も AI の印つきで一覧に出し、戻せる形にする
4. **見直しの一覧の画面**: 紙の画面の上に「見直し N 件」。押すと一覧、行を押すとその欄へ（T135 が紙の上で直接入れる所を作っているので、そこへ送る口だけ。docs/progress/t135.md を読む）。直したら見直しを回し直す。全部見て「確認済」にしないと、刷る所で一言出る（止めはしない）
5. **評価の台**（tools/eval/forms）: 決まりの見直しの数と、AI の見直しが偽の答えで動くことを足す（本物の回は別の評価の作業者がする）。テスト。PC の幅で画面の絵
