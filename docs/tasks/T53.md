# T53 仮想モードの結末を AI が決める形に（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md`（何を作っているか・越えない線・地図・進め方）→ `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）

T50 の仮想モードでは、架空の人の結末（オブラートに包んだ生き死に）を、コード（lib/drill/outcome.ts。時計が切れるまでに助けが届かなかった人）が決め、Opus は 1 文に言い換えるだけにした。決めたこと（docs/DECISIONS.md「訓練」）: 仮想モードでは、架空の人の結末も AI が決める。訓練の架空の人の状態はシナリオ上の事実で、本物の人への判断ではない。仮想モードの狙いは「災害は固定の出来事ばかりではない」なので、結末も世界の流れの中で AI が決める方が筋に合う。

線: これは **訓練の仮想モードの架空の人だけ**。固定の筋（大雨・地震・10 分版）と、発災時の本物の画面（色と連絡の順番はルールの表だけ）には一切持ち込まない。

## 作る物

1. **世界（Managed Agents の部屋と 1 回呼び）が結末を決める**: lib/drill/world-room.ts・world-oneshot.ts の WORLD_SYSTEM と WorldStepSchema の farewells を、「コードが挙げた人の言い換え」から「世界が決めた結末」に変える。入力には今までどおり各人の時計の残り・超過、届いたケアマネの手（通話・到着・手配・受入）、本人役の最後の様子を渡し、世界はそれを見て「この刻みで結末を迎えた人」を 0〜N 人決め、仮名ごとに { target, text（60 字まで）, reason（なぜそうなったかの世界の事実、80 字まで） } を返す。理由は街と物の事実（「停電が 6 時間続き、電池が切れた」「道が通れず誰も着かなかった」）で書かせ、診断・病名・薬の量・医療の助言は書かせない（今の決まりのまま）。
2. **守り**（コード）: 知らない仮名・もう結末の人・参加者でない人は捨てる。禁じる語（死亡・亡くな・死ん・関連死・遺体・息を引き取 ほか、今の一覧）があれば固定の文「A さんには、この時間までに助けが届きませんでした」に。1 刻みに結末の人数の上限（たとえば 2 人）。結末の人は以後、本人役を呼ばず・信号を出さず・着信も鳴らない（今のまま）。画面の「結末」の印と 1 文には AI の印（理由も AI の印つきで行の詳細に）。
3. **部屋が落ちたとき**: 1 回呼びに落ちたら、1 回呼びも同じく結末を決める。1 回呼びも落ちたら、結末はその刻みは出さない（コードで代わりに決めない。AI が決める形に統一。落ちた刻みは「世界 停止」の印のまま）。lib/drill/outcome.ts の「時計が切れた人」の計算は、世界への入力（ヒント）と講評の数字として残す。
4. **講評との数**: 講評（lib/drill/score.ts・review.ts）の「条件に達した人」は時計の計算のまま残し、仮想モードの訓練記録と講評には「結末（AI の筋書き）N 人」と「条件に達した人（時計の計算）M 人」を別の行で出す（同じ数に見せかけない。どちらが何かを 2〜4 字の見出しで）。採点の終わりは 72 時間で切る（docs/DECISIONS.md「訓練」）。
5. **テスト**: 世界が決めた結末が当たる（偽の部屋・偽の 1 回呼び）、捨てる物、禁じる語の置き換え、上限、落ちたとき結末を出さない、結末の人が以後動かない、講評に 2 つの数が別の行で出る、固定の筋の動きとテストが変わらない、発災時（lib/triage）に結末が入らない（型で）。
6. **docs**: docs/CLAUDE_CODE.md と docs/JUDGING.md の仮想モードの行（「結末は時計の計算」→「結末も世界の部屋が決める。訓練の架空の人だけ」）、docs/progress/t53.md。

## 終わりの形

- 仮想で始めると、世界が結末を決めた人に「結末」の印と和らげた 1 文（AI の印）、行の詳細に理由が出る。固定の筋は前と同じ
- `npm test`・`npm run typecheck` が通る。PR を integrate/t11-t12 宛に
