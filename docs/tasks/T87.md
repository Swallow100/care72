# T87 ヘッダーの「様式」を「書類」に、書類を選んで出す画面、不備の見える化

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。

## 意図（なぜこの作業か）

ヘッダーの「様式」は様式 9 と様式対応だけを出し、計画書（松山市・内閣府の様式例・事業所が足した自治体の様式）は本人のページから、事業所の「使用様式」で選んだ 1 つしか出せない。計画書はケアマネが一番出す書類なので、ヘッダーから書類の種類と様式を選んで出せるようにする。また、紙面の空欄は「未確認」と刷られるが、出す前にどこが足りないかの数や一覧が無く、刷ってから気付く。別の自治体の様式は、様式対応（T45）と T86（元の様式の上に値を置く紙、PR #93・#96）で足せるが、入口が「様式対応」の言葉だけで分かりにくい。

## 作る物

1. **ヘッダーの名前**: components/NavLinks.tsx の「様式」を「書類」に。中のタブ（components/ui/Tabs.tsx）は「書類」（新しい一覧）・「様式9」・「様式追加」（今の様式対応の画面。名前だけ替える。URL は今のまま）
2. **書類の一覧（新しい画面、例 /forms）**: lib/forms/catalog.ts の書類を並べる。計画書は使える様式を全部（松山市・内閣府の様式例・事業所の確かめた対応表。listPlanForms）出し、使用様式は「既定」の印だけにする（選ぶのは今のまま事業所の画面）。行ごとに:
   - 出す相手を選ぶ（担当の利用者から 1 人、または全員の一括印刷。一括は app/caseload/own-sheets の作りに合わせる）
   - 開くと今の紙面のページ（/people/[id]/forms/matsuyama・mapped/[mappingId] ほか）。様式の行は ?form= のように様式を指定できるようにし、使用様式でない様式でも出せる
   - 同意で出せない書類（医療要約など、lib/consent/scope.ts）は今と同じ扱いで、一覧でも出せない理由を出す
3. **不備の見える化**: 紙面が「未確認」と刷る欄（lib/forms/matsuyama.ts の BLANK.unconfirmed、対応表の紙も同じ）を数える関数を lib/forms に足し、
   - 一覧の人ごとの行に「未確認 N」
   - 紙面の画面の上の帯（印刷で消える所。components/forms/FormAbout.tsx か PaperBar）に「未確認 N」と、押すと欄の名前の一覧（例: 「かかりつけ医・避難先 2・近親者の電話」）。印刷には出さない
   - 手で書く欄（番号・自署・代理人・市受付印）は数えない（紙面でも空けている欄）
4. **別の自治体の様式を足す入口**: 書類の一覧の計画書の段に「様式追加」（今の様式対応へ）。T86 の元の様式の上に値を置く紙ができていれば、足した様式もそのまま一覧に並ぶ
5. **テスト**: 未確認を数える関数（松山市・対応表・内閣府の様式例、手で書く欄を数えない）、一覧の様式の並び（使用様式の印・確かめていない対応表は出さない）、?form= の様式の指定（ほかの事業所の対応表は 404）。`npm test`・`npm run typecheck`。画面は 375・768・1280、ライトとダークで、一覧・紙面の帯・印刷のプレビュー（帯が消える）を見る

紙面の字・欄・書体（T47・T85）は変えない。未確認の数や一覧は紙に刷らない。使用様式の保存（事業所の画面）は変えない。T86 の作業者が触っているファイル（lib/forms/mapping.ts・components/forms/mapping/・OverlaySheet）は、T86 の取り込みのあとに読むだけにする。
