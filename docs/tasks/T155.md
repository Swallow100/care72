# T155 訓練の通話を会話に（着信と発信を同じ「通話」の画面に、文字でも声でも）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。本人役の通話の往復（docs/tasks/T93.md、lib/drill/talk.ts・dialogue.ts・components/drill/TalkBox.tsx）、着信に通話の中で返す（T127、lib/drill/incoming-talk.ts・components/drill/IncomingCall.tsx）、発災時の声の聞き取りの会話（T137・T137b、lib/speech/dictation.ts の Web Speech）と、その進み（docs/progress/t93.md・t127.md・t137.md・t137b.md）を読む。

## 意図（なぜこの作業か）

訓練の本人役（Haiku）から電話が掛かってきた時と、こちらから電話を掛けた時に、実際の電話のように話を続けられるようにする。今は次の形で、どちらも電話の会話から離れている。

- 着信は問いの候補 7 つと自由の 1 文（60 字）で、1 回の通話に 3 回まで
- 外へ掛けた電話は対応の欄の結果の下にあり、問いの候補から選ぶ形が主。相手の返事に声が無い
- 声で答える道が無い（ケアマネは電話で話すのに、訓練では打つしかない）

線は前と同じ: 色と連絡順はルールの表（lib/triage）だけ。本人役の決まり・仮名化の門・想定の門（T125）・本人ごとの帳面（T130）を外さない。

## 作る物

### 1. 同じ「通話」の画面

- 着信と発信の両方を、同じ部品の通話の画面にする。相手の言葉（声と文字）と自分の言葉が会話の形で並ぶ
- こちらは文字を打つか、マイクで話して送る。話した声は文字にして欄に出し、送る前に直せる
- 問いの候補のボタンは補助として残す（着信は T127 の 7 つ、発信は T93 の 7 つ）
- 終話のボタン。外へ掛けた電話も、つながって話せる間は通話の画面を重ねて出す（早送りは止める）

### 2. 声の入力

- 文字起こしは発災時の聞き取り（T137）と同じブラウザの Web Speech（lib/speech/dictation.ts）を使う。使えない端末では文字だけ
- マイクの許可が無い・断られた時は文字だけで続ける（失敗の言葉を 1 つ出す）
- 声で入れた言葉は、送った行に「声」の印を残す（直した文でも、声で足した物なら印を付ける）

### 3. 会話の長さと時計

- 1 回の通話の往復の上限を 3 回から 8 回に（着信・発信とも）
- 往復ごとにケアマネの時計を進める。前の 1 回 2 分の決まりを、文の長さで 1〜3 分に（境目の字数は定数で 1 か所。docs/DECISIONS.md に案）
- AI の数え方は前と同じ（1 日の上限は askJson の ai_calls、1 訓練の上限は counts.call）。上限・鍵なし・失敗は固定の言葉
- 自由の文の長さの上限は、話した文が入るように少し広げる（定数で 1 か所）

### 4. 本人役と門

- 本人役の決まり（名前・住所・電話・病名・薬の量・医療の助言・「死亡」を言わない、想定と帳面に合う事だけ）と仮名化の門（伏せきれなければ断る）は今どおり
- 想定の門（T125 の gateWords）と帳面（T130 の言われた事を覚える）を、着信と発信の両方の往復に同じ所で通す（往復の 1 回の作り方を 1 か所に寄せる）
- 相手の声は Gemini TTS（作れなければ文字）。外へ掛けた電話の往復の行にも声を作る（文は D1 の記録から読む。画面から送られた文を読まない）

### 5. 残す所

- 経過・訓練記録の紙面・採点・講評に、会話の全部（自分の言葉と相手の言葉、声で入れた印）を残す
- 講評に渡す言葉は仮名化の門を通し、伏せきれない行は渡さない

### 6. テスト

- 偽の client・偽の TTS・偽のマイク（偽の SpeechRecognition）で: 8 往復と 9 回目の断り、文の長さで 1〜3 分、声の印の保存、着信の往復の想定の門、帳面、作り直しが保存と同じ、外へ掛けた電話の往復の声、紙・経過・採点・講評の会話、声の入力の下書き・直し・マイク不可
- PC の幅（1920・1536・1280）の絵をライトとダークで。375 は崩れないかだけ
