# T120 評価の 1 回目で見えた書類の AI の問題を直す（様式の読み取りの上限と時間切れ・入れる欄の取り違え・読めない入力・取りこぼしの見せ方・台の数え方）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。評価の 1 回目の報告 docs/progress/eval-r1-findings.md と数の表 eval-forms-r1.md、書類の評価の台 T107（docs/tasks/T107.md と進み）、T118・T119 の頼み文と進みを読む。生の記録はリポジトリの外（評価の回のフォルダ。読むだけで、中の架空の人の言葉を repo に写さない）。

## 意図（なぜこの作業か）

評価の 1 回目（本物の Claude、様式 33・入力 55）で、書類の AI に次の問題が見えた（番号は findings の番号）。

- 実在の様式の PDF 14 件のうち 12 件が読めない（#1）。様式の読み取り（Opus、出力の上限 16,000、待ち 180 秒）が、欄の多い様式で出力の上限に達して JSON が切れるか、時間切れになる。失敗の前に 122〜360 秒待たせる（#13）
- 入れる欄の取り違え（#8）: 移動手段が選ぶ欄（evacuation.transportKind）だけに入り補記（evacuation.transport）が空く、寝たきりが介護の欄でなく特記に入る。手書きの入力の外れ（#9）は医療機器・常用薬・連絡先の値
- 読めない入力（#3）: HEIC、4,000 字を超える書き起こし
- 様式の読み取りで 1 欄を台帳の項目なしにすると、その欄が全部の紙で空く（#11。同意の欄）
- 紙で空欄なのに未確認に数えない欄が多い（#10）
- 台の様式の id が同じ名前の PDF と Excel で重なる（#15）
- 元の様式が欄の中に「年 月 日」「− −」の空きを持つ欄に、値を丸ごと置いて印刷の字と重なる（埋めた紙を見て）

## 作る物

1. **様式の読み取りを返し切れる形に**（#1・#13）: 次の手から調べて選び、選んだ理由を進みに書く。頁ごとに分けて読む（並べて呼ぶ）、答えの形を短くする（欄の名前の繰り返しを減らす）、考える分（effort）の見直し、出力の上限の見直し、流して受ける（streaming）、途中までの答えを捨てずに続きを頼む。失敗して待たせるより、読めた頁から見せる。費用が増えすぎない形で、1 様式の見込み（費用と時間）を進みに
2. **入れる欄の取り違え**（#8・#9）: Claude に渡す欄の説明と形の決まりを直す。手書きの外れも渡し方（画像の前処理・欄の説明）で減らす。正解の表（T107 の正解）の側に案の所があれば正しい方に直し、どちらを直したかを進みに
3. **読めない入力**（#3）: HEIC を受け取る（ブラウザで JPEG に直す）。4,000 字を超える書き起こしを分けて読む（または上限の見直し）
4. **取りこぼしの見せ方**（#11）: 様式の読み取りで台帳の項目なしにした欄を、確かめの画面で目立たせ、手で割り当てられるように。取りこぼしの起きやすい欄の種類（同意など）が分かる形に
5. **紙の空欄の数え方**（#10）: T111 の決め（2 人目以降の空き枠は刷らず未確認に数えない）と台の数え方の食い違いかを確かめ、決めのとおりなら台を直す。決めと違う欄なら直す
6. **台の様式の id**（#15）: 同じ名前の PDF と Excel の id を分ける
7. **欄の中の空き**: 「年 月 日」「− −」のように元の様式が字の間に空きを持つ欄は、値を空きごとに分けて置く（読み取りで空きの場所を取るか、重ねる紙の側で分ける）
8. **テスト**（偽の client）: 大きな様式で頁ごとに読む、答えが途中で切れても読めた所を捨てない、HEIC、長い書き起こし、取り違えの欄、空きごとに分ける欄
9. **評価の台**: 直したあと、偽の client で `npm run eval:forms` を回して前と比べる（本物は回さない。本物の 2 回目は評価の作業者が回す）
