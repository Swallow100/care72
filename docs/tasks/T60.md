# T60 事業所の幅（災害の種類、担当の一括変更）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）

選べる物・自由度が低い所を洗い出す。事業所の画面の洗い出し:

- 災害の種類が平時・大雨・地震だけ（lib/db/types.ts の DISASTER_KINDS、lib/disaster/state.ts の DISASTER_KIND_LABELS）。四国で起きる台風・土砂・津波が選べない。
- 担当の付け替えが 1 行ずつ（app/office/page.tsx の担当の表と components/office/AssignForm.tsx）。ケアマネの退職・異動で 30 人を移すのに 30 回。

線: ルールの表（lib/triage）は災害の種類で分岐していない（入力は 今・発災・停電の始まり だけ。lib/disaster/state.ts の注）。表の行は増やさない。災害の種類で分岐する所は lib/map/side.ts の場面（大雨か地震かの 2 値）と lib/map/demo.ts の DemoScene だけ。lib/drill・components/drill/DamagePanel.tsx・lib/drill/director.ts・review.ts の heavy_rain / earthquake は訓練の想定の種類（scenarios.ts の DrillKind）で別物。触らない。

## 作る物

1. **災害の種類**: DISASTER_KINDS に typhoon（台風）・landslide（土砂）・tsunami（津波）・other（その他）。DISASTER_KIND_LABELS に言葉。既存の扱いへの写しは lib/disaster/state.ts に 1 つの表 `DISASTER_SCENE: Record<DisasterKind, "heavy_rain" | "earthquake" | null>`（大雨・台風・土砂 → heavy_rain〔警戒レベルが効く〕、地震・津波 → earthquake、その他と平時 → null）。lib/map/side.ts の場面と lib/map/demo.ts はこの表で引く（null は場面なし: 雨雲・震度の層を出さず、ピン・ハザード・避難所は今まで通り。DemoScene を null 許容に。全画面の地図 T46 も同じ）。警戒レベルの欄は heavy_rain の場面の種類で出す（今の出し方を確かめて同じに）。その他に自由記入は持たせない。ヘッダーの印・経過の 1 行（「災害モード 台風」）・事業所の画面の切替のボタン（ModeButton）は labels から出るので、並び（平時 → 大雨 → 台風 → 土砂 → 地震 → 津波 → その他）だけ。migration 0011: disaster_state.kind の CHECK（migrations/0001_init.sql の disaster_state）。事業所ごとに 1 行、子の表なし（`REFERENCES disaster_state` は無し）→ 建て直し（新しい表 → INSERT SELECT → DROP → RENAME。0006 が建て直しを避けた理由は当たらない）。lib/seed/demo.ts は heavy_rain のまま（変えない）。
2. **担当の一括変更**: 事業所の担当の表（app/office/page.tsx）の各行にチェック、見出しに「全選択」、担当ごとの選択（「この担当を全部」を担当の名前の横に 1 押しで）、表の上に帯「選択 N 人」＋移動先（components/ui/Select、ケアマネの一覧）＋「一括変更」（アプリ内の確認の窓: 名前は 6 行まで、超えたら「ほか N 件」〔docs/DECISIONS.md「画面」〕）。POST /office/people に action=assign_many（person を複数、to）。lib/office/http.ts の peoplePost と lib/office/people.ts に assignMany: 人ごとに assignPerson と同じ検査（事業所の中・移動先のケアマネ・今の担当が送ったときと違えば飛ばす）、1 つの batch、経過は既存の person_assigned を人数ぶん（OFFICE_TIMELINE_KINDS を増やさない: 0001 の CHECK の建て直しが要る）。戻り先に「変更 N 人・飛ばし M 人」。1 行ずつの AssignForm は残す。375 で押せる（チェックの列は 640 未満でも省かない。解除の列を省いた T55 の作りを見る。新しい部品は components/office/AssignMany.tsx）。
3. **テスト**: 種類の往復と migration 0011 の契約（CHECK と既存の行の写し）、場面の表（大雨・台風・土砂 → heavy_rain、地震・津波 → earthquake、その他 → null）、地図の側と右の面と全画面が null の場面で落ちない、ルールの表の結果が種類で変わらない（同じ入力で 7 種類とも同じ色・順・理由）、一括変更（N 人・飛ばし・権限・事業所の外・移動先が無い）、経過の行数、375 で押せる（headless Chrome で測る）。
4. **docs**: docs/progress/t60.md（Claude を使う所・使わない所を 1 行。この作業は Claude を呼ばない）、DECISIONS に案（足した種類と場面の表）。
