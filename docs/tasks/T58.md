# T58 担当一覧の幅（電話の「通話」と聞いた安否、絞込・検索、並びの向き）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）

選べる物・自由度が低い所を洗い出す。担当一覧の発災時の洗い出し:

- 電話の結果が「発信」「不通」だけ（lib/list/calls.ts の CALL_RESULTS）。「通じた」もメモも残せず、電話で本人や家族から「無事」と聞いても表の色が変わらない。訓練では、通話で聞いた安否を出どころ care_manager の信号として残し、表の色・順位を動かす形がもうある（docs/DECISIONS.md「訓練」、lib/drill/db.ts の heardStatements）。本番の画面にはその道が無い。
- 絞り込み・検索が無く、並びの向きも列ごとに固定（components/list/SortHeader.tsx の DESCENDING）。10 人なら困らないが、本運用の 30〜40 人の担当では困る。

線: 色と連絡順はルールの表（lib/triage）だけで決める。ケアマネが電話で聞いた「無事」は、人が確かめた事実として信号（source care_manager）に乗せ、色は表に任せる。順番変更（override）の形は使わない（表が悪くなるまで効き続けるので、期限の時計や要確認の黄を隠す）。

## 作る物

1. **電話の結果「通話」と聞いた安否**: CALL_RESULTS に connected（画面は「通話」）。行の詳細の連絡先の 2 行目に「通話」のボタン（「不通」の隣。無色）。押すと行の中に小さな欄が開く: 安否（「無事」「無事でない」「聞けず」の 3 つから 1 つ。選んだ印は枠と太字）、無事でないときだけ「けが」「動けない」の 2 つの確認（本人・家族が答えた事実と同じ列 injured・can_move に入る）、メモ（100 字まで、任意）、「保存」。
   - 保存は POST /api/caseload/call の body を広げる: `{ person, contact, result: "connected", heard?: { color: "green" | "red", injured?: boolean, canMove?: boolean }, memo?: string }`（lib/list/http.ts の callPost と lib/list/calls.ts の saveCall）。聞いた安否があれば 1 つの batch で signals に 1 行（id は UUID、person_id、drill_id NULL、color、source 'care_manager'、injured・can_move、occurred_at は今）と、経過の called の行（signal_id にその信号、payload に result・heard・memo）。安否が無ければ経過だけ。安否つきは災害モードの間だけ（平時は順番変更と同じ "normal" で断る。平時の「通話」だけは残せる）。
   - lib/signals/save.ts の saveSignal は書き手が本人・家族・支援者に限られるので通さず、lib/list/calls.ts に書く（訓練の heardStatements と同じ形）。表への効き方はそのまま: loadOfficeSignals（lib/disaster/triage.ts）が drill_id NULL の信号を全部読むので、care_manager の緑・赤は表が読む。理由は表の言葉のまま（「ケアマネが「無事」」。訓練の通話と同じ）。表（lib/triage）に行・言葉を足さない。
   - **無事が置き換えない物**（保存のときにサーバーで personDisaster を当てる。lib/list/override.ts の saveOverride と同じ道）: 今の表の行（baseColor の rule）が red_injury（本人・家族の答えの けが・動けない）なら、「無事」の信号は書かずに断る（error "injury"、画面は「至急維持」の 1 行。red_injury は本人・家族の答えでもケアマネが直した分類でも当たるので「答え」と言わない。なぜかは理由の欄にもう出ている。下げるなら理由つきの順番変更）。期限を過ぎた機器の時計（green_out_after_report → 赤）、透析先・配達の未確認（green_unchecked → 黄）、時計の半分（green_device_low・green_clock_half → 黄）は表がそのまま守るので、テストで縛るだけ。本人の報告を当てにしない印の人も、ケアマネの緑は本人の緑でないので表が使う（そのまま）。
   - メモは経過の payload に持ち、body（「電話 家族 娘 通話」）には入れない（body は要約や訓練で読み返す文。lib/list/calls.ts の注）。行の詳細の電話の記録の下に小さく出す。timeline_entries の payload を Claude（askJson の入力。要約 summary など）に渡す所が無いことを grep で確かめ、渡るなら pseudonymizeText を通すか外す。
   - 行の詳細の連絡先の 1 行目に距離（contacts.reach。近所・市内…。lib/labels.ts の CONTACT_REACH_LABELS）を出す（lib/list/detail.ts の DetailContact に reach。列は 0001 からあり、T57 が編集で入れられるようにする）。
2. **絞込と検索**: 担当一覧の表の上に絞込の帯（新しい components/list/FilterBar.tsx）: 色（発災時だけ。至急・要確認・不明・無事）、地区（台帳の町名）、医療の印（lib/labels.ts の DEPENDENCE_MARKS の区分）、氏名・カナの検索（部分一致）、「解除」。並び（sort）と同じく URL の query だけで持つ（`/?color=red&area=…&mark=oxygen&q=…`。lib/caseload.ts の caseloadHref に足し、読むのも同じ所。form は GET で、sort と open を hidden で持ち越す: 無いと絞った瞬間に右の本人のページが閉じ、並びが既定に戻る）。絞ると見出しの人数を「N / M 人」に。優先の番号（rank）は絞る前の番号のまま（表の順位を変えない）。上の人数（components/list/DisasterSummary.tsx の 至急 N など）を押すとその色で絞る。列の見出し（SortHeader）のリンクは今の絞込を持ち越す。平時の表・発災時の表・右に本人のページを開いた圧縮の一覧（app/page.tsx の CompactList）が同じ行の集合を見る。
3. **並びの向き**: 押している列をもう一度押すと向きが反転（URL に dir=asc|desc。既定は今の向き: 年齢・ハザード・状態は降順、ほかは昇順）。aria-sort を向きに合わせる。訓練の左の表（DisasterTable の slots.sortHref）は今まで通り。
4. **テスト**: 通話の保存（経過だけ・安否つき・平時の拒否・red_injury の拒否・範囲の外の連絡先）、care_manager の緑のあとに本人の赤 → 赤、緑のあとに機器の時計が切れる → 赤（green_out_after_report）、未確認の頼り先 → 黄、半分 → 黄、ケアマネの赤（けが）→ red_injury、Claude の分類が色・順を動かさない（今のテストのまま通る）、メモが body に入らない・Claude の入力に無い、絞込の読み方と filter と href、向きの反転と aria-sort、375 で通話の欄と絞込の帯が押せる（headless Chrome で測る）。
5. **docs**: docs/progress/t58.md（Claude を使う所・使わない所を 1 行）。migration 0009 は要らない見込み（SIGNAL_SOURCES に care_manager、TIMELINE_KINDS に called が既にあり、メモは payload）。要ったら 0009。

## 終わりの形

- 発災時の担当一覧で「通話」を押して「無事」を保存すると、その人の色と連絡順が表で変わる（赤 けが・動けないの人は変わらず「至急維持」）。絞込・検索・向きで一覧を扱える
- `npm test`・`npm run typecheck` が通る。PR を integrate/t11-t12 宛に
