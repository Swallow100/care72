# T97 医療班・行政のアカウントを作る道

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。

## 意図（なぜこの作業か）

本物の事業所をまっさらから始める流れ（tools/office/new-office.ts で事業所と最初の管理者 → 管理者が /office でケアマネ追加 → 利用者追加・担当）は、手元で通った。足りないのは避難所の医療班と行政のアカウント。今あるのは種の見本の固定のアカウントだけで、作る画面も道具も無い（DECISIONS 11/3 23:2x の問い 1「医療班・行政のアカウントを作る画面が無く」）。本物の事業所で使うと、受入一覧（/staff）を開ける人がいない。

医療班・行政のアカウントは事業所に属さない（accounts.office_id が NULL）。検索と避難所の一覧は事業所をまたぐ（lib/custody/search.ts。所属なしの人も入る）。なので誰が作れるかは、事業所の中のケアマネ追加より重い。

**先に決めること（問い）**: 作れるのは誰か。

- (a) 作者が端末の道具で作る（new-office.ts と同じ形。SQL のファイルとパスワードのハッシュ、初期パスワードは標準出力に 1 回）。自分で登録する画面を作らない決まり（README・DECISIONS 11/4 00:5x）のまま
- (b) 事業所の管理者が /office で作る（事業所をまたいで検索できる人を、1 つの事業所が増やせることになる）
- (c) 行政のアカウントが医療班のアカウントを作る（行政の画面が要る）

答えが来るまでは (a) で作る（決まりに合い、画面が要らない）。

## 作る物（(a) のとき）

1. **道具**: tools/office/new-staff.ts。`--role medical|government --login-id <ID> --display-name <名前>`。中身は new-office.ts に合わせる: 名前と ID の決まりは lib/office/forms.ts の parseStaffInput（名前 20 字・ID の形・judge と種の ID は断る）、初期パスワードは lib/office/staff.ts の generateInitialPassword、ハッシュは lib/auth/password.ts の hashPassword。書くのは SQL のファイルだけ（リポジトリの外、上書きしない）。終わりに打つ命令（`d1 execute care72 --remote --command=…`）を出す。--file は使わない（D1 の取り込みの道で DB が止まる）
2. **入ってから**: 作ったアカウントでログインし、受入一覧が開けること、自分のパスワードを変えられること（DECISIONS 11/4 00:0x の案「事業所の無いアカウントも自分のパスワードを変えられる」）。停止・再発行は道具の別の動き（`--disable`・`--reissue`）か、作者が SQL で。どちらにしたかを docs/progress/t97.md に
3. **README**: 「始め方」に、事業所（new-office.ts）と医療班・行政（new-staff.ts）を作るのは作者の道具、と 1 行ずつ
4. **テスト**: tools/office/new-office.test.ts と同じ形で、出す SQL（役・office_id が NULL・ハッシュ・平文が入らない）、断る ID、手元の D1 に入れてログインと /staff が開く所まで。`npm test`・`npm run typecheck`

## 触るファイル

tools/office/new-staff.ts・new-staff.test.ts、README.md、docs/progress/t97.md

## 守ること

本番の D1 に道具が直に書かない（打つのは作者）。初期パスワードをファイル・ログ・docs に書かない。医療班・行政の見える範囲（lib/auth/scope.ts・lib/custody/search.ts）は変えない。
