## 意図（なぜこの作業か）

訓練の本人役がうまく動かず、訓練自体もうまく回らない。監査で追うと、新しい事業所で訓練を始めると:

- 想定の表（lib/drill/scenarios.ts）の人ごとの行・出来事は全部 p-01〜p-10 を指し、新しい事業所では捨てられる（engine.ts の members の濾し）。表の行が無い人は、スマホで押せる人がいなければ本人役（Haiku）を呼ばず連絡なしのまま（persona.ts の createPersonaHook）。本人のスマホを「使える」にしない限り 72 時間灰色で、理由も出ない。
- 本人役の指示に「松山の言い方（「行かん」「〜けん」「〜じゃ」）でもよい」（persona.ts の PERSONA_SYSTEM の 4 と CALL_SYSTEM）。松山でない事業所で変。
- 仮想モードの街は架空の 8 町の決め打ち（lib/drill/area.ts の AREA_TOWNS）で、台帳の町名と合わない（world-apply.ts は町名で人を引く）。
- 1 日 200 回の上限（lib/claude/usage.ts）は開始のときだけ見る（lib/claude/gate.ts）。途中で当たると本人役も監督も印なしで黙る。担当 30 人なら 12 刻みで 360 回。
- 進行中の訓練は事業所に 1 つ（db.ts の startDrill）。放置がほかのケアマネの開始を止め、期限で閉じない。

線: この作業は Claude の指示（本人役・監督の文）を変えるが、本人役の決まり 6・7（名前・住所・電話を言わない、診断・判定・重症・病名・薬の量・助言を言わない）は変えない。色と連絡順（lib/triage）に触れない。**デモ事業所の 10 人の訓練（想定の表の固定の行・動画の筋〔小林の夫の電話など〕・種の終わった訓練 lib/seed/drill.ts・lib/triage/heavy-rain.test.ts）は 1 bit も変えない。**

## 作る物

1. **想定の表の一般の行（先に 1 commit）**: lib/drill/scenarios.ts の FixedTurn と WorldEvent の `person` に加えて、人を台帳の中身で選ぶ `who?: Pick`（新しい lib/drill/cast.ts）: `{ device: DeviceKind }`（機器）、`{ clock: ClockCategory }`（時計の区分。透析・インスリンなど）、`{ hazard: HazardKind; minDepthM?: number }`、`{ household: "alone" }`、`{ smartphone: "none" }`（本人も連絡先も押せない人）、`{ any: true }`（誰でも）。**デモ事業所の行は `person` のまま**で、`who` は「その行の人が参加者にいないとき」の代わりとして足す（同じ行に person と who を並べる。10 人のどの行が何を表しているかは scenarios.ts の各想定の頭の注〔1 山田 独居・けが、2 小林 呼吸器、3 田中 透析、4 佐藤 スマホなし、5 伊藤 道路、6 高橋 栄養剤 …〕から読む。地震の想定も同じ）。開始のとき（db.ts の startDrill）に `castScenario(scenario, participants, ledgers)` で行ごとに人を決める: person が参加者にいればそれ、いなければ who に合う参加者のうち、まだその想定で配られていない人をカナ順で（1 人に行が集まらないように。合う人がいなければ行を捨てる = 今の動き）。決めた配役は DrillState に `cast: Record<行の鍵, personId>` として持ち（drills.world の JSON に入るので表は変えない。行の鍵は `${hour}:${index}` のような決定的な物）、刻み（engine.ts の step）は cast で引いた person を使う。再開・再生（replayState）でも同じ。テスト: デモ事業所の 10 人では cast が全部 person と同じで、今のテストが全部そのまま通る（既存の drill.test.ts・score.test.ts・persona.test.ts・t59.test.ts・lib/seed の種の訓練）。新しい事業所（架空の 5 人: 呼吸器・透析・独居・スマホなし・ハザードなし）で大雨・地震・10 分版の行が当たり、本人役の入力（PersonaInput.fixed）に行が渡る。
2. **「押せる人なし」の印を開始の設定に**: 開始の設定（components/drill/StartButtons.tsx の参加者の一覧）の人ごとに、本人のスマホ「使える」でなく連絡先に has_smartphone が 1 の人もいないなら「押せる人なし」（lib/drill/persona.ts の reportersOf を使う。db.ts の caseloadForDrill が id と名前のほかに `canPress: boolean` を返す）。印は文字だけ（灰の文字。色の印にしない）。その人は本人役が呼ばれず、表の行が当たれば表の固定の安否になる（今の動き）。人数の横に「押せる人なし N 人」。本人のスマホ・連絡先のスマホを入れるのは T68（本人のページの編集）なので、ここでは入口のリンク「本人のページ」を名前に付けるだけ。
3. **方言の行を外す**: PERSONA_SYSTEM の 4 から「松山の言い方（…）でもよい」を外し「やさしい短い話し言葉で 1〜2 文。認知症の本人は話が噛み合わないことがある」に。CALL_SYSTEM の「松山の言い方でもよい」も外す。PERSONA_VIRTUAL も見て同じ語があれば外す。テスト（persona.test.ts に指示の文を見る物があれば直す）。
4. **仮想モードの街を台帳から**: lib/drill/area.ts に `areaOf(officeId, ledgers): Area`。**デモ事業所（DEMO_OFFICE_ID）は今の AREA_TOWNS・AREA_ROADS・AREA_SHELTERS・AREA_FACILITIES をそのまま返す**（lib/drill/virtual.test.ts が変わらない）。ほかの事業所は台帳の町名（basic.address.town。無い人は「町名なし」の 1 町にまとめる）ごとに町を作る: alias は 甲・乙・丙…（10 を超えたら 甲2…）、terrain は その町の人のハザード（flood の最大の depthM → floodM、landslide・tsunami の有無）から短い一言（「浸水 3 m の想定の低い土地」「裏に急な斜面」「海に近い」「想定なし」）、grid は 3 町ずつ「A 系統」「B 系統」…。架空の町を 1 つ足す（「高台」。避難所と福祉避難所の置き場。台帳に無い名前）。道路は町ごとに 1 本（「○地区の道」）と高台への坂道。施設は時計の depends_on（dialysis_center → 透析施設 1 つ、refrigeration → 冷蔵の要る薬局、delivery → 配達の拠点）で、頼る人がいる物だけ。町名と本人の結び付きはコードだけが持ち、部屋に見せるのは別名と地理の一言（今の注のとおり）。world-apply.ts は Area を引数で受ける形に（今の定数を直接読んでいる所を areaOf の結果に）。テスト: デモは今と同じ物、新しい事業所の 3 町で別名・地形・施設が作られ、部屋への文に町名が出ない（findLeaks）。
5. **上限の見込みと「停止」の印**: 
   - 開始前: `estimateDrillCalls(scenario, participants, pressable)`（lib/drill/estimate.ts）= 刻みの数 × (監督 1 + 本人役を呼ぶ人の数〔表の行があるか押せる人がいる人〕) + 講評 1 + 声（着信ごとに TTS 1 回。上限を同じ表で数えるので、着信の見込み = 本人役を呼ぶ人の数 × 刻み の半分と見積もる〔上限の側に倒す〕）。StartButtons に「見込み 約 N 回 / 残り M 回」（残りは lib/claude/gate.ts の drillGate と同じ値）。N > M なら「上限不足」の 1 語を赤の文字で出すが、**開始は止めない**（途中で当たったら 6 の印で分かる。止めると「残り 0 の開始」の今の決まりと二重になる）。
   - 途中: engine.ts の step で、本人役・監督・部屋の呼び出しが上限（lib/claude/errors.ts の AiLimitReached）で落ちたら、その刻みの Tick に `aiStopped: ("persona" | "director" | "world")[]` を持ち（drill_events の tick の JSON。表は変えない）、画面（components/drill の刻みの行。DrillBar か ActionLog の刻みの見出し）に「本人役 停止」「監督 停止」「世界 停止」の印（灰の文字。AI の印の横）。persona の hook は今 fixedTurns に落とすだけなので、上限だけを区別して刻みに伝える口（PersonaHook の戻りに印を足すか、hooks の文脈に「上限に当たった」を書く口）を作る。講評（review）が上限で作れないときは今の「AI 失敗」の扱いのまま。
6. **進行中をケアマネごとに・24 時間で自動中断**: db.ts の startDrill の「進行中は事業所に 1 つ」を **ケアマネごと**（`started_by` が同じ accountId、審査員は acct-judge。drills.started_by の列はある）に変える（本物の事業所で 2 人のケアマネが別々に訓練できる。審査員どうしは今までどおり 1 つを共有）。合わせて **24 時間**: 進行中（status running）で started_at から 24 時間過ぎた物は、開始・一覧（listDrills・runningDrillId）を読むときに `abandoned`（finished_at = 今、理由「24 時間」を world の JSON に）に変える（cron は使わない〔worker.ts は T72 が触る〕。読むときに済ませる）。中断の経過（drill_events）に 1 行「自動中断 24 時間」。画面の一覧の状態の言葉は「中断」のまま、行の詳細に「24 時間」。migration は要らない見込み（列はある）。要るなら 0019。
