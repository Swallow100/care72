# T31 Claude Code の使い方を作品の中に見せる（フック・Skill・サブエージェントの記録）

## 目的

Claude の使い方を、この作品では 3 つの面で示す。核の部分で Claude がどう使われているか、Claude Code を開発の中心に据えて何が可能になったか、モデルや機能（Skills・サブエージェント・MCP・フック）を目的に応じて使い分けているか。書くだけでは点は動かない。リポジトリの中で動いている形にする。

## 読む物

docs/DECISIONS.md「AI の使い所」。docs/SPEC.md の「提出物」の資料の段。CLAUDE.md。Claude Code の hooks・skills の公式の書き方（推測で書かない。`claude-code-guide` のエージェントか公式の文書で確かめる）。

## 作る物

- **フック**（`.claude/settings.json` の hooks、リポジトリに commit）: この作品の守りをフックで強制する。PreToolUse で Bash の命令を見て、ネットに出る wrangler（login・whoami・deploy・d1 create・r2 bucket create・secret put）、`.env`・`.dev.vars` を読む・書く命令、`git push --force`・`rebase`・`commit --amend` を止めて理由を返す。PostToolUse で `.ts`・`.tsx` を書いたら `npm run typecheck` を流す（遅ければ lint だけ）。フックの script は `tools/hooks/` に置き、テストを書く（止める命令・通す命令の一覧）
- **Skill**（`.claude/skills/`、リポジトリに commit）: 2 つ。`triage-rule`（ルールの表に行を足す手順: テストを先に → `lib/triage/index.ts` → `npm run docs:triage` → docs/DECISIONS.md に案として書く）と `task`（docs/tasks の作業の始め方: worktree・branch・PR・終わりの形）。どちらも SKILL.md に手順と確かめ方
- **サブエージェントの記録** `docs/CLAUDE_CODE.md`: この作品で Claude Code をどう使ったか。設計（Fable）と実装（Opus xhigh のサブエージェント）の分担、1 作業ずつの brief（docs/tasks）、テスト先行、文書をコードから生成、commit の履歴に残る時刻、2 つのアカウントの並行（worktree と PR）、フックで守りを強制、Skill で手順を固定。「何が可能になったか」を数字で（commit 数、テスト数、1 日で進んだ作業、人が書いた行とエージェントが書いた行）
- **モデルの使い分けの表**（docs/CLAUDE_CODE.md に）: 作品の中（Opus 5.5: 様式の読み取り・監督・採点、Sonnet 5.5: 台帳の入力・要約、Haiku 5.5: ペルソナ・分類）と開発の中（Fable: 設計と brief、Opus xhigh: 実装、Sonnet: 機械的な直し）。発災時に Claude を分類だけに留めた理由（HITL、ルールの表）も「目的に応じた使い分け」として書く
- README の「使った資料と方法」から docs/CLAUDE_CODE.md へ 1 行
- MCP: 使う物があれば書く（配信の確かめに Cloudflare の MCP を T27 で使うなら、そこで）。使っていない物は書かない

## 終わりの形

- `wrangler deploy` を Claude Code が打とうとするとフックが止めて理由を出す（手で確かめる）。`.dev.vars` を cat しようとしても止まる
- `/triage-rule`・`/task` の Skill が Claude Code の一覧に出る
- docs/CLAUDE_CODE.md が 1 ページで、数字と commit の hash で裏が取れる

## 触るファイル

.claude/settings.json、.claude/skills/、tools/hooks/、docs/CLAUDE_CODE.md、README.md（1 行）、docs/PROGRESS.md

## 守ること

フックで止める物の一覧は CLAUDE.md の「やらないこと」と同じにし、増やすときは両方を直す。使っていない機能を「使った」と書かない。
