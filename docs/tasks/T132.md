# T132 行の詳細を読んで分かる言葉に、平時の情報を「全部」で開く、訓練は詳細の連絡先から手を選ぶ（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。担当一覧の発災時の行の詳細（T13 の lib/list/detail.ts と components/list/RowDetail.tsx）、訓練の左の表の行の詳細（components/drill/DrillRowDetail.tsx。同じ中身）、本人のページ（T113 のあとの lib/person.ts）を取り込んだあとの物。

## 意図（なぜこの作業か）

行の詳細の時計と連絡先は、区分・長さ・きっかけ・未確認の印を詰めて並べているので、何の物が何から数えてあとどれだけかが読めない。今の表示の例:

- 時計の 2 行目「機器 2 時間 停電」「物 8 時間 停電」（区分・持つ時間・走り出すきっかけ）
- 薬の時計「ワーファリン 未確認 薬 未確認 発災」（名前・残りの欄の未確認・区分・長さの未確認・きっかけ。訓練の詳細は出典を出さないので、2 つ目の未確認が何か分からない）
- 連絡先の「夜間未確認」（夜間に来られるかが未確認、の印）

また、行の詳細は発災時に要る物だけを出すので、台帳の平時の情報（連絡先の全員・機器と物と薬の全部・避難先と手段・同居と介護の様子・計画書の要点）は本人のページを開かないと見られない。訓練では行の詳細に連絡先が並んでも、そこから手を打てず、対応の欄で本人・手・相手を選び直す。

## 作る物

### 1. 時計と連絡先の言葉（1 か所の関数から）

- 時計の 1 行は「物の名前 → きっかけから長さ → 残り」の形に。例「酸素 内蔵電池 停電から 2 時間（残り 0 分）」「酸素 予備ボンベ 停電から 8 時間」「ワーファリン 手元の量 未確認（発災から数える）」
- 区分（機器・物・薬・状態）の語は行に混ぜず、区分ごとの見出しで束ねる。物の区分の見出しは 1 字で読めないので言葉を足す
- 出典と確認は「出典 家族」「確認日 未確認」のように何の値かが分かる形。長さの未確認（「手元の量 未確認」）と出典の未確認が残りの欄と取り違えられない置き方に
- 連絡先の夜間は「夜間 来訪 未確認」のように何の印か分かる形
- 同じ中身を出す所（担当一覧の行の詳細・訓練の左の表の行の詳細・本人のページの時計の欄と上の時計）を、同じ関数から作る。2〜4 字の漢語の方針は守り、印を詰めて並べない

### 2. 平時の情報を「全部」で開く

- 今の行の詳細はそのまま。そこから「全部」で、台帳の平時の情報を全部見られるように: 連絡先の全員（家族・緊急連絡先・支援者・民生委員・夜間支援、電話の有無・スマホ・夜間）、機器・物・薬の全部、避難先 1・2 と手段、同居・介護の様子、計画書の要点（停電時の電源・予備・頼る病院や施設など、あれば）
- 本人のページと同じ組み立て（lib/person.ts）を読み、別に作り直さない。PC の幅（1920・1536・1280）で読みやすく、375 は崩れないか
- 担当一覧では今どおり電話のボタン（tel:）。訓練では番号を出さず、本物の番号に掛けない

### 3. 訓練で、詳細の連絡先から手を選ぶ

- 進行中の訓練の行の詳細（今の詳細と「全部」）の連絡先の行を押すと、対応の欄でその本人・その連絡先・その時に打てる連絡の手（連絡先電話など。本人の行は本人電話）が選ばれた形になる
- 打てるかどうかは手の可否の決まり（T110・T125 の lib/drill/action-terms.ts の結果）を読むだけ。打てなければ理由の 2〜4 字を出して押せない
- 対応の欄の中身（手の一覧の見た目・候補・メモ）は T126 の物で触らない。対象と手と相手を渡す小さな口（画面の中の小さな状態）だけを作り、口の形を docs/progress/t132.md に書く（T126 の頼み事の候補も同じ口を使える形に）

### 4. テスト

- 時計の言葉（機器・物・薬、値あり・なし、停電の前・後・超過、平時）、区分の見出し、出典と確認日、夜間の言葉
- 行の詳細・訓練の詳細・本人のページが同じ関数の言葉を出す
- 「全部」に連絡先の全員・機器と物と薬・避難先と手段・同居と介護・計画書の要点が出る。訓練の「全部」に番号と tel: が無い
- 訓練の連絡先の行の手の選び方（決まりの表の結果を手で作り、中身に頼らない）と、口で対応の欄が選ばれた形になる
- `npx vitest run --maxWorkers=3`・`npm run typecheck`。画面は 1920・1280 のライトとダーク（docs/progress/t132/ に絵）、375 は崩れないか

## 守ること

- 色と連絡順はルールの表（lib/triage）だけ。この作業は並べ方と言葉だけを変える
- 医療の助言をしない。台帳の値をそのまま並べる
- 本人の 1 枚（lib/forms/own-sheet.ts）は時計の値を載せない決まり（T06）なので時計は足さない。夜間はやさしい日本語のまま
- 本物の API・本番の D1（--remote）に触らない。鍵を探さない。.dev.vars を読まない。履歴を書き換えない。他の worktree に触らない
- 画面の言葉は 2〜4 字の漢語。見出しに読点・句点を付けない。CLAUDE.md の使わない型（ピル型・番号ラベル・等幅のラベル・グラデーション・字間・絵文字・`<details>` の黒い▼・真っ黒の塗りボタン・テーマ色の薄い下地）。区切りは枠線より地の色の差。押したときは灰色だけ
- 文書に作者の発言の引用・作業のやり取り・人の名前を書かない（公開のリポジトリ）。作業者の一時ファイルは scratchpad の `t132/` の下
- PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす。T125・T126・T128 と同時に動く）。merge commit にも Co-Authored-By。migration は要らない
