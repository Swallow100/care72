# T163 医療班の受け入れの道

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。受け入れの作り（T23・T24・T78・T81・T152）の頼み文と進み、使う側の模擬（T156）と評価の 7 回目（docs/progress/eval-r7.md の「使う側の模擬」）を読む。

## 意図（なぜこの作業か）

使う側の模擬の本物の 1 回目で、医療班の筋は 4 つの目標のうち 1 つしか届かなかった。受入一覧が 0 人で、氏名で探しても受け入れに進めなかった。
訓練の中には「受入依頼」の手があるが、訓練の外（デモの「発災開始」で入る大雨の想定、実際の発災時）には、ケアマネジャーから医療班へ受け入れを頼む道も、医療班がそれを見て受ける道も無い。

## してほしいこと

- ケアマネジャー（事業所）が本人を医療班への受入依頼として送る → 医療班の受入一覧の上に依頼の一覧 → 医療班が受入か受入不可を返す → 事業所の側（本人のページ）に返事が見える、の道を訓練の外に通す
- 受け入れは今の受け入れ（lib/custody/store.ts の receive）を通す。受け持ちの一意・審査員の壁・第三者提供の記録はそのまま効かせる
- 見える範囲は同意と仮名化の決まりのまま。医療班への提供に同意のある人だけ送れる（未確認・不同意はサーバーが断る）。受け入れる前の依頼の行は本人確認の範囲（カナ・年齢）と依頼元・行き先・依頼の時刻だけ。薬・機器は受け入れて提供の記録を書いてから
- 返事は 2 つの決まった言葉だけ。自由文の理由の欄は作らない（医療の助言の入口にしない）。Claude は呼ばない
- デモ: 種の事業所（デモ・確認用）の「発災開始」で、ルールの表の連絡順の上から、医療班への提供に同意のある人の依頼を入れる（山田の赤を含む）。毎朝 4 時の戻しと「最初に戻す」で消える。もう一度押しても二重にしない
- migration は 0039（相談の側で予約済み）
- 画面の言葉は 2〜4 字の漢語。PC の幅で確かめる
- 使う側の模擬の医療班の筋を今の画面に合わせ、偽の回（npm run eval:persona）で最後まで行くこと。守り（tools/eval/guards.ts）に医療班の筋の達成を足す

## 守ること

- 本物の API・本番の D1（--remote）に触らない。鍵を探さない
- 評価の生の記録は使う側の模擬の 1 回目のフォルダだけ、再現のために読む。中身を repo に写さない（数と形だけ）
- 文書に作者の発言の引用・作業のやり取り・人の名前を書かない。医療の助言をしない
