# T165 訓練の人ごとの筋の点がまだ 2 のまま

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。人ごとの事実の帳面の作業（docs/tasks/T130.md・T139.md・T141.md・T158.md と進み）、評価の台（docs/tasks/T108.md）、点数の表（docs/tasks/T157.md）を読む。

## 意図（なぜこの作業か）

審査役（tools/eval/drill/judge.ts）の「人ごとの筋」の点が r1 から r7 までずっと 2（目安は 3 以上）。T141・T158 で本人役の言葉の門を直し、台の数（通話の繰り返し・いる所の揺れ・電池の数の流れ）は良くなったが、審査役の点は上がらない。

r7 の審査役の指摘（notes）を、次の 4 つに分けて原因を確かめ、全部の人・全部の想定に効く形で直す。

- (a) 本人役の言葉そのものの食い違い
- (b) 想定の表の固定の文（lib/drill/scenarios.ts）と台帳の食い違い
- (c) 人ごとの出来事が少ない・同じ形ばかり
- (d) 審査役に渡す流れの欠け（通話の往復・到着・訪問の様子が入らないなど）

## 作る物

1. 原因の分け方（評価の 7 回目の記録を読むのは再現のためだけ。中身は repo に写さない。数と形だけ）
2. (a)(b)(c) のアプリの側の直し（lib/drill）。AI の呼び出しは増やさない（コードの門・帳面の文・指示の 1 行だけ）。色と連絡順のルールの表には触らない
3. (d) 審査役へ渡す流れ（storyText）に、足りない物（通話の往復の要約・到着・訪問の様子・手の結果の 1 文・発災の時刻）を足す。物差しの文（JUDGE_SYSTEM）と基準は変えない。変えた所は docs/progress/t165.md と点数の表の注（tools/eval/scorecard-items.ts）に書く
4. 台の数: 人ごとの出来事の種類の数と、人どうしの筋の似かた（同じ回の人どうしの出来事の種類の重なり）を findings.json と点数の表に。偽の client のテスト
5. 直した門は台の検査の物差しにも足し、門で 0 になる物は守り（tools/eval/guards.ts）に
6. 本物の回で何を見れば直ったと言えるかを docs/progress/t165.md に
