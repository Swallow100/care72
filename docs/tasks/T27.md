# T27 配信（Cloudflare）と審査員の入口

## 目的

公開デモを Cloudflare に上げ、審査員が提出書類の ID とパスワードで入れるようにする。配信の命令は作者が自分の端末で手で打つ。エージェントは script・設定・確かめの手順を用意するだけで、配信の命令はフックが止める。

## 今の形（11/2 16:4x、docs/DECISIONS.md「11/2 16:1x〜16:4x の確定」）

- 資源は 11/2 に作った。既存のアカウントに D1 `care72`（wrangler.jsonc の database_id）と R2 `care72-recordings`。account_id は wrangler.jsonc に書かない。16:45 に最初の版を配信した
- 配信は作者側が `npm run deploy` を手で打つ（`opennextjs-cloudflare build && wrangler deploy`）。表は `npm run db:migrate:remote`、種は `npm run db:seed:remote`
- Secrets はダッシュボードから入れる（チャット・ファイル・commit に書かない）: `SESSION_SECRET`（32 字以上。無いと全部の画面が止まる）、`JUDGE_PASSWORD_HASH` か `JUDGE_PASSWORD`、`CAREMANAGER_DEMO_PASSWORD_HASH` か `CAREMANAGER_DEMO_PASSWORD`、`ANTHROPIC_API_KEY`、`GEMINI_API_KEY`。平文のパスワードは secret にだけ置く（lib/auth/credential.ts）
- 独自ドメインは保留。workers.dev の URL のサブドメインが他のプロジェクトの名前を含むので、審査員に出す前に取るかを決める
- 11/4 から配信は `bash tools/deploy/migrate-remote.sh <commit>`（T73）。表を落とさず、d1_migrations に無い番号だけを当てる（build → migrations → deploy → check。migrations が落ちれば deploy しない）。種は入れ直さない（デモ事業所は毎朝 4 時の戻しか /office の「最初に戻す」で種に戻る）。入った番号の migration は書き換えない（docs/deploy/migrations.lock と違えば何もせずに止まる。錠は `node tools/deploy/lock-migrations.ts` で作り直し、commit に理由）。`bash tools/deploy/rebuild-remote.sh <commit>` は作り直しが要るときだけで、本物の事業所のデータ（デモ事業所の外の利用者・訓練、種に無いアカウント・事業所）があれば drop の前で止まる。消してよいときだけ `ALLOW_DATA_LOSS=1 bash tools/deploy/rebuild-remote.sh <commit>`（survey_ の表はどちらでも残る）。T72 が wrangler.jsonc に cron を足しても、`wrangler deploy` が triggers を一緒に出すので手順は変わらない
- 本物の事業所を足すとき（T73）: `node tools/office/new-office.ts --name <事業所名> --city <市町村> --login-id <ID> --display-name <管理者の名前>` で、SQL のファイル（$HOME の下）と初期パスワードの 1 回の表示が出る。出た命令 `node node_modules/wrangler/bin/wrangler.js d1 execute care72 --remote --command="$(cat <ファイル>)"` で入れる（`--file` は取り込みの道で DB が止まるので使わない）。管理者は /office で自分のパスワードを変え、ケアマネを足す

## 作る物（残り）

1. 配信後の確かめ: `/api/health` の ai が true、ログインなしの `/` が `/login` へ、審査員ログイン → 役選択 → 担当一覧、本人のスマホ、訓練 10 分版を 1 回、「最初に戻す」
2. ログインの回数の制限: Cloudflare の rate limiting の規則か、失敗の数を D1 に数える形を決める（今の守りは PBKDF2 の遅さだけ）
3. 1 日の上限とクレジット: 審査の 11/9〜10 も動くように、上限の値と残りを docs/PROGRESS.md に
4. README の「触り方」に URL（独自ドメインを決めたあと）。ID とパスワードは書かない
5. OpenNext の build が Windows で止まったら、WSL か GitHub Actions（手動起動）で build する道

## 終わりの形

- 公開の URL で審査員ログイン → 役を選ぶ → 担当一覧、本人のスマホ、訓練が動く。`/api/health` が ai: true。ログインしていなければどの画面も `/login`

## 触るファイル

wrangler.jsonc、package.json（remote の script）、.github/workflows/（build を使うなら）、README.md、docs/PROGRESS.md

## 守ること

鍵をファイル・チャット・commit に書かない。資源は care72・care72-recordings だけで、同じアカウントのほかの資源に触らない。配信の前に `git status` がきれいで、main の先頭が push 済みであること。`db:seed:remote` は全部の表を消して種に戻す（協力事業所の記録も消える）。`--file` は D1 への取り込みで、流している間は DB が止まることがあるので、審査員が触っている時間には流さない。
