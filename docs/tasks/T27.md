# T27 配信（Cloudflare）と審査員の入口

## 目的

公開デモを Cloudflare に上げる。D1・R2 を本物にし、鍵を secret に入れ、審査員が提出書類の ID とパスワードで入れる。11/7 の午前。これだけが配信をしてよい作業。

## 読む物

docs/SPEC.md の「作り」（配信は Cloudflare、Workers 有料、workers.dev）、「GitHub と提出物で守ること」。docs/PROGRESS.md の「あとで本物にする所」。セッション⑥「アプリを安全に公開する方法」（11/7）の内容があれば先に。

## 作る物（作者と一緒に。鍵の入力は 作者）

1. Cloudflare のアカウント（新しいメール、別のプロジェクトと分ける。Workers 有料）に wrangler でログイン。**この PC の wrangler は別のプロジェクトのアカウントに入っているので、`CLOUDFLARE_API_TOKEN` をこの作業の環境変数にだけ置くか、別のプロファイルで入り直す。混ざらないことを `wrangler whoami` で確かめてから進む**
2. `wrangler d1 create care72`、`wrangler r2 bucket create care72-recordings`。wrangler.jsonc の `database_id` と bucket 名を本物に。`account_id` を書く
3. migration を `--remote` で流し、種を入れる（`npm run db:reset` の remote 版を作る）
4. secret: `ANTHROPIC_API_KEY`、`GEMINI_API_KEY`、`JUDGE_PASSWORD_HASH`、`SESSION_SECRET`。値は 作者が `wrangler secret put` で入れる（チャット・ファイルに貼らない。クリップボードから標準入力で渡す）
5. `npm run cf:build` と `wrangler deploy`。OpenNext の build は Windows で警告が出るので、WSL か GitHub Actions（手動起動）で build する道も用意
6. 配信後の確かめ: `/api/health` の ai が true、審査員ログイン、担当一覧、本人のスマホ、訓練 10 分版を 1 回、`最初に戻す`
7. 1 日の上限とクレジット: 審査の 11/9〜10 も動くように、上限の値と残りを docs/PROGRESS.md に
8. README の先頭に入口と役の選び方を 5 行（URL は書く。ID とパスワードは書かない）

## 終わりの形

- workers.dev の URL で審査員ログイン → 役を選ぶ → 担当一覧、本人のスマホ、訓練が動く。`/api/health` が ai: true

## 触るファイル

wrangler.jsonc、package.json（remote の script）、.github/workflows/（build を使うなら）、README.md、docs/PROGRESS.md

## 守ること

鍵をファイル・チャット・commit に書かない。別のプロジェクトのアカウントに資源を作らない。配信の前に `git status` がきれいで、main の先頭が push 済みであること。
