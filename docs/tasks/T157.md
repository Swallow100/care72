# T157 評価の点数の表と指摘の形（指摘の共通の形・回をまたいだ点数の表・指摘から作業の下書き）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。評価の台の頼み文と進み（docs/tasks/T107.md・T108.md・T137.md、docs/progress/t107.md・t108.md・t137.md）と、回ごとの結果（docs/progress/eval-r1〜r5・eval-rN-findings.md）を読む。コードは tools/eval（drill・forms・talk・shapes.ts）。

## 意図（なぜこの作業か）

評価の台は 3 つ（訓練 tools/eval/drill・書類 tools/eval/forms・声の会話 tools/eval/talk）で、使う側の模擬（tools/eval/persona、T156）が別に作られている。回ごとの結果は docs/progress に手で書いてきたが、次の 3 つが人の手のまま。

- 回ごとに表の形が違い、前の回と比べるのに表を読み比べる
- 指摘（何が・何回・どこ）の書き方が回ごとに違い、直しの作業に回すときに書き直す
- 直した物が次の回で戻っても、台の確かめに足していなければ気づかない

これを仕組みにする。線: この作業は Claude を呼ばない。色と連絡順（lib/triage）とアプリの中身には触らない（台の出口だけ）。

## 作る物

1. **指摘の共通の形**（tools/eval/findings.ts）: 台・場所（画面かファイル）・重さ（3 段）・再現の手順・疑うファイル・受け入れの確かめ（数で言える物）・初めて出た回。台ごとの import を持たない小さな型と書き出しの関数にして、T156 も同じ形を使えるようにする。訓練・書類・声の会話の報告が、今出している数と問題（drill の CheckHit、forms の数と見直し、talk の筋ごとの数）から、この形の指摘を回のフォルダの findings.json に出す
2. **回をまたいだ点数の表**（tools/eval/scorecard.ts、`npm run eval:scorecard`）: 各台の回の結果（数の JSON）を集め、docs/progress/eval-scorecard.md に「項目 × r1…rN」の表を作る。項目ごとに良い向きとしきい値を持ち、前の回より悪くなった物・しきい値を外れた物に印。r1〜r5 は docs/progress の表の数を種として入れる（写した表と行を書く）
3. **指摘 → 作業の下書き**（tools/eval/drafts.ts、`npm run eval:drafts`）: findings.json から同じ原因の指摘をまとめ、docs/tasks に置ける下書き（何を直すか・受け入れの確かめ・再現の手順）を出す。受け入れの確かめは次の回の台の確かめ（tools/eval/guards.ts）にそのまま足せる形にし、足し方を docs に書く。見本の確かめを 1 つ足す
4. **テスト**: 偽の client で、訓練 1 回 → findings.json → 下書き → 点数の表まで通る。書類は結果の形を手で組む。声の会話は偽の client の筋

## 触るファイル

tools/eval（新しい findings.ts・scorecard.ts・scorecard-items.ts・scorecard-seed.ts・drafts.ts・guards.ts と、drill・forms・talk の findings.ts、drill/run.ts・forms/cli.ts・talk/run.ts の書き出しの所）、package.json（scripts の 2 行）、docs/tasks/T157.md、docs/tasks/README.md（一覧の 1 行）、docs/progress/t157.md、docs/progress/eval-scorecard.md（作った表）。

触らない: lib（アプリの中身）、台の検査の中身（checks.ts の決まり・forms の数え方）、tools/eval/persona（T156 の作業者）。

## 守ること

- 本物の API・本番の D1（--remote）に触らない。鍵を探さない。.dev.vars を読まない
- 評価の生の記録（リポジトリの外の care72-qa）は読まない。テストは偽の記録で
