# T92 出来事の表 v2（監督の差し込みを 6 種類から 22 に、人ごとの出来事、予定の出来事、仮想の街の種類）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T90〜T94 は 1 組（訓練の自由度）。T90 の準備の PR（engine.ts の型の分割で DirectorEvent・directorIncidents が lib/drill/incident-types.ts へ、drillClocks が world-clocks.ts へ、WorldState の `checks`・`scheduled`・`supplies`・`asks`・`arrivals`）が integrate/t11-t12 に入るまでは、新しいファイル（event-catalog.ts）だけを書く。

## 意図（なぜこの作業か）

監督（Opus、lib/drill/director.ts）が差し込める出来事は 6 種類（栄養剤の持ち出し忘れ・透析施設の浸水・道路が通れない・家の電話が不通・訪問看護が来られない・本人が家に帰ろうとする）で、1 刻み 2 つまで。72 時間を細かく進める（T90）と、同じ 6 つが繰り返され、停電の復旧の見込み・給水所・福祉避難所の開設・薬局や介護事業所の休止・業者の巡回・家族の帰宅困難・余震・避難所の環境のような、実際の 72 時間に起きる事が出ない。種類を増やし、人ごとの出来事と「何時間後に起きる」予定の出来事を持てるようにする。

線はそのまま: 種類は表だけ（表の外は捨てる）、世界の変化はコードが組む（Claude は種類・相手・文・理由・根拠を選ぶだけ）、根拠は出典の登録簿（lib/sources）にある物だけ（無ければ「根拠なし」）、人の体の具合・生き死にを監督は書かない（本人役が演じる）。

### 2. 監督の側（lib/drill/director.ts）

- `eligibleKinds`・`KIND_WORDS`・`INJECT_TEXTS`・`injectChange` を表から引く形に（scenarios.ts の INJECT_KINDS・INJECT_TEXTS・injectChange は表を re-export する薄い物に。固定の差し込み〔fixedInject〕は今のまま動く）
- scope が area の種類は target を「全体」と書かせ、directorIncidents（incident-types.ts）で本人なしを受ける（今は参加者でない本人を捨てている。area は person 無しで通す）
- 予定の出来事: 返事に `after`（時間）を足し、表に `after` のある種類だけ受ける（範囲の外は捨てる）。コードが `scheduled` に積む（T90 の準備の形。fireScheduled は T90）。文は「〇〇 見込 N 時間後」の形で、起きたときの文は表の text
- 差し込みの数: `DirectorInput.budget`（T90 が渡す。無ければ DIRECTOR_MAX）。同じ人に 2 つは当てない、area は 1 区切りに 1 つ
- 指示（DIRECTOR_SYSTEM）: 種類の一覧を表から生成。決まり 3（人の生き死に・けが・体の具合を書かない）はそのまま。足す決まり: 「予定の出来事は after に時間を書く（範囲は種類ごと）」「全体の出来事は target に『全体』」「弱点の無い人に差し込まない」は今のまま
- 根拠の付け方: 表の `basis` が 1 つに決まる種類は、**コードが付ける**（今の fixedInject と同じ形。監督に選ばせない）。監督が選ぶ basis は今までどおり DIRECTOR_SOURCES の 5 つか「根拠なし」で、**DIRECTOR_SOURCES は増やさない**（lib/sources/prompt.ts の sourcesSystem は要旨を system に足すので、健康の助言の要旨を持つ文書〔呼吸・インスリン・血栓〕を監督の指示に入れない。review.ts の REVIEW_SOURCES と同じ理由）。表の jadec-insulin-2023・jrs-respiratory-2012・jsth-pe-2020・mhlw-ecs-2018 はコードが付けるだけで、画面に出典として添える
- 弱点の要約（weaknessText）に、T90 の準備の欄を 1 行ずつ: 頼み事（asks の未対応）、届いた物（supplies）、向かっている人（arrivals）、確認の上書き（checks）。本人の体の様子は書かない
- 言い換え（replies）は今のまま

## 守ること

- 色と連絡順はルールの表（lib/triage）だけ。出来事が表に届く道は時計の頼り先の確認の写し（checks → drillClocks）だけで、入力の形は今のまま。監督に色・順位を決めさせない
- 種類は表だけ。世界の変化はコードが組む（injectChange と同じ）。Claude が表の外の変化を起こす道を作らない。根拠は出典の登録簿の id か「根拠なし」。登録簿に無い根拠を作らない・文書を足さない
- 監督の決まり 3（亡くなる・意識がない・火事を作らない、けがや体の具合は書かない）はそのまま。「避難所での体調の変化」のような体の事は出来事にせず、環境の事（冷蔵不可・車中泊・満員）までにして本人役が演じる。「死亡」の語を使わない。119 は自動にしない
- 仮想モードの結末はデモ事業所だけ（変えない）。仮名化の門を迂回しない。本物の API は呼ばない。鍵を探さない。履歴を書き換えない。端末は増やさない。他のプロジェクトの名前・実在の地名・施設名を書かない。文書に作者の発言の引用・やり取り・人の名前を書かない
- 画面の言葉: 2〜4 字の漢語（表の印の列）。常設の説明文を置かない。使わない語: 診断・判定・重症・緊急度・札
- 見た目の避ける型: ピル型、番号ラベル、等幅のラベル、グラデーション・光る影、字間、絵文字、`<details>` の黒い▼、真っ黒の塗りボタン、テーマ色の薄い下地。印は灰の文字か色の文字（状態の 4 色は安否にだけ）
- 並列の衝突: T90・T91・T93・T94 と T88・T89 が同時に動く。T90 の準備の PR の前は新しいファイルだけ。world-oneshot.ts・world-room.ts は T89 のあと。PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす）。migration は要らない
