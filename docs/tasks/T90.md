# T90 連続の時計（進め方を 30 分・1 時間・3 時間・次の出来事までから選ぶ）と、AI の呼び出しの節約（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md`（何を作っているか・越えない線・地図・進め方）→ `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。T90〜T94 は 1 組（訓練の自由度）で、T90 はその土台。

## 意図（なぜこの作業か）

今の訓練は、想定の表の 12 の刻み（0・1・3・6・9・12・18・24・36・48・60・72 時間）を 1 要求で 1 つ進める形で、刻みのたびに監督（Opus）1 回と本人役（Haiku）を参加者の全員に呼ぶ（lib/drill/engine.ts の step、1 刻み 23〜26 秒）。ケアマネの手は 7 つで分数が固定（lib/drill/action-table.ts）。本物の Claude で回した画面（10 分版）を見ると、6 時間や 12 時間が一息に飛び、その間に本人たちに何が起きたか、打った手がどう効いたかが見えない。訓練として「誰から順に・いつ・何をするか」を試すには、ケアマネが自分の時計を 30 分・1 時間・3 時間・次の出来事まで、と刻めるほうがよい。

ただし細かく進めるほど AI の呼び出しが増える。1 時間刻みで 72 回進めて毎回全員を呼ぶと 72 ×（監督 1 + 本人役 10）≒ 800 回で、デモ事業所の 1 日の上限（600 回。lib/claude/usage.ts、AI_DAILY_LIMIT）を 1 回の訓練で使い切り、審査員の 10 分版を止める。だから進め方の自由化と同時に、**誰を・いつ呼ぶか**を数で決める（本人役はその区切りで何かがあった人だけ、監督は 3 時間ごとか出来事のある区切りだけ、1 訓練の上限）。

10 分版（審査員の見せ場、4 刻み）は 1 bit も変えない。新しい進め方は大雨想定・地震想定（「通常」）と仮想に。

### 1. 連続の時計（advance）

- `DrillOptions.clock?: true`（T59 の night と同じ形で drills.world の options に入る）。**大雨想定・地震想定・仮想は新しく始める訓練は全部 clock**（開始の画面で選ばせない。StartButtons が options に `clock: true` を足す）。10 分版（short）は付けない。前からある訓練（clock の無い物）は今までの刻みの道で再生・再開できる。
- `advance(state, toMinute, hooks, opts)` を engine.ts に作る。toMinute は今の分より大きく 72 × 60 以下。順:
  1. 想定の表を時刻順に平らにし（`events` と `turns` の `at`、無ければ刻みの時刻。固定の差し込み〔by: director〕も）、`(state.minute, toMinute]` に入る物を当てる。配役（T70 の cast）は今のまま
  2. `settleWorld(world, toMinute)`（到着・戻り・arrivals・supplies）と `fireScheduled`（T92・T91 の予定の出来事）
  3. **監督**（下の 3 の決め）。DirectorInput の `since`（前の分）・`budget`（この区切りで差し込んでよい数）を埋める（準備の 4 の欄。T92 が読む。T92 が来るまでは DIRECTOR_MAX で切る）
  4. **本人役**（下の 2 の決め）。PersonaInput の `since`（その人を最後に呼んだ分。無ければ 0）・`reasons`・`toMinute` を埋める（準備の 4 の欄。T93 が読む）
  5. Tick は `{ step: state.step + 1, hour: toMinute / 60, incidents, turns, world, finished: toMinute >= 72 * 60 }`。foldTick の終了の判定を `tick.finished`（分）に（刻みの添字で見ない）
- **`step()` は残す**: clock の無い訓練では今までと同じ（`advance(state, hours[step + 1] * 60, hooks, { policy: "all" })` の包みで、監督を毎刻み・本人役を全員・差し込みは DIRECTOR_MAX）。既存のテスト（drill・score・persona・director・t59・t70・t76・t84・virtual・lib/seed の種の訓練）が 1 行も変わらずに通ることを確かめる。10 分版はこの道。
- **仮想**（virtualStep）も同じ advance に乗せる: 世界の部屋・1 回呼びは監督と同じ決め（3）で呼ぶ。部屋に送る「前の刻みからケアマネがした事」は `since` から（world-oneshot.ts の tickText の prevHour を分に。world-oneshot.ts は T89 が触っているので、**引数を分にする 1 か所だけ**を T89 の取り込みのあとに）。
- 「**次の出来事まで**」: 新しい `lib/drill/clock.ts` の `nextEventMinute(state, sources)` = min(次の表の出来事・行の at、`scheduled` の次の at、`arrivals`/`dispatched` の次の arrive、時計が半分・切れる次の時刻〔hooks.clocks〕、今 + 180 分)。72 × 60 で止める。仮想は表が無いので後ろ 4 つ。
- **手の途中の区切り**（lib/drill/actions.ts の act の「手の途中で次の刻みの時刻を越えたら」の while。T91 もこのファイルを触るので、**この while と replies の所だけ T90 が直し、ほかの行は触らない**）: clock の訓練では手が区切りを起こさない。手の分だけ時計が進み、`(atMinute, endMinute]` に入る表の出来事と予定の出来事は **AI を呼ばずに**当てる（`advance` の policy "silent": 監督なし・本人役なし。touched に積んで次の進めで呼ぶ）。返事（decideAction）は進めたあとの世界で決める。言い換え（replies）は clock では頼まない（固定の文。監督の呼び出しを手で増やさない）。
- 保存（lib/drill/db.ts）: `advanceDrill(db, scope, id, expected, now, hooks, to: { minutes: 30 | 60 | 180 } | { next: true })`。drills.step は進めた回数（今の列のまま）、sim_hour は tick.hour（小数。列は REAL）。**`loadTicks` は刻みの時刻を `hours[i]` から作っている**ので、clock の訓練は drills.world に `cuts: number[]`（区切りの分の列。i 番目の刻みの終わり）を持ち、復元はそこから（clock の無い訓練は今までどおり hours から）。`lastStep` で終わりを見ている所（advanceDrill・actDrill・replayState）を「分が 72 × 60 か status」に。
- API（lib/drill/http.ts の stepPost）: `{ step, minutes?: 30 | 60 | 180, next?: true }`。clock の訓練はどちらか必須（無ければ 400）、clock の無い訓練は無視して今までどおり。

### 2. 本人役を呼ぶ人（この区切りで理由のある人だけ）

区切り `(since, to]` で、次のどれかの理由のある人だけ呼ぶ。理由は PersonaInput.reasons に全部渡す:

- `table`: 想定の表の行がこの区切りに入る（固定の筋。行は今までどおり骨）
- `incident`: この区切りの状況がその人を指す（person のある出来事、町の出来事の persons、固定の差し込み）
- `action`: その人へ向けた手の返事の時刻（result.atMinute。arrivals の到着は arrive）が `lastCalled[person]` より後（手を打った人の様子が次の進めで変わる、の土台。T93 が言葉を作る）
- `clock`: その人の時計が半分か切れを越えた（新しい `hooks.clocks(state, since, to) → string[]`。hooks.ts が loadOutcomeSources と score.ts の clockRuns から作る）
- `round`: 上のどれも無いまま 12 時間（720 分）たった人（押せる人のいる人だけ）。古い順に 1 区切り 3 人まで。仮想が静かになりすぎないため（6 時間にすると 10 人で 120 回になり、下の 4 の上限に途中で当たる）

1 区切りに呼ぶ人は **6 人まで**（Workers の 1 要求の外向きの接続は 6 本。lib/claude/models.ts の注）。多ければ table → action → incident → clock → round の順で、残りは `touched` に残して次の進めで呼ぶ。結末の人（仮想）は呼ばない。「連絡しない」の返事でも 1 回に数える。呼んだ人は `lastCalled[person] = to`。

10 分版（policy "all"）は今までどおり全員。

### 3. 監督を呼ぶ区切りと差し込みの数

- 呼ぶのは、(a) 区切りに表の出来事がある、(b) 前の監督から 180 分以上、(c) 「次の出来事まで」で進めた、のどれか。30 分・1 時間の空の進めでは呼ばない（表の出来事と予定の出来事だけ当てる）
- 差し込んでよい数 `budget` = 区切りの時間を 3 時間で割った物（1 以上 3 以下）。T92 が来るまでは DIRECTOR_MAX（2）で切る
- 1 訓練の監督の回数の上限 **20**（counts.director）。超えたら呼ばない（表と予定の出来事だけ）
- 仮想の世界も同じ決め（部屋の session はそのまま）

### 4. 1 訓練の AI の上限と見込み

- 上限は 2 段（lib/drill/clock.ts）。counts の合計（監督・世界・本人役・通話の相手・自由に書く手）で:
  - `DRILL_CALL_SOFT = 120`: 達したら巡回（round）を止め、監督は表の出来事のある区切りだけに（3 時間ごと・「次まで」では呼ばない）。帯は出さない（被害状況の「残り」の数だけ）
  - `DRILL_CALL_CAP = 150`: 達したら、その訓練は AI を呼ばない（固定の筋は「想定のみ」、仮想は「世界停止」。lib/drill/ai-stop.ts の帯に理由 `cap`〔「訓練上限」〕を足す。戻らない）
  講評（1 回）は数えない。1 日の上限（AI_DAILY_LIMIT）はそのまま
- 開始前の見込み（lib/drill/estimate.ts）を clock の訓練用に: 監督 20 + 本人役（呼ばれうる人 × 9）+ 講評 1 + 声（本人役の半分）。10 人で約 160 回（上限で 150 に収まる）。「見込み 約 N 回」の出し方は今のまま。10 分版の式は変えない
