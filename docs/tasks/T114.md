# T114 新しい事業所で見えた直し（地図の「位置は架空」・初めてのパスワード・原本取込の済み）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T98（初めて入った管理者の準備の欄）のあとの物。

## 意図（なぜこの作業か）

tools/office/new-office.ts で作った事業所（手元の D1 だけ）で、管理者 → 地域の中心 → ケアマネ 2 人の追加 → ケアマネで入り直し → 利用者の登録 → 台帳 → 経路 → 計画書、まで通すと:

- 担当一覧の地図の出典の行に、本物の事業所でも「位置は架空」と出る（components/map/CaseMap.tsx の MapSource がいつも出す）
- ケアマネ追加で出た初期パスワードのまま入れて、変更を求められない（管理者は /office で自分のパスワードを変えられる。T61）
- 計画書の「原本取込」を押すと「取得中」→ 取り込めたあとも数秒「原本未取込」の帯のまま。描き直してから原本の紙に替わるので、取り込めたか分からない間がある

## 先に決めること（問い）

1. 初期パスワードで入った人に変更を求めるか:
   - (a) 初めて入ったとき、自分のパスワードの変更の画面へ送る（変えるまでほかの画面へ行けない）
   - (b) 上の帯に「初期パスワード」の印と変更の入口を出すだけ（推し。審査員・種のアカウントは対象の外）
   - (c) 今のまま
   どの形でも、初期パスワードかどうかを覚える列が要るなら migration（番号は作業者が migrations/ と全部の branch を見て決める）

## 作る物

1. 「位置は架空」はデモの事業所（種の位置）のときだけ。本物の事業所は出さない
2. 問い 1 の答えの形
3. 原本取込のあと、描き直すまで「取得中」のままにする（または取り込めた印を出す）。失敗したら理由の短い言葉
4. テスト: 本物の事業所とデモで出典の行、初期パスワードの印、原本取込の帯の移り。375・1280、ライトとダーク
