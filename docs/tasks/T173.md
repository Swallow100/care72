# T173 使う側の模擬の 3 回目で残った迷いを減らす

r9 の使う側の模擬（persona r3）は目標 24/25、迷い 24。残りの迷いを、同じ作りの画面全部に効く形で減らす。Claude は呼ばない。本物の API を使わない。色と連絡順（lib/triage）に触らない。触らない所: lib/drill の本人役と世界（T174）、lib/forms（T175）。

## 1. 最初に戻す

- 読みの順で 115 個中 114 番目。右の列の頭に置いても、読みは左の列の後ろになる
- 平時復帰の窓の「戻す」と初期化の窓の「戻す」が同じ語で、何を戻すか読めない
- 事業所の画面の頭（押せる物の最初の方）に置く。窓の決める方は何をするかの語に

## 2. 医療班の入口

- 役変更から医療班に着くまで 9 手（最短 2）。役変更に気付かず利用者追加へ入る
- 役を選べる人（審査員と見本のケアマネ）の画面の切替に医療班の入口

## 3. 編集の面（全部の面）

- 保存の横の取消を押して入力が消える。「編集」が画面に何個もあり、どの面の物か読めない
- 「変更 0 件」の間は保存が押せない理由が読めない
- 保存のあと古い値を一瞬出さない

## 4. 全選択の選んだ印

- 全部選んだあとも名前が「全選択」で、もう 1 度押して 0 人に戻す
- 選んだ行と人数を読めるように。受入依頼・検索のヒット・事業所の担当の全部

## 5. 台

- ブラウザの必須の案内（required）を読みに入れる。実物の画面で案内が人に見えるかも確かめる
- 様式 9 の印刷のあとに次の目標を済んだと読む形（使う人の指示の側）

## 6. 守り

直した所を tools/eval/guards.ts の守りか台の check に足す（足し方は docs/progress/t157.md）。

## 確かめ

関係するテスト（--maxWorkers=2）、`npm run -s typecheck`、`npm run eval:persona` の偽の回、手元の dev で 1920・1536・1280 と 375（崩れないかだけ）。絵は要る枚数だけ docs/progress/t173/。
