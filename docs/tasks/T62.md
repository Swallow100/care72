# T62 書き出しの幅（担当一覧と受け持ちの CSV、本人の 1 枚の一括印刷）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）


- CSV は様式 9 だけ（app/office/form9/csv/route.ts、lib/forms/form9-csv.ts）。ケアマネが毎日見る担当一覧（app/page.tsx、lib/caseload.ts）と、医療班・行政の受け持ちの表（app/staff/page.tsx、lib/custody/board.ts）には無い。発災時に「至急の人だけを紙に出して手分けする」「避難所の受け持ちを市に渡す」ができない。
- 本人の 1 枚（app/people/[id]/forms/own/page.tsx）は 1 人ずつ開いて印刷する。30 人の担当なら 30 回。玄関に貼る紙は全員分を一度に刷る物。
- 線: 氏名の入る物を出すのは、担当一覧は自分の担当（lib/auth/scope.ts の caseloadScope）、受け持ちは自分が受け入れた人（lib/custody/actor.ts の staffActor）、本人の 1 枚はケアマネの役だけ（lib/consent/scope.ts で医療班・行政の書類の範囲に own は無い）。範囲の外は 404、ログインなしは 401、役が違えば 403（今の様式 9 の CSV と同じ断り方）。Claude は呼ばない。

書き出したことを経過に残すか: **残さない**（今の様式 9 の CSV と印刷も残していない。残すなら事業所の経過の種類を足す migration が要り、T61 の 0012 の建て直しと重なる。T61 が merge されたあとに、要れば別の作業で `care_manager_changed` と同じ形で足す）。

## 作る物

1. **CSV の共通の道**: lib/forms/form9-csv.ts の `csvText`（BOM・CRLF・式の守り）を export し、`csvFileNames` を名前を受ける形に広げる（`csvFileNames(madeAt, { ascii: "caseload", utf8: "担当一覧" })`。今の呼び方は様式 9 のまま動く）。再実装しない。
2. **担当一覧の CSV**: `GET /caseload/csv`（app/caseload/csv/route.ts。`/` の担当一覧と同じ loadCaseload）。URL の絞込（color・area・mark・q）と並び（sort・dir）を担当一覧と同じ読み方（lib/caseload.ts の parseFilter・parseDir・filterCaseload・sortCaseload）で受け、**今 画面に出ている行をその順で**書く（既定は絞らず表の順）。上の 2 行は様式 9 と同じ形（題「担当一覧」、事業所名・担当・作成日、並びと絞込の言葉「絞込：至急」）。列は表と同じ言葉（lib/list/labels.ts の COLUMN_LABELS）: 平時は 連絡順・氏名・カナ・年齢・介護度・医療・ハザード・支援者・避難計画・未確認・地区、発災時は先頭に 順位・状態・理由、末尾に 残り・最終連絡（色は COLOR_LABELS、理由は triage の 1 行をそのまま。順位は絞っても元の番号）。入口は app/page.tsx の PageHead の右、「利用者追加」の左に「CSV出力」（様式 9 と同じ字・アイコン DownloadIcon・`download` の a。平時・発災時の両方）。href は今の URL の query を持ち越す（caseloadHref と同じ作り）。
3. **受け持ちの CSV**: `GET /staff/csv`（app/staff/csv/route.ts）。`loadStaffBoard(actor)` の StaffRow を**そのまま**書く（reason は同意の範囲で空になり、medicalShown の濾しが入っている。再問合せしない）。StaffTable の絞込は氏名を URL に載せない設計（画面の中だけ）なので CSV は全員・表の順（rank）。列: 連絡順・状態・理由・氏名・カナ・年齢・医療・薬・機器・残り・避難所・経路（CUSTODY_VIA_LABELS）・受入時刻・事業所。入口は app/staff/page.tsx の見出しの行の右に「CSV出力」。役は staffActor（医療班・行政。審査員の医療班の役も）。
4. **本人の 1 枚の一括印刷**: `GET /caseload/own-sheets`（app/caseload/own-sheets/page.tsx。`?print=1` で開いてすぐ印刷）。入口は `requirePage("caseload")`（1 人の own の頁は "person" で医療班も通るが、一括はケアマネの役だけ）。担当一覧と同じ絞込と並びを受け（2 と同じ読み方。「至急の人だけ刷る」ができる）、1 人ずつ `loadPersonDocument(db, principal, id, "own")` を通して（範囲の外・同意で開けない人は飛ばして数える。人ごとの読みは `Promise.all` で並べ、1 人ずつ待たない〔1 人 6 回ほどの D1 の往復を 30 人分直列にしない。CONTEXT「長い処理は 1 要求で回さない」〕）、`OwnSheetPaper` を人数分並べる 1 頁。QR は own/page.tsx と同じ（loadQrRow → qrState → currentQrToken → qrUrl。未作成・期限切れは今と同じ枠）。1 人 2 頁（表・裏）で、人の間は paper.css:496 の `break-after: page` の作りで割る（最後の人の裏のあとは割らない）。上の帯（PaperBar、紙には出さない）に「N 人」、未確認のある人の数「未確認 3 人」、飛ばした人の数、絞込の言葉。`metadata.title` は DOCUMENT_LABELS.own（氏名を入れない）。入口は app/page.tsx の PageHead の「CSV出力」の隣に「一括印刷」（PrintIcon。ケアマネの役だけ。href は `?print=1` と今の query）と、絞込の帯（FilterBar）の右端にも同じ 2 つ（絞ったあとに押す流れ。375 で折り返す）。
5. **テスト**（lib/forms/t62.test.ts）: CSV の中身（BOM・CRLF・式の守り・列の数と順・絞込と並びが画面と同じ行・発災時の列）、権限（401・403・範囲の外）、受け持ちの CSV が reason の濾しを守る（同意の無い人の理由が空）、一括印刷の頁数（lib/forms/print-pages.test.ts の作りで puppeteer の printToPDF。種の 3 人で 6 頁・10 人で 20 頁、人の境で割れる。10 人の読みの時間も測って progress に）、飛ばした人の数、`?print=1` の autoPrint。頁数のテストは時間がかかるので `--testTimeout=60000`。
6. **docs**: docs/progress/t62.md（Claude を使う所・使わない所を 1 行。この作業は Claude を呼ばない。「書き出しを経過に残さない」の決めも書く）。仕様と違う決めは docs/DECISIONS.md に案として。
