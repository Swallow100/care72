# T94 採点と講評 v2（増えた手と分の時計で順番・遅れ・条件到達を正しく数え、講評は手の選び方を具体的に）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T90〜T94 は 1 組（訓練の自由度）。**始めるのは T90（連続の時計）と T91（手の表 v2）が integrate/t11-t12 に入ってから**。T93（頼み事・通話の往復）が入っていればそれも数え、入っていなければその部分は無い物として進める（欄が無ければ読まない形に）。

## 意図（なぜこの作業か）

採点（lib/drill/score.ts）は 4 つの数字（対応の順番の一致・市役所への報告の遅れ・様式 9 の空欄・条件に達した人）で、「その人への手」は 7 つの手のうち 5 つを決め打ち（PERSON_ACTIONS）、「届いた」は status の ok と訪問依頼の着く時刻の決め打ち（reachedAt）。講評（lib/drill/review.ts、Opus 1 回）の指示も手の言葉を 6 つ列挙している。T91 で手が 18 になり、T90 で時計が分になると、このままでは新しい手（透析調整・薬手配・見守依頼・移送・電源・自由対応）が順番にも条件にも数えられず、講評が名指しできない。手の表の旗（towardPerson・reach）を読む形にし、講評に「その手を打った時に分かっていた事実」を渡して、手の選び方の良し悪しを具体的に書けるようにする。

線はそのまま: 数字は機械、言葉だけ Opus。色・順位は表が決めた物で講評が付け直さない。病名・薬・医療の助言・「死亡」を書かせない（REVIEW_BANNED）。根拠は登録簿の id だけ。

## 作る物

### 1. 数える所（lib/drill/score.ts）

- `PERSON_ACTIONS` と `isPersonAction` を lib/drill/action-catalog.ts の `towardPerson` から。自由対応（kind free）は読み替えた手（record.as）で数える
- `reachedAt` を表の `reach`（届いたに数える status と到着までの分）から。arrivals（T90 の準備の欄）に着く時刻があればそれ、無ければ表の分。訪問依頼の 40 分の決め打ちを表に寄せる
- 順番の一致（scoreOrder）の決めは変えない（その人への最初の手が、その時の左の表で手のまだ無い人の一番上か）。記録だけ（note）・退避・行政報告・応援依頼は今までどおり数えない
- 報告の遅れ（scoreReport）は分のまま（T90 で手の時刻が分になっても今の atMinute で足りる）
- 条件に達した人（scoreReached）の計算は変えない（clockRuns は分）
- 足す数（内訳に出す。4 つの大きな数字は増やさない）:
  - `wasted`（空振り）: 打った時に分かっていた事実で結果が決まっていた手。手の前の状態（before）で、電話の線が不通なのに電話・家の前の道が通行止なのに訪問・職員の空き 0 なのに職員の訪問依頼・休止と分かっている透析施設へ透析調整。人ごとの数と手の番号
  - `repeat`（重複）: 同じ人に同じ手を、新しい事（その人の連絡・状況・到着）が無いまま 30 分以内に 2 回
  - `asks`（頼み事）: 本人・家族の頼み事（world.asks）のうち、訓練の終わりまでに済まなかった数と人（T93 が入っていれば）
  - `talks`（通話の往復の数。T93）
- `DrillScore` の v は 1 のまま（欄を足すだけ。無い記録は 0 として読む。lib/drill/record.ts の parseStoredScore は欄が無くても通る形に）

### 2. 講評（lib/drill/review.ts）

- REVIEW_SYSTEM の手の言葉の列挙を表の label から生成（「本人電話・連絡先電話・訪問・訪問依頼・見守依頼・薬手配・透析調整・受入依頼・病院受入・移送手配・電源手配・業者連絡・応援依頼・119勧奨・行政報告・記録・退避」）。指摘の kind に `choice`（手の選び方）を足す
- 入力の文（reviewText）の手の履歴の行に、**その時に分かっていた事実**を添える（before から: 「電話 不通」「道 通行止」「職員 0」「透析先 休止」「本人 赤 けが」「前の手から 10 分」）と、結果（表の status の言葉）。自由対応は「自由対応（読み替え: 薬手配）」。通話の往復（T93）は「通話 3 往復（頼み事: 薬・電源）」
- 「機械で数えた結果」に空振り・重複・頼み事の未対応・往復の数を足す
- 指示に足す決まり: 「手の選び方は、その時に分かっていた事実と、表にある別の手の名前で書く（例: 道が通行止と分かっていたので、訪問でなく訪問依頼か見守依頼）。無かった手を作らない」「頼み事に応えなかった事は、その頼み事と、応えられた手の名前で書く」
- REVIEW_BANNED（禁じる語）に、表の label・頼み事の言葉・結果の言葉が掛からないことをテストで確かめる（掛かるとその手を名指しできない。「薬手配」の「薬」は「薬を続け」でないので通る。「購入」「服用」「mg」を含む label を作らない）
- 講評に渡す出典（REVIEW_SOURCES）は今のまま（健康の助言の要旨を持つ文書を足さない）

### 3. 画面と紙面

- 採点の欄（components/drill/ScorePanel.tsx・lib/drill/score-view.ts・score-labels.ts）: 4 つの数字はそのまま。内訳に「空振り N」「重複 N」「頼み事 未対応 N」「通話 N 往復」。言葉は 2〜4 字（「空振り」「重複」「未対応」「往復」）
- 講評（components/drill/ReviewBox.tsx）: kind `choice` の印「選択」。直せる形は今のまま
- 訓練記録の紙面（components/drill/DrillPaper.tsx・DrillRecordTable.tsx）: 手の行に分の時刻と「その時に分かっていた事実」の短い列、自由対応の読み替え、通話の往復は畳んで「3 往復」、訪問の様子と頼み事の 1 行
- 前回との比較（record.ts の previous）は 4 つの数字だけ（増やさない）

### 4. 偽の hooks で通す筋（テストの土台。lib/drill/t94.test.ts）

- T90 の advance と T91 の手で、新しい手を打った訓練を手元で 72 時間まで回し、採点が: 透析調整で届いた人を条件に数えない、見守依頼の到着で順番の一致に数える、自由対応（読み替え 薬手配）が順番に数えられる、空振り・重複が数えられる、分の時刻で報告の遅れが正しい
- 講評: 偽の client で、REVIEW_SYSTEM に表の label が全部ある、入力の文に事実と結果が入る、kind choice を受ける、禁じる語の検査が label を通す
- 既存の score.test.ts・t59・t70・seed の採点が同じ数字のまま通る。`npm test`・`npm run typecheck`。画面は 1280 と印刷のプレビューで採点と紙面（絵は docs/progress/t94/）

## 守ること

- 数字は機械で数え、Opus は言葉だけ（数え直さない・新しい数字を作らない）。色・順位はルールの表が決めた物で、講評が付け直す・変えることを書かない
- 病名・薬・薬の量・処置・医療の助言を書かせない（REVIEW_BANNED を緩めない）。「死亡」「関連死」を書かない（「条件に達した」まで）。根拠は出典の登録簿の id か「根拠なし」。登録簿に無い根拠を作らない
- 講評の入力は仮名（pseudonymize の並び）で、氏名・住所・電話・町名を渡さない。ケアマネのメモ（T59）と自由対応の元の文は渡さない（読み替えた手の名前だけ）。自由対応の文を講評が引用する道を作らない
- 本物の API は呼ばない（偽の client）。鍵を探さない。履歴を書き換えない。端末は増やさない。他のプロジェクトの名前を書かない。文書に作者の発言の引用・やり取り・人の名前を書かない
- 画面の言葉: 2〜4 字の漢語。常設の説明文を置かない。見出しに読点・句点を付けない。使わない語: 診断・判定・重症・緊急度・札
- 見た目の避ける型: ピル型、番号ラベル、等幅のラベル、グラデーション・光る影、字間、絵文字、`<details>` の黒い▼、真っ黒の塗りボタン、テーマ色の薄い下地。数字は tabular-nums。紙面の字・欄の決まり（T36・T47）は変えない
- 並列の衝突: T92・T93 が同時に動くことがある。PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす）。migration は要らない
