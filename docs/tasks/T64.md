# T64 細かい幅（医療班の機器その他の名前、QR の期限、録音の分類「その他」）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）

残りの幅も足す。T57〜T60 の洗い出しで残った小さな物を 1 本にまとめる。どれも色と連絡順（lib/triage）には効かない。

- 医療班の受け持ちの表は機器を DEVICE_LABELS で出す（lib/custody/board.ts:208）ので、T57 で足した「その他」の名前（Ledger の devices の detail。例「電動ベッド」）が「その他」としか出ない。現場の登録（components/staff/StaffIntake.tsx:363、lib/custody/forms.ts:109、lib/custody/store.ts:172 の onSiteLedger）は種類だけで、その他に名前を書けない（間に合えば後でと決めていた物）。
- QR の期限は 90 日で固定（lib/qr/token.ts:14 の QR_TTL_DAYS）。lib/qr/store.ts:80 の resolveQrToken が `p.exp !== iat + QR_TTL_SEC` で固定の TTL を**再計算して**比べるので、期限を選ぶには本人の行に持つしかない。
- 録音と自由文の分類は 5 つ（lib/db/types.ts:159 の RECORDING_CLASSES: けが・動けない・水が来た・機器が止まった・不明）で、「はっきり言っているが 4 つのどれでもない」（食べ物が無い・家族と連絡が取れない・不安）が「不明」に落ちる。ケアマネが録音を聞く手がかりとしては、不明（聞き取れない）と分けたい。表（lib/triage/index.ts:424 の injuryWords）は injury・immobile しか見ないので、足しても色・順は変わらない。
- アンケートの期限と取り消しは**この作業に入れない**。T65 がアンケートを共有の 1 本のリンク（受付 11/5 まで）に作り直し、components/office/Survey*.tsx・lib/survey/store.ts・links.ts を書き換えるため。
- 本人・家族のスマホに自由に書く欄は**足さない**（下の決め）。

線: 分類は Claude（Haiku）の出力で、色と順には使わない（CLAUDE.md「守ること」、docs/TRIAGE.md）。「その他」も同じ。119 の文言は触らない。本人・家族の画面は触らない。

本人・家族の自由記入を足さない理由（progress にも 1 行）: 本人の画面は「はなす → 30 秒録る」が自由記入で、文字起こしが仮名化の門を通って分類と聞き取りメモになる道がもうある（lib/signals/phone.ts）。打つ欄は 1 画面 1 問・大きな字・やさしい日本語の設計と逆で、高齢の本人には録音より難しい。家族の画面は録音を持たせない設計（lib/signals/save.ts の注。本人の信号に家族が録音を添えないため）で、文字の欄を足すと Claude に渡す新しい道（分類するなら仮名化の門、しないなら本人の言葉と混ざらない置き場）が要る。足すなら別の作業で、条件は「家族だけ・60 字・Claude に渡さない（分類しない）・色と順に効かない・行の詳細に『家族の言葉』として出す」。

## 作る物

1. **医療班の機器「その他」の名前**: lib/labels.ts に `deviceText(d: { kind; detail? })`（hazardText と同じ形。「その他（電動ベッド）」、ほかの種類は DEVICE_LABELS のまま）。lib/custody/board.ts:208 と、同じく DEVICE_LABELS[d.kind] で機器を並べる所（`grep -rn "DEVICE_LABELS\[" lib components` で洗う。lib/caseload.ts の devices、lib/forms/medical-summary.ts:942 の tierLine。様式の欄は T57 で直っている所は変えない）を deviceText に。現場の登録: StaffIntake の「その他」を選ぶと名前の欄（1 行、40 字）が開き、空なら送らない（T57 の編集と同じ理由: 名前が無いと何か分からない）。lib/custody/forms.ts の OnSiteInput を `devices: Array<{ kind: DeviceKind; detail?: string }>`（その他だけ detail、ほかは落とす）に、store.ts の onSiteLedger が detail を Ledger に写す。テスト: 往復と、その他で名前が空の拒否、deviceText。
2. **QR の期限**: migration 0015 で `people.qr_ttl_days INTEGER NOT NULL DEFAULT 90 CHECK (qr_ttl_days IN (30, 90, 180))`（0007 と同じ ADD COLUMN）。lib/qr/store.ts の QrRow に足し、qrState・currentQrToken・resolveQrToken が**行の日数**で期限を出す・確かめる（`p.exp === iat + ttl * 86400`。固定の QR_TTL_SEC は既定の 90 として残す）。lib/qr/token.ts の signQrToken・verifyQrToken の上限は 180 日に（「期限なしは作らない」「上限より長い物は署名が合っても通さない」はそのまま）。作る・作り直す（app/api/people/[id]/qr/route.ts の issueQr）が日数を受ける（フォームの `ttl`。集合の外は 400）。QR の画面（app/people/[id]/forms/qr/page.tsx）の「作成」「再作成」の横に期限の選択（30・90・180 日。既定は今の行の値）。本人の 1 枚の裏・QR の紙の期限（qrExpiryDate）は qrState から出るので行の値で変わる。テスト: 行の日数で期限が変わる、別の日数で署名した token が通らない、作り直しで前の版が通らない（今のテストのまま）、180 日より長い物を作れない、migration 0015 の契約（既定 90・既存の行）。
3. **録音の分類「その他」**: RECORDING_CLASSES に `other`（unknown の前）。lib/classify/prompt.ts に 1 行「other（その他）: はっきり言っているが上の 4 つのどれでもない（食べ物・水が無い、家族と連絡が取れない、不安、頼みごと など）」、「unknown はほかと一緒に選ばない」はそのまま（other は 4 つと一緒に選べる。other だけなら other）。lib/classify/labels.ts の CLASS_LABELS に「その他」。zod（classify.ts:72・http.ts の ClassEditBody）・画面の修正の選択肢（components/list/Classification.tsx）・CONFIDENCE_MIN の落とし方は RECORDING_CLASSES から自動で広がるので確かめるだけ。signals.classes は json_valid だけの列なので migration は要らない。lib/triage は**行と決め方を変えない**（injuryWords は injury・immobile しか見ない）。ただし lib/triage/index.ts:505 の行の説明（`input:` の字「…不明を含む」）と lib/triage/doc.ts:28 の「5 つに分ける」（docs/TRIAGE.md:5 の元）が分類の名前と数を書いているので、**字だけ**直して `npm run docs:triage` で TRIAGE.md を作り直し、lib/triage/*.test.ts と lib/triage/heavy-rain.test.ts の 10 人の色・並び・理由が変わらないことを確かめる（match・apply には触らない）。lib/seed/demo.ts が RECORDING_CLASSES を読むので落ちないことを見る。テスト: classes が ["other"] の赤と [] の赤と ["unknown"] の赤で色・順・理由が同じ、other と injury を一緒に返したときの理由（AI の印つきの「録音の分類（AI）: けが」だけ。other は理由に出さない）、Claude が other と unknown を一緒に返したときの落とし方、人の修正で other を選べる。
4. **テスト・docs**: 1〜3 のテストは lib/custody/t64.test.ts・lib/qr/t64.test.ts・lib/classify/t64.test.ts に分けてよい。docs/progress/t64.md（Claude を使う所・使わない所を 1 行: 3 だけ Claude の出力の種類が 1 つ増え、色と順には使わない。1〜2 は Claude を呼ばない）。仕様と違う決めは docs/DECISIONS.md に案として（QR の日数の集合、「その他」の定義）。
