# T01 ログインと役、事業所の切替、審査員ログイン

## 目的

誰がどの事業所の何の役で開いているかを持つ。本運用の認証ではなく、ハッカソンの間に要る最小の物。審査員は提出書類の ID とパスワードでデモ事業所に入り、役（ケアマネ・医療班・本人のスマホ・家族のスマホ）を選ぶだけ。

## 読む物

docs/SPEC.md の「アカウント」「作り」（審査員用の公開デモの段）、「画面 7 事業所の設定」。migrations の accounts の表。

## 作る物

- ログインの画面 `/login`: ID とパスワード。パスワードは `JUDGE_PASSWORD_HASH`（審査員）か accounts の列（ハッシュ。平文を入れない）。cookie のセッション（HttpOnly、`SESSION_SECRET` で署名、7 日。手元は `.dev.vars`、配信は secret）
- 役: ケアマネ・管理者・行政/医療班・審査員。審査員はログイン後に「役を選ぶ」画面で ケアマネ（山本）・医療班・本人のスマホ（山田 ハナ）・家族のスマホ（山田の娘）のどれかで入る。選び直せる
- 事業所: デモ事業所（審査員・動画）と協力事業所（協力してくれるケアマネの訓練。審査員には見せない）。種に協力事業所の枠を足す（利用者は入れない。ケアマネ 1 人を空の名前で）
- サーバー側の守り: 事業所をまたいで本人を読めない（行政・医療班は受け持ちの範囲だけ。T23 で広げる）
- ログアウト。ヘッダーの右上に 事業所名 と 役
- 本番のアカウントの作り方（管理者がケアマネを足す）は T27 の前に最小で

## 終わりの形

- 審査員 ID で入ると役を選ぶ画面 → 担当一覧。ケアマネで入ると担当一覧。行政/医療班で入ると受け持ち（T23 までは空の一覧）
- 違う事業所の本人の id を URL に入れても 404
- テスト: セッションの署名、役ごとの到達、事業所の壁

## 触るファイル

app/login、app/(役ごとの入口)、lib/auth/、middleware か layout の確認、migrations（accounts と sessions。配信前なので 0001 を直してよい）、seed、docs/PROGRESS.md

## 守ること

審査員の ID とパスワードをリポジトリ・README・動画に書かない。種に入れるのはハッシュだけで、ハッシュの元の文字列は作者が決める（`JUDGE_PASSWORD_HASH` の作り方を README でなく docs/PROGRESS.md に 1 行）。
