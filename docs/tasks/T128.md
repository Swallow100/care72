# T128 訓練の画面を PC で「何が起きてきたか」が送らずに分かる形に（上の帯・経過の置き場所・新着・区域の対象）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。訓練の骨組み（docs/tasks/T17.md）、連続の時計（T90）、訓練の世界（T104）、経過の 3 つのタブ（T105）と、その進み（docs/progress/t90.md・t104.md・t105.md）を読む。画面は app/drill/[id]/page.tsx（並び）、components/drill/DrillBar.tsx（上の 72 時間の棒）、components/drill/DrillLog.tsx（経過: 発生・把握・対応）・Situation.tsx・DamagePanel.tsx（被害状況）、lib/drill/view.ts（画面の形）・timeline.ts（経過の分け方）。

## 前提

ケアマネ・事業所・行政の画面は基本 PC で使う。1920×1080・1536×864・1280×800 で、画面を送らずに分かることを主に作る。375 は崩れないかだけ見る。

## 意図（なぜこの作業か）

本番の地震想定を PC の広い画面（1920）で回したところ、次の 2 つが分かりにくかった。

1. **何が起きてきたかが分かりにくい**: 上の時間の帯は「停電」「電話」の 2 段だけで、横の空きが多い。経過（発生・把握・対応）は対応の欄の下にあり、画面を送らないと見えず見落としやすい
2. **区域の出来事の対象が分からない**: 被害状況の津波に「避難」とだけ出て、誰が対象か（事業所自身も対象か）が分からない

## 作る物

### 1. 上の時間の帯を「何が起きたか」の一覧に

- 72 時間の軸に、出来事を種類の段（災害〔地震・津波・警戒〕・ライフライン〔停電・通話不可・断水・道路〕・避難所・人の連絡〔赤・着信〕・自分の対応）に分けて印で置く。段はやりすぎず、要る物だけ。空の段は出さない
- 印に触れると、その出来事の 1 行（時刻・種類・文・対象）。押すと経過のその所へ（タブを替えて行まで送り、行に印）
- 段ごとに今の様子を短く（例「停電中 6 時間」「沿岸の道 通行止」）
- 進行中は、ケアマネが知り得ない物（本人に起きたこと）を出さない（経過の発生のタブと同じ表 lib/drill/timeline.ts）

### 2. 経過を PC で送らずに見える所に

- 1920・1536 では経過を列の 1 つに（表・対応・経過・被害状況と地図）。1280 では対応と経過を切り替える。表（左）・対応・被害状況と地図も見えたままにする
- 画面の中にスクロールの箱を作らない（CLAUDE.md）

### 3. 新着

- 進める・手のあとに新しく起きた事（発生・把握）を、目に入る所に短く出す（多いときは数件と「他 N 件」）
- 経過の行には新着の印。見たら消える（端末の sessionStorage で十分。文は入れず、見た行の鍵だけ）
- 再生（終わった訓練）では出さない

### 4. 区域の出来事の対象

- 津波・避難指示・土砂の警戒・停電の地区など区域の出来事は、被害状況の行と帯の印に対象を出す（例「避難 対象 3 人 伊藤・… 事業所 対象外」）。人を押すと左の表のその人の行へ
- 対象を決める決まりは同時に動く T125 が lib/drill に 1 つの関数（出来事 → 対象の人の id と事業所が対象か）として作る（名前と形は docs/progress/t125.md）。まだ無ければ、台帳のハザード（tsunami・flood・landslide）で仮に出す形にし、取り込みでそろえる。呼ぶ所は 1 か所にして差し替えを import の 1 行にする
- 事業所のハザードがまだ無ければ「事業所」の部分は出さない（対象外と言い切らない）
- 地図でも対象の人のピンが分かるとよい（地図の部品の中は小さな足しだけ）

### 5. 手の時刻の書き方

- 今は時刻の範囲を「1 時間〜2 時間」のように書き、同じ時間の中なら終わりを分だけにする（lib/drill/busy.ts の spanLabel。「2 時間〜2 分」）。そのうしろに所要（「60 分」）と理由（「浸水」）を詰めて並べるので、「2 時間 60 分」や「2 分2 分」と読み違える
- 時刻の範囲と所要を分ける: 訓練の中の時刻「13:44〜14:44」と「所要 60 分」、所要の理由は別の小さな文字で。夜間発災の訓練は訓練の中の時刻（深夜 2 時から）、日をまたぐ範囲は終わりに日付
- 対応の結果・経過の対応・訓練記録の紙面・採点・職員の空き（次空）で同じ書き方にそろえる。書き方は lib/drill に 1 か所

### 6. 切替の下線

- 経過の切替（発生 6・把握 14・対応 2）の選んだ印の下線が、名前と数字で 2 本に分かれる。名前と数字をまとめて 1 本の下線に
- 同じ形の切替はほかの画面にもある（components/ui/Tabs）。部品の側に見た目を 1 か所持ち、経過の切替もそれを使う

### 7. 訓練の上の操作を減らす

- 時間を進めるのは「次まで」だけにし、「30 分」「1 時間」「3 時間」を外す
- 「手の分」は、「次まで」が手に使った時間も閉じるなら要らないので外す（閉じることをテストで確かめる。閉じなければ閉じる形にしてから外す）
- 早送りは残す（決まった間隔で「次まで」をくり返す物と見て分かる言い方に）。間隔の選択は外す
- 中断は今のまま。API の口（30 分などの進め方・手の分）は、テストと評価の台が使うので残し、画面から外すだけ

## 守ること

- 色と連絡順は lib/triage の表だけ。帯・新着・対象は色と連絡順に使わない。色は安否の色と、今の被害状況の要確認の色だけで、段ごとに新しい色を作らない

- 文書に作者の発言の引用・作業のやり取り・人の名前を書かない（公開のリポジトリ）。作業者の一時ファイルは scratchpad の `t128/` の下
- `npx vitest run --maxWorkers=3` と `npm run typecheck`。手元の訓練の見本で 1920・1536・1280・375 とライト・ダークの絵を docs/progress/t128/ に
- PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす）。merge commit にも Co-Authored-By。PR は integrate/t11-t12 宛で merge しない
