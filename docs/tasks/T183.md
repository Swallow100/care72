# T183 デモの 10 人に避難先の位置を足し、そらみ台の人の家の位置を直す

作者の指示（11/7 22 時）: デモの利用者に避難先の位置を足し、担当一覧の地図に計画の避難先の旗を出す。

今は種の 10 人（seed/people.ts）に避難先の位置（ledger.evacuation.destination1Location・2）が無く、担当一覧の地図の計画の避難先の旗は 0 本で「避難先 位置なし」だけ出る（docs/progress/t169.md の問い 1）。避難先の名前は架空（「そらみ台小学校」など）。また p-09（そらみ台、台帳はハザードなし）の家のピンが、重ねる洪水の層で 0.5〜3 m の区域に入り、種の注「なしはどの層も無い所」と食い違う（docs/progress/t170.md の問い 1）。

進みは docs/progress/t183.md。worktree care72-t183、branch task/t183（origin/integrate/t11-t12 から）。

## やること

1. 種の 10 人の避難先を、家のピンの近くの実在の指定避難所・指定緊急避難場所（国土地理院のデータ。lib/map/shelters.ts が読む物と同じ）にする。名前と位置をそのデータの物にそろえる（地図の地理院の旗と計画の旗が同じ施設として 1 つにまとまるように）。本人の台帳のハザード（大雨・土砂・地震）に合う種類を選び、洪水の区域の人の避難先は洪水の区域の外に。避難先 2 がある人は 2 も
   - 取ってきたデータは数と形だけ記録に。施設の一覧を repo に丸ごと写さない（種の 10 人ぶんの名前と位置だけ）
2. p-09 の家のピンを、近くのどの層（洪水・土砂・津波）にも入らない所に動かす（町は同じそらみ台のまま）。ほかの 9 人も、台帳のハザードと重ねる層が食い違っていないかを見て、食い違えば同じく直す
3. 種の名前・位置に頼る所を全部合わせる: seed/generated/seed.sql（作り直しの道具で）、seed のテスト、確認用の事業所の写し、訓練の想定の表・筋書き（lib/drill の scenarios など）・医療班の受入依頼（lib/seed/requests.ts）・紙面のテスト・評価の台の正解（tools/eval の fixtures）。grep で旧の避難先の名前を全部探す
   - 評価の台の正解を変えたら、変えた物と、次の本物の回（r12）の数の比べに効く所を記録に書く
4. 本番では毎朝 4 時のデモの戻し（lib/seed/reset.ts）で新しい種になる。戻しの道で新しい位置が入ることをテストで確かめる

## 守ること

- 台帳の項目を増やさない。名前から位置を推し量る作りを足さない（種のデータに入れるだけ）
- 触らない所: lib/auth、lib/custody（T180）、lib/forms の読み取りの決まり（T181）、lib/drill の engine・person-facts・hooks（T182）。lib/drill の想定の表の名前を変えるときは文字だけ
- 本物の AI の API は呼ばない

## 確かめ

全部のテスト（--maxWorkers=2）、`npm run -s typecheck`。手元の dev で担当一覧の地図を 1280 で開き、ズーム 16 で計画の避難先の旗が出て、地理院の旗と重なっていないことを絵で見る。p-09 のピンが洪水の帯の外にあることを絵で見る。

## 終わりの形

PR を integrate/t11-t12 宛てに。docs/progress/t183.md に、10 人の前後の表（避難先の名前・種類・家との距離）・動いたピン・変えた評価の正解・絵のパス。
