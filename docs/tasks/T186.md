# T186 訓練の参加者は 20 人まで、越えたら参加者を選ぶ

作者の指示（11/8 0 時台）: 訓練の最大人数を 20 人にする。それより多い場合は、訓練に入れる人を選ぶ画面を出す。

進みは docs/progress/t186.md。worktree care72-t186、branch task/t186（origin/integrate/t11-t12 から）。

## やること

1. 今の訓練の参加者の決め方（lib/drill/db.ts の開始、app/drill の開始の画面、事業所・ケアマネの担当）と、人数の上限が今あるかを調べて記録に
2. 上限を 20 人（定数 1 か所）。担当（または事業所）の人が 20 人以下なら今のまま全員で始める
3. 20 人を越えるときは、開始の画面で参加者を選ぶ: 一覧（名前・町・台帳の要点〔機器・ひとり暮らしなど〕）にチェック、既定は台帳の順（ルールの表の連絡の順か、今の並び）の上から 20 人、選んだ数を「選択 18 / 20」の形で。20 を越えては選べない。0 人では始められない
4. サーバー側でも 20 人を越える開始は断る。選んだ人がその事業所（壁）の中かを確かめる
5. 仮想の世界の部屋（lib/drill/world-room.ts）・本人役・講評など、参加者の数に頼る所が選んだ人だけで動くことを確かめる
6. 新規事業所（審査員の試用事業所）でも同じ

## 守ること

- 画面の決まり（CLAUDE.md）と言葉の決まり（短い漢語、常設の説明文を置かない、「札」を使わない）。チェックの選んだ印に下地を敷かない
- 触らない所: lib/drill/review.ts と講評の画面（T185）、lib/forms、lib/auth、lib/custody
- migration は足さない形で（要るなら docs/deploy/migrations.lock で 0040 を取ってから）
- 本物の AI の API は呼ばない

## 確かめ

関係するテスト（lib/drill・app/drill、--maxWorkers=2）、`npm run -s typecheck`。手元の dev で、21 人以上の事業所（テスト用に手元の D1 に足す）で選ぶ画面を 1280 で絵に撮り、20 人で始めて進むこと、20 人以下では今のままであることを見る。

## 終わりの形

PR を integrate/t11-t12 宛てに。docs/progress/t186.md に作り・絵のパス・言葉の一覧。
