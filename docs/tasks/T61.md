# T61 アカウントの幅（名前の変更・管理者の付け外し・停止・パスワード。種と審査員は固定）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md`（何を作っているか・越えない線・地図・進め方）→ `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）


- ケアマネのアカウントは足すだけ（lib/office/staff.ts の addCareManager）。名前の変更・管理者の付け外し・停止（退職）・自分のパスワードの変更が無い。app/api/auth は login・logout・role の 3 つだけ。本運用でケアマネが辞めても、初期パスワードを忘れても、何もできない。
- 外していた理由は「審査員のログインの導線を壊す危険」。審査員は皆で 1 つの judge を共有し、ケアマネの役では種の山本（acct-yamamoto）の担当一覧を開く（lib/auth/principal.ts の judgePrincipal）。judge のパスワードは env の JUDGE_PASSWORD_HASH で決まり（lib/auth/credential.ts・demo.ts）、表の行ではない。山本も env の CAREMANAGER_DEMO_PASSWORD_HASH が表より先に効く（credential.ts の accountCredential）。1 人の審査員が山本を停止・改名・パスワード変更できると、次の審査員が詰む。毎朝 4 時の戻し（lib/seed/reset.ts）で名前は戻るが、日中は戻らない。
- だから、種のアカウントと judge は「変えられない形」にする。審査員のケアマネの役はもともと管理者でない（lib/office/scope.ts の officeActor は `admin: p.admin && !p.judge`）ので管理者の操作は届かないが、「自分のパスワード」の口は新しく作る物なので、ここで塞ぐ。

線: この作業は Claude を呼ばない。色と連絡順（lib/triage）には触れない。平文のパスワードは表・経過・ログ・URL に出さない（staff.ts の注のまま）。
