# T145 本人のページの面の編集を、区分の中の小さな組に分けて、どこが何かを分かりやすく（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T45 の頼み文と進み（面の「編集」）、components/person/SectionEdit.tsx（面の編集）・PersonView.tsx（読む側）、lib/intake/fields.ts（台帳の欄の表と区分）・lib/intake/edit.ts（編集の下書きと変更）、lib/person.ts（区分と読む側の欄 FIELDS）、lib/intake/ask.ts（問いの順）、lib/labels.ts を読む。

## 意図（なぜこの作業か）

本人のページの面の右上の「編集」（T45）を押すと、その区分の項目が入力の欄に変わる。区分の中は 1 本の長い並びで、本番で使うと次の所で手が止まる:

- 基本の面は 市・町名・位置・性別・世帯・連絡の手段・介護度・心身の 8 項目・手帳・難病・特記が切れ目なく 20 行以上続き、今どの辺りを直しているのかが分かりにくい
- 避難の面は 避難先・手段・経路・住まい・持出品・様式のために足した欄（T117）が混ざって並び、欄の表の並び（足した順）のまま出ている
- 関係者の面は 家族・支援者・民生委員・かかりつけなどの連絡先が種類に関係なく並ぶ。連絡先の行の文字の欄は欄の名前が下書きの字だけで、入れると何の欄か（電話か携帯か、続柄か備考か）が見えなくなる

区分の中を小さな組に分け、組ごとに短い見出しを付けて、どこが何かが一目で分かる形にしたい。組の分け方は 1 か所の表に持ち、あとで読む側の画面と問いの順も同じ並びにそろえられるようにする。

## 作る物

1. **組の表**: lib/intake/fields.ts に、区分ごとの組（見出しは 2〜4 字の漢語）と、組に入る項目の鍵の表を 1 つ。鍵は台帳の欄の表（INTAKE_FIELDS）の鍵と、表の外の項目（薬・機器・時計・ハザード・住所・位置・特記・同意・連絡先の種類）を、lib/person.ts の FIELDS と同じ書き方で。関係者の組は連絡先の種類（CONTACT_KINDS）も持つ。区分は今のコードのまま（住まいは避難、心身は基本）。編集の画面・読む側の画面・問いの順で同じ並びに使えるように用意し、使うのは今回は編集の画面だけ（読む側の画面と問いの順は変えない。INTAKE_FIELDS の並びも変えない）
   - 組の例: 基本 → 本人・住所・連絡・認定・移動・感覚・認知・特記／医療 → 薬・機器・時計・既往／避難 → ハザード・避難先・経路・支援・住まい・持出・計画／関係者 → 家族・支援者・地域・関係先・本人電話／同意 → 登録・提供
2. **編集の画面**: 面の編集を組ごとに分けて出す。組の間は地の色の差で区切り、枠線を重ねない。組が 3 つ以上の区分は、組の見出しへ飛べる小さな目次を面の上に横に並べる。今どの組を直しているか（入力の欄に入った組・目次で飛んだ組）の見出しを強くする。関係者の面は連絡先を種類の組に分け、足す行は組ごとの「連絡先追加」から（その組の種類で始まる）。連絡先・薬・時計の行の文字の欄は、入れたあとも欄の名前が見える形に
3. **今の動きは変えない**: 保存・取消・外す・戻す・値確認・確認・順番重複・本人重複・未入力の止め・競合・未確認の数は今のまま。送る変更（lib/intake/edit.ts の editChanges）は変えない
4. **使わない型**: CLAUDE.md の避ける型（details の既定の▼・ピル型・番号のラベル・等幅のラベル・グラデーション・光る影・選んだ印のテーマ色の薄い下地など）は使わない。画面の中にスクロールの箱を作らない
5. **絵とテスト**: PC（1920・1280）と狭い幅（390）、ライトとダークの絵を docs/progress/t145/ に（人は種の架空の 10 人）。テスト: 組が台帳の欄の表と読む側の欄を漏れなく覆う・同じ項目が 2 つの組に入らない・連絡先の種類が 1 つの組にだけ入る・組の鍵に打ち間違いが無い・画面の各欄がその鍵を持つ組の中に出る
