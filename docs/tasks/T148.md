# T148 事業所の情報・複数の市にまたがる地域・ケアマネの ID とパスワード

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T61・T68・T79・T81・T115 の頼み文と進み（docs/progress/t61.md・t68.md・t79.md・t81.md・t115.md）、docs/DECISIONS.md の「アカウントと事業所」を読む。コードは app/office・components/office（事業所の画面・準備の欄・地域・ケアマネ追加）、lib/office（staff.ts・place.ts・setup.ts・forms.ts・http.ts）、lib/auth（password.ts・credential.ts・password-change.ts）、migrations（offices の city・center_lat/lng、0030 の事業所のハザード）、気象庁の欄（lib/jma）、地図の中心（lib/map/center.ts・components/map/CaseMap.tsx）、災害の状態（lib/disaster）、雨雲（lib/jma/nowcast.ts）。

## 意図（なぜこの作業か）

新しい事業所・試用事業所（T115）を最初から使うと、次の 3 つで止まる。

1. 事業所の名前・住所・電話・事業所番号を入れる所が無い。名前は事業所を作る道具で入れたまま変えられず、計画書・様式 9 の事業所の欄（T131 の事業所名・担当ケアマネ）はその名前を読むだけ。
2. 地域は「市 1 つ＋中心」（T68）。担当の利用者が隣の市にもいる事業所が多いのに、気象庁の欄・地図・雨雲・上の帯・事業所の区域・様式の一覧の初めの選択が、1 つの市か利用者の住所の市のどちらかから別々に決まる。どこで地域を直せば何に効くかが分からない。
3. ケアマネを足すとき、ID は決められるが、パスワードはサーバーが作った物を 1 回だけ見せる形しか無い。その場で本人が決めたパスワードを入れる道が無い。パスワードの決まり（8〜64 字）は今のパスワード変更の 1 か所にしか無く、作るパスワードと決まりがそろっていない。

線: この作業は Claude を呼ばない。色と連絡順はルールの表（lib/triage）のまま触らない。気象庁の警報・注意報は見せるだけで、災害モードは切り替えない（押すのは人）。パスワードは画面・記録・ログ・URL・応答に平文で残さない（ハッシュだけ。サーバーが作った初期パスワードを 1 回だけ見せる形は今どおり）。

## 作る物

1. **事業所の情報**: 事業所の画面に「事業所」の区分。事業所名・所在地・電話・FAX・事業所番号（介護保険の 10 桁）を入れて直せる。書けるのは地域と同じ人（事業所の管理者・試用事業所の審査員。デモ事業所の審査員は見るだけ）。名前は計画書・様式 9・本人の 1 枚・医療要約・様式の対応表の事業所名の欄にそのまま入る（今の officeName の道）
2. **地域を複数の市に**: 事業所の地域を「主な市＋周りの市」で持つ。広さ（km）と事業所の区域（0030 の洪水・土砂・津波）も同じ区分で置く。その地域が次にそろって効く:
   - 気象庁の警報・注意報の欄（どの市の発表を出すか。主な市 → 周りの市 → 利用者の住所の市の順）
   - 地図の中心と広さ（ピンが無いときの初めの表示と「地域」の表示。ピンがある事業所の初めの表示は今のまま）と、その上に重ねる雨雲
   - 上の帯の災害の状態（地域の市に出ている警報の数を添える。表示だけ）
   - 事業所の区域（offices.hazards、訓練の区域の出来事）
   - 様式の一覧の「地域から選ぶ」の初めの市（地域の市を順に見て、一覧にある最初の市）
   - 利用者の住所の市で地域に入っていない市があれば、地域の区分に「地域に追加」を出す
3. **ケアマネの ID とパスワード**: ケアマネ追加で ID とパスワードを決められる（パスワードを空にすれば今どおりサーバーが作って 1 回だけ見せる）。決まりは 10 字以上で大文字・小文字・記号を含む物（64 字まで）。決まりは 1 か所に置き、追加・管理者の再設定・自分の変更・サーバーが作る初期パスワードがみな同じ決まりを通る。本人は今のパスワード変更で変えられる。管理者は再設定できる（決めたパスワードか、サーバーが作る物）。ID の重なりは今どおり断る。審査員のアカウント・変えられないアカウント（FIXED_ACCOUNT_IDS）と試用事業所の決まり（T115・T81 の judge_made）は今どおり
4. **migration**: 要るなら 0035（offices に列を足すだけ。ほかの作業と重なったら取り込みで付け直す）。種のデモ事業所の名前・所在地・地域は架空の値で埋める（デモ事業所は松山市の中心のまま）。種の 10 人の中身には触らない
5. **テスト**: 事業所の情報の保存と様式への反映、地域の複数の市が気象庁の欄・地図・上の帯・様式の一覧に効く、地域に追加の候補、パスワードの決まり、ID の重なり、審査員と変えられないアカウントは今どおり。PC の幅の絵

## 終わりの形

- 新しい事業所の管理者が、事業所の画面で事業所の情報と地域（主な市・周りの市・中心・広さ・区域）を置け、それが気象庁の欄・地図・上の帯・訓練の区域・様式の一覧の初めの市にそろって効く。利用者の住所に地域の外の市があれば「地域に追加」で足せる
- ケアマネ追加で ID とパスワードを決められ、決まりに合わないパスワードは断る。管理者は再設定でき、本人は変えられる
- デモ事業所の 10 人の地図・色・並び・審査員の流れは前と同じ。`npx vitest run --maxWorkers=3`・`npm run typecheck` が通る。PR を integrate/t11-t12 宛に

## 守ること

- 色と連絡順はルールの表（lib/triage）だけで決める。気象庁の警報は表示だけで、色・順・災害モードに使わない。この作業は Claude を呼ばない
- 審査員の流れ（ログイン → 役 → デモ事業所の 10 人）を壊さない。デモ事業所の事業所の情報・地域は審査員が書けない（地域と同じ placeEdit）。審査員と変えられないアカウントの決まりは今どおり（lib/auth/demo.ts は触らない。同時の作業が触る）
- パスワードの平文を表・経過・ログ・URL・応答・progress・commit に書かない。管理者が決めたパスワードは応答で返さない。鍵（env の値）を読まない・探さない
- 画面の言葉は 2〜4 字の漢語（事業所・名称・所在地・電話・FAX・事業所番号・主な市・周りの市・広さ・区域・地域に追加・条件不足など）。常設の説明文を置かない。見出しに読点・句点を付けない。使わない語: 診断・判定・重症・緊急度・札
- 見た目の避ける型（CLAUDE.md）。選んだ印にテーマ色の薄い下地を敷かない。新しい押せる物・入れる欄には focus-visible:outline-solid
- 同時の作業: T144（審査員のアカウント 3 つと確認用の事業所。lib/auth/demo.ts・seed の事業所とアカウントの行・migration 0035 の予定）、T146（読み取りの頁と計画の状態）、T147（書類の画面）。seed/people.ts は SEED_OFFICES の行の中だけ、lib/office/staff.ts は追加と再設定の 2 つの関数だけ。PR の前に origin/integrate/t11-t12 を取り込む（両方を活かす）
