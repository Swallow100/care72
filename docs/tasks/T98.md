# T98 初めて入った管理者の準備の欄

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。

## 意図（なぜこの作業か）

tools/office/new-office.ts で作った事業所の管理者で手元からログインすると、担当一覧は 0 人の「なし」、事業所の画面は地域「未設定」・ケアマネ 1（自分）・担当 0 人の「なし」が並ぶだけで、何から始めるかが画面から分からない。する事は決まっている（パスワード変更・地域・使用様式・ケアマネ追加・利用者追加・担当）ので、残っている物だけを短い言葉で出し、済んだら消す。

## 作る物

1. **準備の欄（事業所の画面 /office の一番上、管理者だけ）**: 残っている物を 1 行ずつ、言葉は 2〜4 字（例: 地域 未設定・ケアマネ追加・利用者追加・担当 未割当 3）。行を押すとその区分へ（/office の区分の id。今の保存のあとに戻る所と同じ id）。全部済んだら欄ごと出さない。常設の説明文は置かない
   - 地域: 事業所の中心（center_lat・center_lng、lib/office/place.ts）が無い
   - ケアマネ: 使えるケアマネが管理者だけ（1 人で回す事業所もあるので、押して閉じられる「後で」を付けるか、欄に出すだけで止めない）
   - 利用者: 担当一覧に人が 0
   - 担当: 担当の無い利用者がいる（数）
   - パスワード: 初期のままかを持つ列は無い（migration を足さない）。出さない
   - 使用様式: 既定（lib/forms/plan-form.ts の defaultPlanForm）で入っているので出さない
2. **担当一覧（/）の 0 人のとき**: 「なし」の所に、管理者には「利用者追加」の主のボタン（右上の物と同じ）。ケアマネ（管理者でない）には「なし」のまま（足すのは管理者だけの事業所もある。今の決まりに合わせて、誰が利用者追加できるかは変えない）
3. **デモ事業所と審査員**: デモ事業所は種で全部済んでいるので欄は出ない。審査員のケアマネの役（管理者でない）にも出さない
4. **テスト**: 残りを数える関数（lib/office に。地域なし・ケアマネ 1・利用者 0・担当なし N・全部済み）を単体で、事業所の画面の描き（管理者だけ・全部済みで出ない）。`npm test`・`npm run typecheck`。画面は new-office.ts の試しの事業所を手元の D1 に入れて（--local）、375・768・1280、ライトとダークで、1 つずつ済ませて行が消えるのを見る

## 触るファイル

app/office/page.tsx、components/office/（準備の欄）、app/page.tsx（0 人のとき）、lib/office/（数える関数）、docs/progress/t98.md

## 守ること

画面の決まり（CLAUDE.md）: 言葉は 2〜4 字の漢語、説明文を置かない、番号のラベル（01/02）を付けない、色の枠は使わない。準備の欄は印刷に出さない。
