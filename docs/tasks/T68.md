# T68 地域と住所（本人の住所・位置・本人の電話、連絡先のスマホ・車、事業所の市と中心、様式の既定、写真の縮小。migration 0017）（Opus、分岐）

## 意図（なぜこの作業か）

地域を設定してもその地域にならない。実際に使うときに使える形にする。監査で追うと、新しい事業所が画面から利用者を足しても、住所（市・町名）と地図の位置を入れる道が無い（入れる欄の表 lib/intake/fields.ts に無く、利用者追加は氏名・カナ・生年月日・性別・担当だけ lib/office/forms.ts）。台帳の型（lib/db/types.ts の Ledger.basic.address・location）と列（contacts.has_smartphone・has_car）はもうあるが、種だけが入れている。結果:

- 地図はピン 0 人で中心は松山の市街（components/map/CaseMap.tsx の FALLBACK）。停電の地区の候補が空（app/office/page.tsx の towns は台帳の町名から数える）。様式の住所はいつも「未確認」（lib/forms/matsuyama.ts・medical-summary.ts・form9.ts・own-sheet.ts はもう basic.address と本人の電話〔連絡先の kind self〕を読む）。
- 訓練の本人役は「押せる人」（本人のスマホ「使える」か連絡先の has_smartphone）が無いと呼ばれない（lib/drill/persona.ts の reportersOf）が、スマホ・車の有無を画面で入れられない。本人の電話（self）も作れない（lib/intake/schema.ts の CONTACT_KINDS_FOR_EDIT が self を外している）。
- 事業所の市（offices.city）は種だけが入れ、どの画面も読まない。
- 既定の様式が松山市で、選んでいない事業所の計画書が「（あて先）松山市長」。写真・PDF は 5 MB 超を断り、iPhone の写真は断られやすい。

線: 色と連絡順はルールの表（lib/triage）だけで決める。この作業は表の入力（町名で停電の地区を当てる lib/disaster/state.ts の inOutageArea、押せる人）を人が入れられるようにするだけで、表の行・並びは変えない。**住所・位置・本人の電話は手入力だけで、AI の分け方（Claude）には足さない**（Ledger の location の注のとおり。入れる欄の文に新しい町名が混ざると、仮名化の門が知る前に Claude へ届く）。
