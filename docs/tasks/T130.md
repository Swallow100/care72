# T130 訓練の本人役・世界の「人ごとの筋」を崩さない（人ごとの事実の帳面・計画が効く・出来事の重なり・講評の数・結末の理由）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。評価の 3 回目の報告（origin/eval/r3 の docs/progress/eval-r3-findings.md・eval-drill-r3.md。この作業は 1・2・6・7・8）と、訓練の作り（docs/tasks/T50・T93・T121・T123 とその進み、lib/drill の persona.ts・engine.ts・world-apply.ts・review.ts、tools/eval/drill の checks.ts）を読んでから始める。生の記録はリポジトリの外（評価の台の記録の置き場）にあり、読むだけ。中の架空の人の台詞をリポジトリに写さない。

## 意図（なぜこの作業か）

評価の 3 回目（本物の Claude）で、訓練の AI に次の問題が残った（findings の番号）。

- #1 人ごとの筋（審査役）が 3 回とも 2/5 で、1 回目から変わらない。審査役の根拠に挙がった種類: 電池が少ないと言ったあとも長く落ち着いたまま、避難所に着いたと言う一方で家で過ごすと答える、同居の家族があとから来たとされる、停電が戻ったあとも電池を頼み続ける、家族が声が無いと伝えたあとに本人が普通に話す、電池が切れた少しあとに予備に替えている、業者の巡回で手を打たなくても酸素や電池が届く
- #2 赤（動けない）から、手も到着も無いまま緑に変わる（10 人全員の回で 5 回中 3 回。どれも表の行の無い、本人役が自分で決めた連絡）
- #6 10 人全員の回で出来事が似る（倒木・薬局の休止・家族の帰宅困難が、別の人に同じ文言で出る）
- #7 講評の指摘がいつも 8 件（中身に合わせた数になっていない）
- #8 仮想の世界の結末の理由に医療の言い方が入った

T121・T123 は世界の側の状態（変わった時刻・変わり方の決まり・話し手）を足したが、本人役が自分で言った事・頼んだ事・いる所・機器の電池の扱いは、どこにも事実として残っていない。だから次の呼び出しの本人役は、前に言った事と食い違っても気づけず、コードも止められない。

考え方: **筋の事実はコードが持ち、AI はそれに沿って言葉を作る。AI が事実を変えてよいのは決まった口だけ。** 人ごとの事実の帳面を作り、刻みごとにコードが更新して、次の刻みの本人役と世界に渡す。帳面に反する答えは使わない。

### 計画が効く（追加）

連絡が取れない時にこそ、事前に決めた行動が効く。本人・家族の本人役と世界は、その人の台帳と計画書の中身（停電時の電源・予備の電池やボンベ・避難先・頼る病院や施設・家族の役割など）を事実の帳面に持ち、ケアマネと連絡が取れなくても計画どおりに自分で動く（停電したら予備に替える・決めた避難先へ向かう）。計画に無い事は勝手に良い方へ動かさない（計画が無い・薄い人ほど手が要る形）。採点・講評で「計画で動けた人」と「計画が無く手が要った人」が分かるように記録に残す。

## 作る物

1. **人ごとの事実の帳面**（lib/drill の新しいファイル）
   - 居場所（家・避難所・病院・移動中）、同居・そばにいる人、機器と電池（内蔵・予備・外部、切れた時刻、替えた時刻と誰が）、届いた物と手（誰の手で・いつ）、話せるか、言った事の要点（動けない・けが・電池が少ない など、コードの決まった印で）
   - 計画（台帳から）: 停電時の予備・外部の電源、避難先と移動の手段・手伝う人、頼る施設、在宅避難
   - 本人役・世界・監督の答えと手の結果から、刻みごとにコードが更新し、次の刻みの本人役・世界・監督に渡す（drills.world の JSON。migration は要らない見込み）
2. **帳面に反する答えを使わない**（直すか、固定の形に落とす。落とした数は決まりの名前で世界に数える）
   - 避難所・病院にいるのに家にいる、いない家族・同居の家族が「来た」、切れた電池が手も計画も無く戻る、予備の無い人が予備に替える、停電が戻った・電源が届いたのに電池を頼む、話せないと伝えられた人が話す、電池が切れたあとも落ち着いたまま、など
   - 赤（動けない・けが）→ 緑は、手の到着か筋の表の行があるときだけ（コードで止める。色と連絡順はルールの表のままで、安否の入力側を止める）
   - 業者の巡回・物が届く出来事（監督・世界）は、その人への手か筋の表の行か計画があるときだけ
3. **同じ出来事の文言を別の人にくり返さない**: 刻みの中・訓練の中で、AI の出来事の種類と言い回しの重なりを数え、監督・世界に「もう出した物」を渡す。言い回しがほぼ同じ物は捨てる
4. **講評の指摘の数を中身に合わせる**: 決まった数を求めない（0 件もあり得る）。指示と形の上限だけ
5. **仮想の結末の理由に医療の言い方を入れない**: 本人役の決まり 6・7 と同じ線を門で止める（理由を捨てて固定の言い方に）
6. **計画で動く**: 停電で予備がある人は計画どおり替える（帳面に替えた時刻と誰が）、避難先が決まっていて手段のある人はそこへ動いてよい。計画が無い人の「良い方への変化」は止める。採点の記録と講評の入力に「計画で動けた人」「計画が無く手が要った人」
7. **評価の台**（tools/eval/drill）: 帳面との矛盾（上の型）を数える検査を足す。帳面の決まりは lib の関数をそのまま使う
8. **テスト**（偽の答え。本物の API は呼ばない）: 帳面の更新、反する答えを落とす型ごと、赤 → 緑の門、業者の巡回の門、重なりの門、講評の数、結末の理由、同じ人で計画あり・なしの差、台の検査

- 医療の助言をしない。計画で動くのは台帳に書いてある事だけ
- 本物の API・本番の D1（--remote）に触らない。鍵を探さない。.dev.vars を読まない。履歴を書き換えない。他の worktree に触らない（評価の記録の置き場は読むだけ）
