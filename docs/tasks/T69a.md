# T69a 本人・家族の入口（署名つきのリンクで本物の利用者と家族が自分のスマホを開く。ログインも新規登録も作らない。新しい人の同意は「未確認」。migration 0018）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md`（何を作っているか・越えない線・地図・進め方）→ `CLAUDE.md` → `docs/tasks/README.md` を読む。元は docs/progress/real-use-audit-20261104.md の「いちばん重い」と 7、順の 2・10。本人のスマホの中身（選択肢の枠と色・場所・録音・まとめ）は T69b で、ここでは触らない。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）

実際に使うときに使える形にする。今は本人・家族の画面（/me・/family）を開けるのは審査員が役を選んだときだけで、本物の利用者と家族が自分のスマホで 2 つのボタンを押す道が無い（lib/auth/principal.ts の judgePrincipal の self・family は種の p-01 と c-01-1 に固定。役の表 migrations/0001 の accounts.role に本人・家族は無い）。

決まっていること（docs/DECISIONS.md「アカウントと事業所」）: **新規登録は作らない。ログインだけ**（自分で登録できると、同意や利用規約の仕組みが無いまま本物の人の情報が入りうる）。本人・家族に ID とパスワードを持たせるのも無理がある（80 代の本人、家族は遠方）。だから入口は **QR の頁と同じ署名つきのリンク**（lib/qr/token.ts の形）を本人用・家族用に作り、ケアマネが本人のページから出して渡す（紙に刷る・LINE で送るのはケアマネの手。アプリは作らない）。リンクを開くとその本人（またはその連絡先）としてのセッションが入り、今の /me・/family・信号の API がそのまま動く。

線: この作業は Claude を呼ばない。色と連絡順（lib/triage）に触れない。リンクは期限なしにしない（QR と同じ決まり）。氏名・カナ・生年月日・電話を URL に載せない。

## 作る物

1. **リンクのトークン（先に 1 commit）**: `lib/qr/phone-link.ts`。lib/qr/token.ts と同じ作り（HMAC-SHA256、SESSION_SECRET）で、署名の頭は `care72-phone-v1:`（QR の `care72-qr-v1:` ともセッションとも取り違えない）。中身は `{ v: 1, p: 本人の id, c: 連絡先の id | null（本人用は null）, g: 版, iat, exp }`。期限は作った時刻から **180 日**（QR の上限と同じ。日数の選択は作らない。期限なし・180 日より長い物は署名が合っても通さない）。版は本人ごとに 1 つ（people.phone_link_generation）で、本人用と家族用の全部のリンクが同じ版を使う（作り直すと全部のリンクが一度に無効になる。1 人ずつ消す形は作らない）。migration 0018: `ALTER TABLE people ADD COLUMN phone_link_generation INTEGER NOT NULL DEFAULT 0 CHECK (phone_link_generation >= 0)`、`ALTER TABLE people ADD COLUMN phone_link_issued_at TEXT`（0007・0015 と同じ ADD COLUMN。QR の版〔qr_generation〕とは別の列にし、QR を作り直してもスマホの入口は消えず、その逆も）。型は lib/db/types.ts に PersonListMark と同じ理由で PersonRow に入れず `PersonPhoneLink = { phone_link_generation: number; phone_link_issued_at: string | null }`。lib/qr/phone-link-store.ts に loadPhoneLinkRow・issuePhoneLink（版を 1 つ上げて時刻を書く。台帳の version・updated_at は変えない）・resolvePhoneLink（署名・期限・版が表と同じ・本人が一覧にいる〔people.unlisted_at IS NULL〕・家族用なら連絡先の行がその本人の物で kind が self・機関でない〔lib/signals/family.ts の familyWriterOf と同じ範囲〕）。
2. **開く口**: `app/s/[token]/route.ts`（GET）。resolvePhoneLink が通れば、本人用は役 self・家族用は役 family のセッションを cookie に付けて `/me` か `/family` へ 303（lib/auth/cookie.ts の seeOther）。通らなければ QR の無効の頁と同じ形の 1 画面（「無効」の 1 語と「ケアマネに連絡」。app/q/[token]/page.tsx の QrInvalid を使い回すか、同じ見た目の小さな頁）。応答に `Cache-Control: no-store`、`Referrer-Policy: no-referrer`、検索に載せない（QR の頁と同じ）。
3. **セッションの第 3 の形**: lib/auth/session.ts の payloadSchema に `{ k: "link", p: 本人の id, c: 連絡先の id | null, g: 版, pv: "link", iat, exp }` を足す（pv は base の形を満たす固定の文字。パスワードの指紋は無い）。exp はトークンの exp と同じ（最長 180 日。セッションの 7 日ではない。理由: 本人・家族はホーム画面に追加して何か月も開く）。**verifySession（lib/auth/session.ts:88）は `exp - iat > SESSION_TTL_SEC`（7 日）を null にする**ので、k が "link" のときだけ上限を 180 日（QR_TTL_MAX_DAYS と同じ定数）にする（account・judge は 7 日のまま。テストで link の 8 日目・179 日目の cookie が通り、181 日は通らず、account の 8 日目は今までどおり通らないことを見る）。lib/auth/cookie.ts の sessionCookie に Max-Age を渡せる形を足す（既定は今の SESSION_TTL_SEC。ログインの route は変えない）。lib/auth/principal.ts の principalOf に `k === "link"` の枝: D1 から本人の行（office_id・name・unlisted_at・phone_link_generation）と連絡先の行を読み、版が違う・本人が一覧から外れた・事業所が無い なら null（次の要求から入れない。QR と同じ「作り直すと前の物は通らない」）。返す Principal は `{ role: "self" | "family", judge: false, admin: false, accountId: null, displayName: 本人の名前 | 連絡先の名前, office, caseloadOf: null, personId, contactId }`。**accountId が null でも今の道が動くことを確かめる**: lib/signals/save.ts の signalScope（authorId: p.accountId → 経過の author_id が NULL。timeline_entries.author_id は NULL 可）、録音（recordingPost）、答え（answers）、家族の経過（familyHistory）、ログアウト（cookie を消すだけ）、AppHeader の右（事業所名 → 役 → ログアウト。役変更は審査員だけなので出ない）。lib/auth/roles.ts の PERMISSIONS・PAGE_ROLES は self・family のままで足りる。
4. **本人のページからリンクを出す**: `app/people/[id]/phone/page.tsx`（app/people/[id]/forms/qr/page.tsx と同じ作り。ケアマネの役だけ。医療班・行政は 404）と `components/phone/PhoneLinkPanel.tsx`。出す物: 本人用（台帳のスマホが「使える」〔basic.contactMeans.smartphone === "uses"〕でなくても出す。押せるかは本人と家族が決める）と、家族・支援者用（連絡先のうち kind が self・機関でない行ごと。has_smartphone が 1 の行を上に）。行ごとに URL（qrUrl と同じく要求の元から `/s/<token>`）・「コピー」・QR の画像（lib/qr/image.ts を使い回す）。上に「発行」（まだ版が 0 のとき）/「再発行」（appConfirm で確かめてから。前のリンクは全部無効）と期限（issued_at + 180 日）。入口は本人のページの書類の行の並び（lib/person.ts の documents に 1 項目「スマホ入口」。lib/person.ts はこの 1 項目だけ触る。T68 が同じファイルの連絡先の行を触るので hunk を分ける）。印刷は作らない（紙に貼るときは QR の画像を保存）。経過に「スマホ入口 発行」「スマホ入口 再発行」を残す（timeline_entries の kind は今ある "note" に body で。kind の CHECK を広げない〔表の建て直しが要る〕）。
5. **平時の扱い（案。DECISIONS に書く）**: 本人・家族の頁の平時は今のまま（本人の 1 枚、災害モードになると 30 秒の読み直しで 2 つのボタンに替わる）。2 つのボタンを平時にも出す形は取らない。理由: 平時の信号はサーバーが 409「平時」で捨て（lib/signals/save.ts:106）、ルールの表も平時は動かない（lib/disaster/state.ts の toSituation が null）ので、押せても届かない。平時に「無事じゃない」を受ける形は、平時の担当一覧の並び（lib/caseload.ts）に信号を効かせる作りが要り、この期間では作らない。代わりに、災害モードへの切替を勧める物は T72（気象庁の警報）が /office に出す。平時の頁の上の方に事業所名の横で「ふだん」と 2 字の状態を出すだけ（PhoneSheet の上。やさしい日本語で「いまは ふだん です」は置かない。印だけ）。
