# T122 評価の 2 回目で残った書類の AI の問題を直す（複数のシートのブック・実在の様式の欄の読み違い・崩れた伏せ字）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。評価の 2 回目（書類の分）の報告 docs/progress/eval-r2-forms-findings.md と数の表 eval-forms-r2.md、T118・T119・T120 の頼み文と進みを読む。生の記録はリポジトリの外（評価の回のフォルダ。読むだけで、中の架空の人の言葉を repo に写さない）。

## 意図（なぜこの作業か）

評価の 2 回目（本物の Claude、T118・T119・T120 の入った木）で、書類の AI に次の問題が残った（番号は findings の番号）。

- 複数のシートのブックで、要るシートが読まれない（#1）。様式 9（厚労省の BCP のひな形）のブックは様式 9 のシートが後ろにあり、ブラウザで描く頁の上限（12）と既定の 3 頁（記入例を外した頭から）のどちらにも入らない。様式 9 の欄は 0/12、紙は全部空く
- 実在の様式の欄の当たりが 76%（#2）。対応表は様式に 1 つなので、1 欄の読み違いが全部の入力の紙で同じ空きになる
- 括弧の崩れた町名の伏せ字が戻らずに台帳に入った（#3）。T118 の戻し・捨ては全角の括弧の形だけを見ている

## 作る物

1. **複数のシートのブック**（#1）:
   - ブックのシートの一覧を黒塗りの画面に出し、ケアマネがシートを選べるように（シートの名前と頁の数、対象・除外）
   - 既定のシートは、シートの名前・印刷範囲・中の字から様式の本体らしい物を選ぶ。表紙・目次・説明・手引き・記入例のシートは後ろに
   - 頁の上限の見直し: シートの一覧と頁の形は上限に縛られずに作り、画像に描くのは選んだ頁と見ている頁だけ。送るのは今までどおり 3 頁まで
   - 評価の台も同じ決まりで既定のシートを選ぶ（正解の表の様式で、人が選ぶシートを台に渡せるように）
2. **実在の様式の欄の読み違い**（#2）:
   - 評価の記録から、読み違いの多い欄の種類（どの様式のどんな欄か）を数えて進みに書く。正解の表・台の数え方の側の食い違いは台を直す（どちらを直したかを進みに）
   - 欄の説明（台帳の項目表）と読み取りの決まりを直す。複数選択の □ の並び、元号の選択肢、医療機器の種類の □、2 つの欄を 1 つに読む所など
   - 紙の側: 複数選択の欄で当てはまる選択肢を全部に印、□ ごとに種類を問う欄は □ の名前と台帳の値を照らす
   - 確かめの画面: 自信の低い欄・台帳の項目なしの欄・よく外れる種類の欄を先に並べて目立たせ、確かめるまで紙に使わない形を選べるように（今ある確かめの流れを活かす）
3. **崩れた伏せ字**（#3）: Claude の返事で伏せ字の印の括弧が落ちる・形が崩れる（半角の括弧・別の括弧・片方だけ・空き）場合も元に戻せるように。戻せない印が残る値は画面に出さず保存もしない（T118 の決まりを全部の形に）
4. **テスト**（偽の client）: 様式の本体が後ろにあるブック（テストの中で作る小さな xlsx）、読み取りの決まりと紙の複数の印、確かめの画面の並び、崩れた伏せ字の形を数種類
5. **評価の台**: 直したあと、偽の client で `npm run eval:forms` を回して前と比べる（本物は回さない）
