# T172 医療班の一括受入・PC のカメラ・伝達を止める

医療班の側の 4 つ。Claude は呼ばない。色と連絡順（lib/triage）に触らない。触らない所: lib/drill（T167）、lib/forms（T168）、components/map・SidePane（T169）。

## 1. 複数人をまとめて受け入れる

- 受入一覧の受入依頼を事業所ごとにまとめ、選んで「一括受入」
- 氏名検索のヒットにも選ぶ欄を付け、まとめて受入
- 避難所は 1 回の入力で全員に
- 1 人ごとに今の受入と同じ処理（受け持ち・経過・第三者提供の記録・同意の範囲の確かめ）。途中で失敗した人は一覧で分かる。成功した人は戻さない
- 上限の人数を決める
- 守る線: 依頼の無い事業所の利用者の一覧を医療班に見せない（検索のヒットはカナ・生年月日・年齢だけ、全件を返さない、審査員の壁はそのまま）

## 2. PC のカメラで QR を読む

- BarcodeDetector が無い端末（Windows の Chrome など）は jsQR で読む（Apache-2.0、動的 import で頁の最初の読み込みを重くしない）
- PC は前面のカメラだけなので facingMode の environment は ideal にして、外れても開く
- カメラが無い・断られた時は理由を短く
- 映像は端末の中だけで読み、送らない・残さない

## 3. 医療班からケアマネジャーへの伝達を今はなしに

- 医療班の役の経過の書き足しの欄を出さず、API でも書けない（lib/consent/scope.ts の writes。行政の役は今のまま）
- 受入依頼の返事の中身に自由文を持たない
- 受入・搬送・退所・受入依頼への受入と受入不可の状態は事実として今のまま
- 1 か所の定数で戻せる形に。医療班が台帳を編集する機能は作らない

## 4. 守り

直した所を tools/eval/guards.ts の守りか台の check に足す（docs/progress/t157.md の足し方）。
