# T28 評価の数字と README の仕上げ

## 目的

数字 3 つ（医療班の様式への転記の欠け、訓練 1 回目 → 2 回目の穴、対応の順番の一致率）を README に件数で書く。README に「使った資料と方法」「守り」「本運用の条件」「診断・用量・医療助言をしない」「色と順位はルールの表で AI は決めない」を揃える。提出の 11/8 20:00 の前日。

## 読む物

docs/SPEC.md の「評価」「審査基準と提出物」（資料と方法の段、GitHub と提出物で守ること）、「正直な見立て」。docs/PROGRESS.md、docs/DECISIONS.md、docs/KNOWN_UNKNOWN.md（T29）。

## 作る物

- `docs/EVALUATION.md`: 数字 3 つの取り方と結果。転記の欠けは 作者が要約から災害診療記録 2018 の欄を埋めて数える（できれば教員 1 人）。訓練の穴は協力事業所の 1 回目と 2 回目の件数。一致率は T22 の数字。母数が小さいことを隠さない。比率より件数
- README:
  - 先頭 5 行: 何か、入口（URL）、役の選び方（ID とパスワードは提出書類）
  - 「作るもの」を「できること」に（実際に動く物だけ）
  - 「使った資料と方法」: 使った物だけ 1 行ずつ（CLAUDE.md、テスト先行、Known/Unknown、Building Effective Agents の形、Cookbook のレシピ、Managed Agents を使った・使わなかった理由、セッション⑥の守り）
  - 「守り」: .dev.vars と secret、仮名化、1 日の上限、Push protection
  - 「本運用の条件」: 委託契約、学習に使わない契約、データ保持なし、事業所内の利用ルール、電気通信事業法の確認
  - 「この道具がしないこと」: 診断・用量・医療助言、順位の AI 判断、自動の電話
  - ライセンス（AGPL-3.0）、THIRD_PARTY.md、出典（docs/SOURCES.md）
- docs/PROGRESS.md を「できた物・できなかった物・未確認」の最終の形に
- 提出書類の下書き `docs/SUBMISSION.md`（概要文、動画の URL の枠、リポジトリ、デモの URL。ID とパスワードは**このファイルにも書かず**、提出フォームにだけ）

## 終わりの形

- README を上から読むと、何か → 入口 → できること → 守り → 数字 → 資料と方法 → ライセンス、の順で揃い、嘘が無い

## 触るファイル

README.md、docs/EVALUATION.md、docs/SUBMISSION.md、docs/PROGRESS.md

## 守ること

動かない物を「できる」と書かない。数字を丸めない。審査員のログインを書かない。
