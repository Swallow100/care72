# T63 経過の撤回（消さずに取り消し線で残す。誰がいつ）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）


- 本人のページの経過（timeline_entries）は書き足すだけ（lib/timeline/write.ts の T24、電話の記録 lib/list/calls.ts）。人を間違えて「安否確認」を押した、避難所の名前を打ち違えた、電話の相手を取り違えた、が直せない。
- 直し方は「編集」でなく**撤回**にする: 行は消さず、取り消し線で残し、誰がいつ撤回したかを行に持つ（履歴を書き換えない。災害の記録は後から読み返す物で、消えた記録は信用を落とす）。直したければ撤回して書き直す。
- 線: 経過の行には**色と連絡順に効く物**がある。信号（本人・家族・支援者が押した事実。kind signal）、順番変更（override。もう「解除」の行を足す作りがある）、時計の確認と本人の報告の印（clock_check・self_report_mark。付け直せる）、同意（consent）は撤回の対象に**しない**。撤回できるのは人が書いた行だけ。撤回で表（lib/triage）が読む入力を減らすのは、T58 の通話で足した出どころ care_manager の信号だけで、それも「表に戻すだけ」（人が確かめた事実を取り下げ、表が残りの事実から出し直す）。AI は関わらない（この作業は Claude を呼ばない）。

## 作る物

1. **撤回の列と、撤回できる行**: migration 0014 で `timeline_entries` に `retracted_at TEXT`・`retracted_by TEXT REFERENCES accounts (id) ON DELETE SET NULL`・`retracted_note TEXT CHECK (retracted_note IS NULL OR length(retracted_note) <= 40)`（0007 と同じ ADD COLUMN。新しい kind は足さない: 0001 の CHECK の建て直しを避ける）。lib/db/types.ts の TimelineEntryRow に 3 列。撤回できる行の集合は lib/timeline/retract.ts に字で固定: kind が WRITABLE_KINDS（safety_check・examined・medication_given・transported・arrived_shelter・note）と called で、**note は payload が NULL の物だけ**（payload の source が intake・office・custody・qr_view・分類の記録〔author_role system〕は撤回できない）。撤回できない kind（signal・override・consent・clock_check・self_report_mark・pickup・received・released）と、すでに撤回した行は 409（"not_retractable"・"already"）。
2. **誰が撤回できるか**: その行の author_id が自分（審査員は acct-judge の行）のとき。加えてケアマネの役は、本人が自分の事業所の人（lib/auth/scope.ts の personInScope の壁の中）で **author_role が care_manager の行**だけ（医療班・行政が書いた 診察・配薬・搬送・到着・記録 は書いた本人しか撤回できない。lib/timeline/write.ts の注「医療班の記録はそのまま」）。医療班・行政は自分の行だけ（受け持ちの間だけ。personInScope が受け持ちを見る）。本人・家族は不可。理由（retracted_note、40 字、任意）は D1 に入れるだけで Claude にも声にも渡さない（write.ts の自由文と同じ）。`retractTimeline(db, p, { id, note }, at)` と `POST /api/timeline/retract`（lib/timeline/write.ts の writeTimelineRequest と同じ断り方。route は同じ所からの POST だけ）。UPDATE は `WHERE id = ? AND retracted_at IS NULL`（同時の撤回で 1 回だけ）。
3. **読む側**（撤回した行を「見せる所」と「除く所」に分ける。`grep -rn "timeline_entries" lib app` で全部洗い、progress に表で残す）: lib/person.ts:1332 の本人のページは撤回した行も**見せる**（TimelineItem に `retracted?: { who: string; when: string; note: string | null }`。並びは元の時刻のまま）。lib/caseload.ts:449 の called（行の詳細の電話の記録と最後の電話）は**除く**（`AND t.retracted_at IS NULL`）。lib/forms/form9-db.ts:170 の ENTRY_KINDS（様式 9 の避難先の列に出す transported・arrived_shelter）は**除く**。lib/disaster/override.ts:92 は override なので対象外。lib/classify/store.ts:144 は分類の記録の有無を見るだけで対象外。
4. **通話で聞いた安否の撤回**（同じ branch の後半。別の commit）: called の行に signal_id があれば（T58 の「通話」で足した出どころ care_manager の信号）、撤回で**その信号も表から外す**: migration 0014 で `signals` にも `retracted_at TEXT`。外せるのは `source = 'care_manager' AND drill_id IS NULL` で called の行と結ばれた信号だけ（本人・家族・支援者・訓練の信号は外さない。SignalRow に列を足す）。表を読む SQL は 5 か所で、**全部に同じ濾し `AND retracted_at IS NULL` を 1 つの commit で**: lib/disaster/triage.ts:83・:95（loadOfficeSignals・loadPersonSignals）、lib/caseload.ts:443（行の詳細の信号）、lib/custody/board.ts:131（受け持ち）、lib/forms/form9-db.ts:164（様式 9）。通話の信号には kind signal の経過の行が無く（T58 は called の行に signal_id を結ぶだけ）、本人のページに出るのは called の行なので、取り消し線はその行に付く。縛るテスト: lib/list/call-heard.test.ts の形で「通話で無事 → 緑 → 撤回 → 通話の前の色・順・理由に戻る」を担当一覧・本人のページ・様式 9・受け持ちの 4 か所で同じ色、「至急維持」で断られた通話は信号が無いので経過だけ。**5 か所のどれかに濾しを入れられない形なら、聞いた安否の撤回は出さず（called の行の撤回だけ）progress に理由を書く**。lib/triage の行・言葉は変えない。
5. **画面**: components/person/Timeline.tsx は Server Component なので、行の右に小さな client の部品 `components/person/RetractButton.tsx`（TimelineComposer と同じ fetch → router.refresh）。押すと行の下に 理由（40 字、任意）と「撤回」（赤の文字）・「戻る」が開く（appConfirm でなく行の中。lib/ui/dialog.ts は理由を受けないため）。撤回した行は種類と本文に `line-through`（components/person/IntakeChanges.tsx:144 と同じ decoration）と薄い字、2 行目に「撤回 山本 11/3 22:10 理由」。撤回できる行にだけボタンを出す（TimelineItem に `retractable?: true`。誰が押せるかはサーバーが決め、画面は view.writes と同じく lib/person.ts の toPersonView で付ける）。災害モードの上の経過（本人のページの一番上）も同じ部品。
6. **テスト**（lib/timeline/t63.test.ts、node:sqlite）: 撤回の往復（列・誰が・いつ・理由）、撤回できない kind と payload つき note と二度目の拒否、権限（自分の行・事業所のケアマネ・ケアマネが医療班の行を撤回 → 403・医療班の受け持ちの外・本人・家族・ログインなし）、読む側（本人のページに取り消し線つきで残る、caseload の電話の記録と様式 9 の避難先から消える）、4 の色の戻り（4 か所）、migration 0014 の契約、理由が Claude の入力に無い（askJson を呼ぶ所の入力に timeline_entries の本文・理由が渡らないことを grep で確かめて progress に）。375 で撤回の欄が押せる（headless Chrome で測る）。
7. **docs**: docs/progress/t63.md（Claude を使う所・使わない所を 1 行。読む側の表）。仕様と違う決めは docs/DECISIONS.md に案として（撤回できる行の集合、聞いた安否の撤回を出したか）。
