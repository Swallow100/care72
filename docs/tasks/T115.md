# T115 審査員がまっさらの事業所から始められる役

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T61・T81・T95（審査員の壁と役変更）と docs/DECISIONS.md の「アカウントと事業所」を読む。

## 意図（なぜこの作業か）

審査員は今、種の入ったデモ事業所（10 人と山本）に入り、役（ケアマネ・本人・家族・医療班・行政）を選んで見る。利用者が紐づいた所から始まるので、本物の事業所が最初にする流れを審査員が自分で試す道が無い。その流れは、地域の中心を置き、ケアマネを足し、利用者を登録して台帳を埋め、経路と紙を作り、訓練をすること。

手元では tools/office/new-office.ts で作った事業所（D1 だけ）で、この流れを最後まで通せた（docs/progress/screens-20261105.md）。審査員の入口から同じ流れを試せるようにする。デモ事業所（種の入った形）はそのまま残す。

## 先に決めること（問い）

1. まっさらの事業所の持ち方:
   - (a) 審査員の役の一覧に「新規事業所」を足す。押すとその審査員のセッションだけの空の事業所を作り、審査員がその管理者になる。毎朝 4 時の戻しで消す（推し。審査員が同時に何人いても混ざらない）
   - (b) 空の事業所を 1 つ固定で置き、毎朝戻す（同時に入った審査員どうしで混ざる）
   - (c) 審査員だけ、デモ事業所を空にする道（ほかの審査員の見本が消える）
2. 作れる数の上限（1 日に N 件、1 セッション 1 件など）と、AI の 1 日の上限をデモ事業所と同じに数えるか
3. 事業所の名前と市の初めの値（松山市の様式が出るよう市は松山市、名前は「試し事業所」など）と、地域の中心を最初から置くか（準備の欄 T98 を試せるよう置かないのが推し）

## 作る物

1. 問いの答えの形で、審査員の役の切替から入る道と、空の事業所を作るサーバーの口
2. 審査員の壁（lib/auth/wall.ts）: まっさらの事業所は作った審査員だけが見え、そこから本物の事業所・デモ事業所の人に届かない。そこで作ったケアマネ・利用者も同じ壁の中
3. 毎朝の掃除: 審査員のまっさらの事業所を、人・台帳・訓練・アンケート・取り込んだ原本（R2）・録音（R2）ごと消す（lib/seed/reset.ts の隣。種の事業所を消す守り tools/deploy/guard.ts と食い違わない）
4. README の審査員の触り方に 1 行
5. テスト: 作る・壁・上限・掃除（消える物の一覧が漏れない）。本物の事業所の行に触らないこと

## 触るファイル

lib/auth（wall.ts・役の切替）、app/api/auth/role、lib/seed/reset.ts（掃除）、事業所を作る処理（tools/office/new-office.ts の SQL と同じ形を lib に寄せる）、役の切替の部品、README、docs/progress/t115.md。migration が要るなら番号は作業者が migrations/ と全部の branch を見て決める。

## 守ること

審査員の ID とパスワードは README・動画に書かない。審査員と種のアカウントは固定（T61）。デモ事業所の見本（10 人・山本）は変えない。本物の事業所のデータに触れない。
