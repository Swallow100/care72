# T125 訓練の想定に合わない物を、どの道でも出さない（想定の表・1 つの門・通信の段・連絡の経路・区域の出来事）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。訓練の作り（docs/tasks/T90・T104・T110・T121・T123 とその進み）を読んでから始める。

## 意図（なぜこの作業か）

地震想定の訓練で、地震に合わない物が画面に出ていた。

1. 手の一覧で「訪問 60 分 浸水」。手の可否と所要の決まり（T110 の lib/drill/action-terms.ts）が、津波警報の間は全員の家を浸水として扱い、訪問の所要を伸ばしていた（家が津波の区域かを見ない）
2. 地震想定の担当一覧の「ハザード」の列に、河川の浸水の深さ（「浸水 3 m」）が出る
3. 訓練の画面の上の帯に、事業所の今の状態（「大雨 レベル 4 停電（地区）11 時間」）が出たままで、訓練の想定と食い違って見える
4. 地震想定で、電話が「通話不可」の間に家族・本人から着信が来る

地図の既定の層（地震で 浸水 off・土砂 on・津波 on）は合っていた。

この 4 か所だけでなく、別の想定・別の訓練でも同じ種類の食い違いが起きないようにする。想定ごとに「効く物・起きる物」を 1 か所の表に持ち、手・一覧・帯・地図・監督・世界・本人役・時間ごとの起きやすさ・評価の台が全部その表を見る。AI が出す物は、表と世界の今の状態（T121 の状態の表）の両方に照らす 1 つの門を通してから画面と記録に出す。

## 作る物

1. **想定ごとの表を 1 か所に**（lib/drill の新しいファイル）
   - 想定（訓練の災害の種類）ごとに、効くハザード（河川の浸水・津波の浸水・土砂・揺れ・倒壊など）、起こりうる状況（停電・断水・通行止め・電話・電波・道路の被害など）、出来事の種類（event-catalog の kind・世界の部屋の kind・世界の変化の kind）、地図の既定の層、起きてはいけない言葉を持つ
   - ハザードが効く条件も表に持つ（例: 津波は「津波警報が出ていて、家が津波の浸水想定の区域」のときだけ浸水を効かせる）
   - 表は全部の想定を必ず持つ（型と試験で網羅を確かめる。新しい想定を足して行が無いと落ちる）。仮想は開始で決めた規模の災害、無ければ世界の出来事、それも無ければ未決（両方を許す）
2. **全部の道がその表を見る**
   - 手の可否と所要（action-terms）。浸水・津波・土砂の警戒は区域にいる人（台帳のハザード）と、区域の事業所にだけ効かせる
   - 担当一覧のハザードの列（訓練の画面では想定に効くハザードだけ。平時・事業所の画面は今のまま）
   - 訓練の画面の上の帯（訓練の画面では訓練の想定・規模・経過を出し、事業所の今の状態と混ぜない）
   - 地図の既定の層（今の決まりを表から）
   - 監督・世界の部屋・1 回呼びの出来事（表に無い種類は作らせない・捨てる。指示の文に想定に効くハザードを渡す）、本人役に渡す状況、時間ごとの起きやすさ（time-odds）
3. **1 つの門**: AI が出す物（監督・世界の部屋・1 回呼びの出来事、本人役の言葉、自由対応の読み替えの理由と 1 文）は、どの訓練でも想定の表と世界の今の状態に照らしてから画面と記録に出す。合わない物は捨てるか直し、捨てたことを区切りの記録に残す（評価の台が数える）
4. **通信の段**: 通話（音声）は規制でも全部は止めない（つながりにくい。出る割合と所要で効かせる）。家の固定電話は停電で使えない。メッセージ（LINE・SMS・メールの形）と安否のボタンはデータの道で、電波不通になるまで届く。電波不通は携帯の基地局の予備電源が尽きる頃から（目安 24 時間、想定ごとの表で区域ごとに）。世界の状態・手の可否（固定電話と携帯を分ける。本人の携帯・スマホの有無〔台帳〕も効く）・帯・被害状況・着信・本人役が同じ 1 つの通信の状態を読む。手の表にメッセージの手を足す。事業所の職員への訪問依頼は電話が要らない。地震・大雨の想定の表の電話の行はこの段で書き直す（デモの 10 人の固定の行は変えない）。要る段だけ足す
5. **連絡の経路**: 本人役・表の行の安否 1 件ごとに、どの経路で届いたか（着信・ボタン・伝言・来所・近所など）を、通信の段と本人・家族のスマホの有無から決めて付ける。通話不可・電波不通の間は着信にしない。着信の画面・選び方の上限・経過の見え方は別の作業（T127）で、ここは経路の決まりと、着信の形かの判定（lib/drill/calls.ts の isPhoneTurn）が経路を見る所だけ
6. **区域の出来事の対象**: 津波・避難指示・土砂の警戒などの区域の出来事が、どの人（台帳のハザード）と、事業所（事業所のハザード）に効くかを返す 1 つの関数。事業所のハザード（津波・浸水・土砂）を持つ形を足し、事業所が津波の区域なら警報の間の職員の退避（空き職員・訪問の可否）に効かせる。対象を画面に出すのは別の作業（T128）
7. **評価の台**（tools/eval/drill）: 出来事・手の所要の理由・本人役の言葉・画面の帯・着信の経路に、想定に合わない物が出たら数える。「起きてはいけない物」の一覧は表から作り、全部の想定で効く
8. **テスト**（偽の client）: 地震で訪問に浸水が付かない・津波警報と区域があれば付く、担当一覧のハザードの列が想定ごと、上の帯が訓練の想定、監督・世界の答えの表に無い種類を捨てて記録に残る、通話不可の間は着信にしない、区域の出来事の対象、台の検査。直す前と直したあとに偽の client で `npm run eval:drill -- --runs 6` を回し、想定に合わない物が 0 になることを確かめる（本物は回さない）。画面は 375・1280、ライトとダーク

- 本人役の決まり（名前・住所・電話・病名・薬の量・医療の助言・「死亡」を言わない）は変えない。本人役の掃除（T118）を全部の道で通す

- 多様さは筋書きの表に行を足さず、自由さで。想定に合わない物だけを外す
- 本物の API・本番の D1（--remote）に触らない。鍵を探さない。.dev.vars を読まない。履歴を書き換えない。他の worktree に触らない

- 文書に作者の発言の引用・作業のやり取り・人の名前を書かない（公開のリポジトリ）。作業者の一時ファイルは scratchpad の `t125/` の下
