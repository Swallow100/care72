# T131 評価の 3 回目で残った書類の AI の問題を直す（一覧の形の様式・実在の様式の読み違いと紙のずれ・1 頁の出力の上限・正解の表の古い所）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。評価の 3 回目の報告 docs/progress/eval-r3-findings.md（3・4・5・9 がこの作業。origin/eval/r3 にある）と数の表 eval-forms-r3.md、T107・T111・T120・T122 の頼み文と進みを読む。生の記録はリポジトリの外（評価の回のフォルダ。読むだけで、中の架空の人の言葉を repo に写さない）。

## 意図（なぜこの作業か）

評価の 3 回目（本物の Claude、T122・T123 の入った木）で、書類の AI に次の問題が残った（番号は findings の番号）。

- 様式 9（利用者の一覧の表）で、AI が見出しでなく 1 行目のセルを欄として読み、紙の半分が空く（#3。欄 8/12、紙 161/308）。担当ケアマネの欄も項目なし
- 実在の様式の読み違いと紙のずれ（#4）: 松山市の計画書の「医薬品情報」を欄として読まない、避難の手段の字を別の避難場所の手段の欄に置く、民生・児童委員と事業所等の欄に収まらない。災害診療記録の避難先 1・2 を項目なしにする、薬の区分の □ に正解では空の所へ印を付ける
- 1 頁の出力が上限 20,000 token に達して切れ、切れた呼び出しが失敗として 1 日の上限に数わる（#5）
- 正解の表の古い所（#9）: T120 の決まり（機器の中身に種類の名前を重ねない）どおりの答えを外れと数えるなど

## 作る物

1. **一覧の形の様式**（#3）:
   - 見出しの行と人ごとの行が並ぶ様式を見分け、見出しを欄にし、行ごとに人を入れられる形にする（読み取りの決まりと答えの形、対応表、紙）
   - アプリには様式 9 の専用の紙（lib/forms/frame-form9.ts）がある。AI の読み取りの道とどちらを使うかを決め、決めを docs/DECISIONS.md に案として書く
   - 担当ケアマネの欄に当てる項目
2. **実在の様式の読み違いと紙のずれ**（#4）:
   - 2 つの欄の名前が 1 つの書く所に付く欄、避難場所ごとの手段・時間、名前と電話が別の列の欄、種類の □ と名前を書く所の欄の読み方と紙の置き方
   - 薬の区分の □ の印は、T122 の直しと正解の表のどちらが合っているかを台帳と様式の原本（専用の紙）で確かめ、間違っている方を直す
3. **1 頁の出力の上限**（#5）: 上限・頁の分け方・切れた時の扱いを見直す（費用を増やしすぎない）
4. **正解の表の古い所**（#9）: tools/eval/forms の正解の表と数え方の古い所を直す（どちらを直したかを進みに）
5. **テスト**（偽の client）と **評価の台**: 直したあと、偽の client で `npm run eval:forms` を回して前と比べる（本物は回さない。本物の回は別の評価の作業者がする）

直しは特定の自治体の様式に合わせた決め打ちにせず、ほかの自治体の様式（評価の置き場の 15 自治体）でも効く形にする。
