# T57 台帳の幅（連絡先の順番・種類・距離、機器・ハザード・世帯の「その他」、時計の手入力）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md`（何を作っているか・越えない線・地図・進め方）→ `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）


- 連絡先の「緊急連絡先 1・2」「支援者 1・2」の順（contacts.emergency_order・supporter_order）が、本人のページの編集（components/person/SectionEdit.tsx の ContactRow）にも保存（lib/intake/save.ts の planContacts。INSERT の列にも overwrite の UPDATE にも無い）にも無い。ルールの表は supporter_order のある連絡先を「支援者」と数え（lib/triage/from-ledger.ts の hasSupporter）、同じ色の中で「支援者なし」を先に並べる（lib/triage/index.ts の ORDER、案 5）。だから画面で足した支援者は、種の 10 人以外ずっと「支援者なし」。これは自由度でなく不具合で、最優先。
- 連絡先の種類は 10 種（lib/db/types.ts の CONTACT_KINDS）で、酸素業者・電力会社・病院・その他が無い。距離（同居・近所・市内・県外・遠方。CONTACT_REACHES、contacts.reach）は型と列にあるが画面に無い。
- 機器 5 種（DEVICE_KINDS）・ハザード 3 種（HAZARD_KINDS）・世帯 4 種（HOUSEHOLDS）に「その他」と自由記入が無い。
- 時計は機器と薬からしか作られず（lib/intake/marks.ts）、手で足す・消す・起点（停電か発災か）を選べない（SectionEdit.tsx の時計の欄は値と単位だけ）。

線: 色と連絡の順はルールの表（lib/triage）だけで決める。この作業は表の入力（支援者の有無・時計）を人が正しく入れられるようにするだけで、表の行・並びは変えない。

## 作る物

1. **連絡先の順番（最優先。先に 1 commit で出す）**: 本人のページの編集の連絡先の行（ContactRow）に「緊急」「支援」の選択（— / 1 / 2 / 3）。編集の差分（lib/intake/edit.ts の ContactValue）と保存（lib/intake/save.ts の planContacts。overwrite の UPDATE と INSERT の両方）に emergency_order・supporter_order を足す。同じ順を 2 人に付けた保存はサーバーで断り、画面にも 1 行で知らせる。AI の入れる欄（lib/intake/ask.ts・answer.ts）からは今までどおり順を付けない（人が決める所。docs/PROGRESS.md の T03 の決め）。テスト: 画面で足した支援者に「支援 1」を付けて保存すると、表の入力（lib/triage/from-ledger.ts の toTriagePerson）で hasSupporter が true になり、理由の「支援者なし」が消える。
2. **連絡先の種類と距離**: CONTACT_KINDS に oxygen_supplier（酸素業者）・power_company（電力会社）・hospital（病院）・other（その他）。lib/labels.ts の CONTACT_KIND_LABELS、lib/pseudonym/index.ts の KIND_ROLE（Claude に渡る役割名。名前でない語にする）、lib/signals/family.ts の書き手の判定（新しい種類は本人・家族・支援者でないので書き手にしない）。lib/intake/schema.ts の CONTACT_KINDS_FOR_INTAKE は自動で広がる。その他は間柄（relation）が空なら編集の画面で止める（保存ボタンの前。保存の batch は guard 付きで丸ごと通るか落ちるかなので、サーバーで断ると AI の提案の行が混ざった保存が全部落ちる。種類だけでは誰か分からない）。距離（reach）は ContactRow に選択（— / 同居 / 近所 / 市内 / 県外 / 遠方。lib/labels.ts の CONTACT_REACH_LABELS）を足し、保存と本人のページの連絡先の行（lib/person.ts の contactLine）に出す。担当一覧の行の詳細（lib/list/detail.ts・components/list/CallButtons.tsx）は T58 が同時に触るので、ここでは触らない（T58 が距離を出す）。migration 0008: contacts.kind の CHECK（migrations/0001_init.sql の contacts）を広げる。contacts を指す表は無い（`REFERENCES contacts` は無し）ので建て直してよい（新しい表 → INSERT SELECT → DROP → RENAME。索引があれば作り直す）。0006 が建て直しを避けた理由（drills の子の CASCADE）は contacts には当たらない。
3. **機器・ハザード・世帯の「その他」**: DEVICE_KINDS・HAZARD_KINDS に other、HOUSEHOLDS に facility（施設）と other。機器のその他は今ある detail（中身）に名前を書く（空なら編集の画面で止める。2 と同じ理由）。ハザードは Ledger の hazards の要素に note?: string（60 字まで）、世帯は basic.householdNote?: string（60 字まで）。people.ledger は JSON なので SQL は変えない。typecheck が止める表を先に直す: lib/labels.ts の各 LABELS、lib/intake/marks.ts の DEVICE_CLOCKS（その他の機器は時計を作らない。Partial にして other を持たない）、lib/forms/own-sheet.ts の DEVICE_CARRY、lib/map/side.ts の HAZARD_ORDER（other は最後）、lib/intake/schema.ts・save.ts の zod、lib/db/ledger.ts。ルールの表の livesAlone（household === "alone"）は変えない（施設・その他は独居でない）。様式（lib/forms）は「その他」を機器・ハザードの行に名前つきで出す。
4. **時計の手入力**（同じ branch の後半。SectionEdit.tsx の時計の欄は 1 と同じファイルなので別の人に出さない）: 時計の欄に「追加」（名前・区分 device/supply/medication・何で決まるか CLOCK_CATEGORIES・値と単位〔空は未確認〕・起点 停電/発災・出典 CLOCK_SOURCES と出典の書き足し）、今ある時計に起点の選択（停電/発災）と「外す」。本人の状態の時計（kind condition）は足せない・起点は none のまま（clocks の CHECK）。機器・薬の印の時計（lib/intake/marks.ts が作る物）は、機器・薬を外せば一緒に消える道（save.ts の DELETE FROM clocks）がある。時計だけの「外す」を印の時計にも出すかは、planMarkClocks が次の保存で作り直さないかを確かめて決め、progress に書く。IntakeChange（lib/intake/changes.ts）に clockAdd・clockStart、remove に clock を足し、経過の fields に残す。
5. **種**: 種の本体は seed/people.ts（lib/seed はそれを D1 に入れる側）。emergency_order・supporter_order・reach は既に入っている。無い人がいれば足す。加えて 1〜2 人に新しい種類の連絡先（たとえば小林 p-02 の酸素業者、田中 p-03 の病院）と「その他」の機器かハザードを 1 件足し、配信後の見本（毎朝の戻し）で種類の広がりが見えるようにする。足す連絡先に supporter_order は付けない（ルールの表の結果を変えない）。lib/triage/heavy-rain.test.ts の 10 人の色・並びと様式の照合テストが変わらないことを確かめる（様式に行が増えて落ちるテストは、増えた行だけ直す）。
6. **テスト**: 1〜5 の保存の往復（node:sqlite で保存 → 読み戻し）、同じ順の二重の拒否、新しい種類の KIND_ROLE に名前が混ざらない（findLeaks）、「その他」の自由記入が Claude に渡るときは今の自由文と同じ道（lib/pseudonym の ClaudePerson・pseudonymize）を通ること、時計の追加・外す・起点の往復、migration 0008 を当てたあとの契約（CHECK と列）。

## 守ること

- 色と連絡順はルールの表（lib/triage）だけで決める。lib/triage は読むだけで変えない。AI（Claude）の出力は色と順番に一切触れない（AI の入れる欄から順番を付けない）
- 自由記入（その他の中身・ハザードの注・世帯の注・時計の名前と出典の書き足し）が Claude（入れる欄の問い返し・要約）に流れる道は、今の自由文と同じ仮名化の門（lib/pseudonym → askJson、ForClaude）だけ。新しい道を作らない
- 119 の文言（「命が危ないと感じたら、すぐ119番へ」）は触らない。端末は増やさない（iPhone・Android・LINE のまま）。本物の API は呼ばない（偽の client）。鍵を探さない。履歴を書き換えない。他のプロジェクトの名前を書かない
- 画面の言葉: ボタン・見出し・状態は 2〜4 字の漢語（「緊急」「支援」「距離」「追加」「外す」「起点」「停電」「発災」「出典」）。「を・が・の」でつなぐ文にしない。常設の説明文を置かない。見出しに読点・句点を付けない。使わない語: 診断・判定・重症・緊急度・札
- 見た目の避ける型: ピル型ボタン、01/02 の番号ラベル、等幅のラベル、グラデーション・光る影、字間、文字の中の絵文字、`<details>` の既定の黒い▼、ライトで真っ黒の塗りボタン、選んだ印にテーマ色の薄い下地（枠・文字色・下線・灰色の濃淡で示す）。区切りは枠線より地の色の差。新しい押せる物・選ぶ物には focus-visible:outline-solid（lib/ui/focus-ring.test.ts で落ちる）。375px 幅で押せる・選べること（T55 で落ちた型。headless Chrome で 375・768・1280 を測る）
