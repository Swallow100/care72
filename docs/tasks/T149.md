## 意図（なぜこの作業か）

本人・家族のスマホの入口（T69a）は、ケアマネが本人のページの「書類」の行から出すリンクだけで、次の 4 つが足りない。

- 置き場所: スマホ入口は書類（紙）ではなく、本人と家族がスマホで使う入口。書類の行にあると探しにくく、何の入口かも伝わりにくい
- ログイン: リンクで開いた端末の cookie だけが入口になる。別の端末や、ホーム画面に追加したアプリ（iPhone は Safari と cookie を分ける）、リンクの期限が切れたあとは入れない
- ホーム画面と通知: 案内は平時の画面の上の「ホーム画面に追加」だけで、通知の許可を求めていない。閉じると同じタブでは出ない
- 災害時の知らせ: 事業所が災害モードに入っても、本人・家族のスマホには何も届かない。開いていない人は 2 つのボタンに気付かない

本人・家族がリンクから入ったその場で ID とパスワードを作れ、ホーム画面への追加と通知の許可を済ませるまで案内が出続け、災害モードに入った時とケアマネが安否確認を送った時に「大丈夫ですか」の通知が届き、押すと安否のボタンの頁が開く形にする。

## 作る物

1. **置き場所**: 本人のページで、スマホ入口を書類の行から外し、同意の面の近くに「スマホ」の面を置く（入口の状態・期限、本人用と家族用ごとの ID と通知の有無、詳しい画面への入口）。置き場所の案と理由を DECISIONS に。同意の無い人には作れない形にする（画面は押せず、理由は「同意なし」。サーバーの決まりは T147）。どの同意を前提にするかは 1 か所の関数に置き、案と問いにする
2. **本人・家族の ID とパスワード**: スマホ入口のリンクで開いた本人・家族が、その場で自分の ID とパスワードを作れる。次からは別の端末や、リンクの期限が切れたあとでもログインの画面から入れる。パスワードの決まりはケアマネと同じ（10 字以上・大文字・小文字・記号。T148 が 1 か所に作る。無ければ同じ決まりを 1 つの関数に置き、取り込みでそろえる）。ID の決まりはケアマネの ID と同じ形で、ケアマネの ID とも重ならない。作ったアカウントで見られるのは、その本人（家族用はその連絡先として、その本人）だけで、今の本人スマホ・家族スマホの役の壁のまま。審査員の本人スマホ・家族スマホの役（p-01・c-01-1）は今どおり
3. **ホーム画面に追加と通知の許可**: 本人・家族の頁（/me・/family）の上に、ホーム画面に追加（iPhone は共有の手順の絵、Android は追加のボタン、LINE の中は外のブラウザへ）と通知の許可を順に案内し、済むまで出し続ける。閉じてもその表示の間だけで、次に開いた時にまた出す。済んだら出さない。押さないと先に進めない形にはしない（災害モードの安否のボタンはいつも押せる）
4. **「大丈夫ですか」の通知**: Web Push（Service Worker の push と notificationclick、購読は D1 に。migration は今の最大の次の 0035。ほかの作業と重なったら取り込みで付け直す）。送るのは、事業所が災害モードに入った時（今の災害モードの切替）と、ケアマネが担当一覧の行から「安否確認」を送った時。通知を押すと本人・家族の頁の安否のボタンへ。Workers で動く Web Push（VAPID の署名と中身の暗号化を WebCrypto で。依存を足すなら MIT・Apache だけで THIRD_PARTY_NOTICES.md に）。鍵は env の VAPID_PUBLIC_KEY・VAPID_PRIVATE_KEY・VAPID_SUBJECT から読む（作業者は鍵を作らない・書かない）。無ければ送らず、画面は「通知 未設定」。デモ事業所でも審査員が自分の端末で試せる（本人スマホの役で購読し、ケアマネの役で「安否確認」を送ると届く）。通知の文に名前・病名など人の中身を入れない（「ケア72」「大丈夫ですか」程度）
5. **確かめ**: テスト（購読の保存・送る時・押した先・鍵が無い時・同意の無い人には作れない・ID とパスワードの決まり・壁）、狭い幅（iPhone の幅）とライト・ダークの絵を docs/progress/t149/ に。本物の通知は鍵が無いので送らない（偽の送り先でテスト）
