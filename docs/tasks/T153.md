# T153 デモ事業所と確認用の事業所の最初の画面を平時に、発災時は「発災開始」で入る

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。README.md の「触り方」、docs/SPEC.md の「審査員用の公開デモ」と「画面 1 担当一覧」（平時の右の面）を読む。コードは seed（people.ts・sql.ts・full.ts・build-sql.ts）、lib/seed（reset.ts・check.ts・demo.ts・drill.ts・http.ts・cron.ts）、lib/disaster（state.ts・db.ts・http.ts）、事業所の画面（app/office/page.tsx と app/office/mode/route.ts）、T149 の通知（lib/push/http.ts の officeSafety）。

## 意図（なぜこの作業か）

今のデモ事業所と確認用の事業所の種は、大雨の最中（警戒レベル 4・浸水 3 m の町で停電・山田の赤と録音）で始まる。毎朝 4 時の戻しと「最初に戻す」も同じ形に戻す。審査員が最初に開く担当一覧は発災時の並びで、平時の担当一覧（今週の見直し・未確認の多い人・計画の状態）が見えない。

道具の使い方の順は 平時 → 訓練 → 発災時 で、最初の画面は平時であるべき。平時から始め、審査員が自分で発災に切り替えると同じ表が色と連絡順に並び替わる形にすると、その変わり目そのものを見せられる。

## 作る物

1. 種を平時で始める
   - デモ事業所と確認用の事業所の種（手元の `npm run db:reset`、毎朝 4 時の戻し、「最初に戻す」）を、災害の状態でない平時で始める。災害の状態の行・事業所の経過の切替の 2 行・山田の赤と経過の 3 行を種から外す
   - 担当一覧は平時の形（右の面は計画の内訳・今週の見直し・未確認の多い人）
   - QR・同意・台帳・終わった訓練は今どおり種に残す
2. 発災時を見る道
   - 事業所の画面の災害モードの区分に、種の事業所だけ「発災開始」。押すと今の種の大雨の想定（警戒レベル 4・浸水 3 m の町で停電）に入る
   - 入った時に、種の安否（山田の赤・録音・分類の経過）も入る。平時の間は出さない
   - 時刻は今の種と同じ数え方で、押した時刻から数える（発災 4 時間前・停電 3 時間前・山田の赤 1 時間前）。時計の経過で決まる色と連絡順が、今の種の担当一覧と同じになるように
   - 書き手は押した人（審査員なら審査員 1〜3）
   - 平時に戻すは今の「平時」のボタン。もう一度「発災開始」を押すと、前に入った種の安否を消してから入れ直す（二重に残さない）
   - 切り替えは審査員 3 人で共有（同じデモ事業所）。版が合わなければ「競合」
   - 平時から入ったら、T149 の通知（「大丈夫ですか」）を本人・家族のスマホへ送る。審査員の本人スマホの役に届く形のまま
   - 種の事業所の外（協力事業所・試用事業所）には出さない。サーバーも断る
3. 訓練は今どおり。種の終わった訓練と新しく始める訓練は、平時・災害の状態と関係なく動く
4. README の触り方を、平時から始めて「発災開始」で発災時を見る順に直す（頭の「最初に見るなら」の行も）。ID とパスワードは書かない
5. テスト
   - 種と戻し（デモ・確認用）が平時。担当一覧が平時の形
   - 「発災開始」で災害の状態・事業所の経過・山田の赤が入り、担当一覧が発災時の並び（山田が至急の 1 番）。色と連絡順はルールの表のまま
   - 平時に戻す。もう一度入れても種の安否が二重にならない
   - 審査員 1 が入れた状態が審査員 2・3 に見える。確認用の事業所は確認用の id で入り、デモ事業所に効かない
   - 平時から入ったときだけ通知を送る
   - 種の終わった訓練の中身と、新しい訓練の開始は今どおり
