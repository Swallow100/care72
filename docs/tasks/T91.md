# T91 ケアマネの手の表 v2（手を 7 つから 18 に、手の効き目を閉じた形で、自由に書く手）（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T90〜T94 は 1 組（訓練の自由度）。T90 の準備の PR（engine.ts の型の分割、director.ts の「世界の返事」を lib/drill/world-reply.ts へ、WorldState の `checks`・`arrivals`・`supplies`・`asks`・`scheduled`・`advised`）が integrate/t11-t12 に入るまでは、新しいファイル（action-catalog.ts・free-action.ts）だけを書く。

## 意図（なぜこの作業か）

ケアマネの手は 7 つ（本人電話・連絡先電話・訪問・訪問依頼・受入依頼・行政報告・退避。lib/drill/action-table.ts）で、所要時間が固定、相手は台帳の連絡先の一部。本物の Claude で回した画面では、透析先が休止した人・栄養剤を置いてきた人・酸素の電池が切れかけている人に、打てる手が「電話か訪問」しか無く、現場でケアマネがする調整（透析の振替、薬局への手配、酸素業者・電力会社への連絡、民生委員や近所への見守りの依頼、福祉避難所や病院への受け入れの調整、移送、蓄電池の貸出、ほかの事業所への応援、家族への頼み、119 を勧める、記録だけ）が出せない。手の種類を増やし、手ごとに時間と職員の空きがかかる形にする。

加えて、表に無い対応をケアマネが文で書ける「自由に書く手」を作る。文は監督役の Claude が **表のどの手に当たるか**に読み替え、世界の変化と結果（届いた・届かない）は表と確率でコードが決める（Claude が世界を自由に変える道は作らない）。

線: 手の効き目が左の表（色と連絡順）に届く道は今までの 2 つだけ（時計の頼り先の確認の写し `checks`、通話・訪問で聞いた安否 `heard`）。119 は勧めるまで（自動の 119 はしない）。

## 作る物

### 1. 手の表（新しい lib/drill/action-catalog.ts。型と定数だけ、Claude を呼ばない。ブラウザの束に入る）

1 行 1 手。欄: `id`（DrillAction）・`label`（画面、2〜4 字）・`group`（連絡・訪問・手配・報告・記録）・`minutes`・`staff`（職員の空きを減らす数。0 か 1）・`needsPerson`・`targetKinds`（台帳の連絡先の区分。空なら相手なし。固定の相手〔事業所の職員・市役所・福祉避難所〕は今の calleeText の形）・`decide`（世界の事実と確率で結果を決める規則の種類。world-reply.ts が読む）・`effects`（閉じた一覧から。下）・`towardPerson`（採点で「その人への手」に数える）・`reach`（「届いた」に数える結果の status と、到着までの分）・`words`（Claude に渡す言い方。本人役・監督・世界・講評が同じ物を読む）。

### 2. 結果の決め方（lib/drill/world-reply.ts。T90 の準備で director.ts から移した物を一般化）

- `decideWorldReply` を表の `decide` の種類で分岐する形に（電話型: 線の様子 → つながる確率、訪問型: 通行止 → 警戒の確率、手配型: 電話の様子の確率と職員の空き・訪問看護の印、受入型: 時間ごとの確率、報告型、記録型: いつも ok）。確率の表（WORLD_ODDS）に手配・業者・応援の行を足す（例: 業者 ok 0.7・busy 0.4・down 0、応援 ok 0.6・busy 0.3）。世界の事実（通行止・不通・休止・職員の空き・訪問看護が来られない）は今までどおり先に見る
- 返事の状態（ActionStatus）に `scheduled`（手配済で、着くのは後）を足す。言葉は 2〜4 字（「手配済」のまま使えるなら増やさない）
- 本人・家族・支援者・民生委員への電話で出るかは今までどおり本人役の割合（lib/drill/persona.ts の decideCallPickup。触らない）

### 3. 手を打つ所（lib/drill/actions.ts。T90 の取り込みのあと）

- `act` の返事のあとの効き目を、表の `effects` を順に当てる形に（今の「訪問で着いた → 印を消す」「訪問依頼 → dispatched」「受入 → 印を消す」もこの形に書き直す。動きは同じ）。`applyResult` も同じ表を読む（保存した物からの作り直しで同じ所を通る）
- `arrivals` の到着は settleWorld（T90 の準備）が進める。到着した人の報告は本人役（T90 の理由 action・T93 の言葉）
- 職員の空きは `staff` の分だけ減らし、back で戻す（今の dispatch と同じ）
- act の「手の途中で区切りを越える」while は T90 が直すので触らない

### 4. 自由に書く手（新しい lib/drill/free-action.ts）

- 入力: ケアマネの文（120 字まで）と相手の本人（任意）。**ケアマネが打った文が Claude に渡る初めての口**なので、必ず `pseudonymizeText`（lib/pseudonym）を通し、伏せきれない（PseudonymLeakError）なら手を**断る**（400、理由「伏字不可」。黙って送らない）。メモ（T59 の memo）は今までどおり Claude に渡さない
- 読み替え: askJson（用途 director、Opus。lib/claude/call.ts の門）に、伏せた文・本人の仮名・その本人に使える手の表（id・label・words・相手の区分）・その時に分かっている世界の事実（電話の様子・家の前の道・職員の空き）を渡し、`{ kind: 表の id か "note", callee: 連絡先の区分か "", text: 現場の言い方の 1 文（30 字まで）, reason: 読み替えの理由（60 字まで） }` を返させる。zod で形を確かめ、kind が表に無い・その本人に使えない・相手の区分が無い物は `note`（記録）に落とす。「119 を呼ぶ」「救急車を呼んだ」に当たる文は `advise_119` に落とし、救急が来た結果を作らない
- 結果: 読み替えた手の表の行で、所要時間・結果（world-reply.ts の確率）・効き目をコードが決める。画面の 1 文は Claude の text（AI の印）、使えなければ固定の文。手の記録（ActionRecord）に `kind: "free"`、`as: 読み替えた id`、`text: 伏せた文を氏名に戻した物（サーバーの中だけ）`、`reason` を持つ（drills.world の JSON。採点は `as` で数える）
- **文は Claude に流さない**: `text` と `reason` は T90 の準備で広げた `withoutMemo`（engine.ts）が落とす欄。`state.actions` は監督・世界・本人役・講評の入力に渡るので、そこに渡るのは `kind: "free"` と `as`（読み替えた手の id。Claude に渡す言い方は表の words）だけ。読み替えの askJson に渡す物は伏せた文だけで、元の文を別の道で送らない
- 回数: 1 訓練 10 回まで（counts.free。T90 の準備の欄）。超えたら読み替えずに `note`。1 日の上限・150 の上限（T90）も同じ数で数える
- 待ち: Opus 1 回（10〜13 秒）。画面の待ちの印は ActionPanel の実行の横に

## 守ること

- 色と連絡順はルールの表（lib/triage）だけ。手の効き目が表に届く道は `checks`（時計の頼り先の確認の写し）と `heard`（聞いた安否）だけで、表の入力の形は今のまま。Claude の出力は色と順番に触れない
- 自由に書く手でも、世界の変化と結果はコードと確率。Claude は「表のどの手か」と文だけ。askJson の外に Claude を呼ぶ道を作らない。ケアマネの文は仮名化の門を通し、伏せきれなければ断る
- 119 は勧めるまで。救急が来た・病院に運ばれた、の結果を世界が作らない。「死亡」の語を使わない。本人役の決まり（T18 の 6・7）は変えない
- 仮想モードの結末はデモ事業所だけ。本物の API は呼ばない（偽の client）。鍵を探さない。履歴を書き換えない。端末は増やさない。他のプロジェクトの名前を書かない。文書に作者の発言の引用・やり取り・人の名前を書かない
- 画面の言葉: 2〜4 字の漢語（表の label の列のとおり）。「を・が・の」でつなぐ文にしない。常設の説明文を置かない。使わない語: 診断・判定・重症・緊急度・札・購入（講評の禁じる語に掛かる）
- 見た目の避ける型: ピル型、01/02 の番号ラベル、等幅のラベル、グラデーション・光る影、字間、絵文字、`<details>` の黒い▼、真っ黒の塗りボタン、選んだ印にテーマ色の薄い下地。押したときは灰色だけ。新しい押せる物には focus-visible:outline-solid。375px で押せること
- 並列の衝突: T90（engine・db・http・actions の while）、T92（scenarios の印・director の差し込み）、T93（persona・hooks・ActionLog）、T94（score・review）が同時に動く。T90 の準備の PR の前は新しいファイルだけ。PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす）。migration は要らない
