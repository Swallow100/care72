# T117 様式の欄で台帳に元の無い物を、台帳に置き場を作り、問い・書類に直接書く・書く話す（AI 入力）・書類の取り込みで埋める

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T03・T45（入れる欄の問い）、T86（添付の様式）、T101・T111 を読む。

## 意図（なぜこの作業か）

新しい事業所で 1 人を登録し、問いと手の編集で台帳を埋めて計画書（松山市）を開くと、近親者や支援者のフリガナなどがいつまでも空のまま残る。これらは台帳に置き場が無いので、入れる欄も問いも無い。

- 問い（lib/intake/ask.ts、本人のページの「問い 残り N 問」）は、台帳の空いた欄（lib/intake/fields.ts の INTAKE_FIELDS）から 1 問ずつ作る。台帳に無い欄は問いに出ない
- 計画書の欄の元（lib/forms/matsuyama.ts の source）が NO_SOURCE（「台帳に無い」）の物がある:
  - 近親者・避難支援等実施者 1・2 のフリガナ（連絡先 contacts は続柄・名前・電話 1 つ・距離・夜間・車・スマホ・備考だけ）
  - 近親者・実施者の住所（距離の reach で代わりにしていて「住所は持たない」）と携帯番号（電話 1 つと備考で代わり）
  - 組織・団体名称と電話（自主防災組織・町内会など）
  - 住居の【種別】（戸建住宅・共同住宅）
  - 避難場所ごとの【時間】、最寄りの避難場所
  - まつやま総合防災マップからの引用（あり・なし）
- 紙の上の帯の「未確認 27」と問いの「残り 37 問」は、別の物を数えていて合わない

様式の空きを、ケアマネが使いやすい道のどれからでも埋められるようにしたい。入れた値は台帳に入れて、本人のページ・連絡順・訓練・医療要約など、アプリの中でも使えるようにしたい。紙のためだけの別の入力を作らない（正は台帳の 1 か所）。埋める道は 4 つ:

1. **問い**: 本人のページの「問い 残り N 問」で 1 問ずつ（今の T03・T45 の形）
2. **書類に直接書く**: 紙の画面（計画書など）で空の欄を押し、その場で書く。保存すると台帳のその欄に入り、本人のページにも出る
3. **書く・話す（AI 入力）**: 様子やケアプランの文を貼る・書く・話すと、Claude が欄に分ける（今の AI 入力。新しく置き場を作った欄も分ける先に入れる）
4. **書類の取り込み**: 前に書いた計画書・アセスメントなどの写真・PDF を読み、欄に分ける（今の「写真・PDF 読取」）

どの道でも、入る前に「どの欄に何が入るか」を見せてケアマネが確かめる（今の AI 入力の確かめの形にそろえる）。

## 先に決めること（問い）

1. 連絡先に足す物: フリガナ・住所・2 つ目の電話（固定・携帯）。住所はどこまで持つか（番地まで／町名まで）。持てば計画書の欄が埋まるが、台帳の個人の情報が増える
2. 組織・団体（自主防災組織・町内会）の置き場:
   - (a) 事業所の設定に地区ごとに持ち、本人の町名から選ぶ
   - (b) 人ごとの台帳に持つ（推し。地区の名簿を事業所が持たない形）
3. 避難場所の【時間】と最寄りの避難場所: T112 の経路の見込み時間・避難場所の一覧から入れるか（推し。ケアマネが確かめて直せる）、手で書くか
4. 添付の様式（T86。ほかの市の様式を AI が欄の対応にした物）で、台帳に対応の無い欄が出たとき:
   - (a) その様式の欄として問いに出し、答えは人ごとの「様式の追加の欄」に持つ（その様式の紙にだけ刷る）
   - (b) 台帳に近い欄があれば対応の付け直しを勧め、無ければ紙に手で書く欄にする
5. フリガナ・住所・電話（氏名と同じ扱いで Claude に渡さない物）を、書く・話す・書類の取り込みの道でどう埋めるか:
   - (a) この 3 つは問いと書類に直接書く道だけで埋め、AI の道では埋めない（推し。今の門のまま）。取り込んだ書類にあれば「フリガナ・住所は手で」と出す
   - (b) 端末の中だけで読む道（Claude に送らない文字の読み取り）を作り、取り込んだ書類からも埋める。端末の中で読めるか・精度・重さを作業者が確かめる

## 作る物

1. **欄の棚卸し**: 同梱の様式（計画書 松山市・内閣府の様式例・医療要約・様式 9）の全部の欄を、(A) 台帳にある／(B) 台帳に置き場を作る／(C) 紙だけ（署名・受付印・手書き）に分けた表を docs/progress/t117.md に。(C) は HANDWRITE のまま
2. **台帳の置き場**: (B) の物を台帳に（連絡先の列は migration。番号は作業者が migrations/ と全部の branch を見て決める）。本人のページの編集の欄にも出す
3. **問い**: (B) の物を INTAKE_FIELDS に足し、問いの文・なぜ要るか・例（T45 の 3 つ）を定型で。順は今の決まり（医療 → 夜間 → その他）の後ろに、使っている様式の欄の物を先に
4. **様式の元**: (B) の欄の source を台帳から読む形に（NO_SOURCE を減らす）。T111 の空の値の刷り方に合わせる
5. **書類に直接書く**: 紙の画面（components/forms の OverlaySheet・MatsuyamaSheet など）で、(A)・(B) の欄を押すとその欄の入力が開き、保存で台帳に入る。(C) の欄は押せない。押せる欄は画面だけの印で分かるように（紙には刷らない）
6. **AI の道**: AI 入力（書く・話す）と写真・PDF 読取の分ける先（lib/intake の extract・schema）に (B) の欄を足す。問い 5 の答えの物は除く
7. **数をそろえる**: 紙の帯の「未確認 N」は、問いで埋められる物と手で書く物を分けて出す（例「未確認 12・手書き 3」）。問いの「残り N 問」と、紙の未確認のうち問いで埋められる物が同じ元から数えられること
8. **テスト**: 棚卸しの表の (B) が全部、台帳の置き場・問い・様式の元・書類に直接書く入口の 4 つを持つ（漏れたら落ちる）。4 つの道のどれで入れても同じ台帳の値になる。種の 10 人で紙の未確認が減る。フリガナ・住所を Claude に渡さない（下の守ること）。`npm test`・`npm run typecheck`。375・1280、ライトとダーク
