# T49 赤のあとの聞き取りを増やす（選択の枝分かれ・声の問い・聞き取りメモ。Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md`（何を作っているか・越えない線・地図・進め方）→ `CLAUDE.md` → `docs/tasks/README.md` を読む。この文書は、それ以外に何も知らなくても作業できるように書いてある。

## 意図（なぜこの作業か）

発災時、本人のスマホで「無事じゃない」を押した人の情報は、ケアマネが誰から順に連絡するかを決める材料になる。今は押したあとに聞く事が 4 問（けが・家にいるか・動けるか・薬があるか）しか無く、録音の言葉は文字起こしのまま一覧の行の詳細に出るだけ。録音を 5 つに分けるだけでは簡素化しすぎで、場所・家具に挟まっている・どこにいたか・胸が少し痛い・足を打った、のような細かい事実がケアマネに要る。押せる人にはオンボーディングのように選択肢で 1 問ずつ事実を取り、押せなくて声に切り替わった人からも、制約の中で状況を取る。

守る線: 聞くのは **事実** だけで、症状の重さや緊急度を点数にしない。AI は本人の言葉を欄に **そのまま写す** だけで、言い換えず、推し量らず、判断しない。色と連絡の順は今まで通りルールの表だけで決め、聞き取りの結果で順を動かさない。119 の案内は固定の文をいつも出す。これを守れば「問診票を内容を変えずに電子化する物」の側で、医療機器にも、AI に緊急度を判断させる形にもならない。

## 目的

本人・家族のスマホで「無事じゃない」を押したあと、今は 4 問（けが・家・動けるか・薬）と録音だけで、ケアマネに届く事実が少ない（docs/DECISIONS.md「本人・家族のスマホと聞き取り」）。押せる人にはオンボーディングのように 1 画面 1 問で選択肢を押させて事実を取り、押せなくなった人には同じ問いを声で 1 つずつ読み上げて「はい・いいえ」を拾い、録音の言葉からは Claude（Haiku）が決まった欄に本人の言葉をそのまま入れる「聞き取りメモ」を作る。色と順番は今まで通りルールの表だけで決め、聞き取りは動かさない。

## 作る物

1. **問いの表（コードの定数、1 か所）**: lib/signals/questions.ts に、問いの id・文（やさしい日本語、{漢字|よみ}）・選択肢（2〜4 つ＋「わからない」）・次の問い（答えで枝分かれ）・声で読む文・声の答えの言葉の一致表を持つ。問いは事実だけで、重さ・点数・緊急度を聞かない。今の 4 問はこの表の先頭に移す。枝の例:
   - いる場所: 家・避難所・ほか → 家なら 1 階・2 階・外 → 部屋（寝室・居間・トイレ・風呂・台所・玄関・ほか）。避難所・ほかは名前を声で（録音に残す）
   - 出られるか: 出られる・出られない → 出られないなら 何に（ドア・家具・倒れた物・水・ほか）
   - けが: ある・ない → あるなら どこ（頭・胸・おなか・腕・足・ほか）→ 血は 出ているか（出ている・出ていない）
   - からだの つらさ（本人の言葉を欄に残すためで、重さは聞かない）: 息が くるしい・胸が いたい・めまい・はきけ・ない・ほか
   - 水: 来ていない・床・ひざ・腰より上
   - 火・ガスの におい: ある・ない
   - 機械（台帳に機器がある人だけ出す）: 動いている・止まった・わからない
   - 薬: ある・ない・わからない
   - そばに いる人: ひとり・家族・近所の人・ほか
   - れんらく: この スマホ・電話・ない
   - 頼みたい こと: 声で（録音へ）
   表の形・順・言葉は作業の側が決めてよいが、「とばす」をどの問いにも置き、どこで止めても送れる。119 の固定の 1 行（T48）はどの画面にも出し続ける
2. **押す流れ**: 1 画面 1 問、大きな 2〜4 つのボタン、押すたびに答えをすぐ送る（最後まで待たない。今の「赤を押した時点で一覧に赤が出る」と同じ考え。サーバーは同じ信号の行に答えを足す受け口を持つ。新しい API か、今の添え方の拡張。版の競合は後勝ちでよい）。答えは signals の表に JSON の欄（answers）で持ち、今の 4 問の列（injured・at_home・can_move・has_medicine）はそのまま残して同じ値を書く（ルールの表と採点が読むため）。migration は origin を見て空いている番号で（0005 は T47、0002〜0004 は済み）
3. **声の流れ**: どの問いでも 20 秒押さなければ（今の IDLE_MS）、T48 の「AI が きいています」のあと、その問いと選択肢を声で読み上げ（Gemini TTS があればそれ、無ければ端末の読み上げ）、10 秒聞く。ブラウザの文字起こし（lib/speech）に選択肢の言葉か「はい・いいえ・うん・ない・ある」などが含まれれば答えにし、無ければ「わからない」で次の問いへ。Claude は使わない（言葉の一致だけ）。問いが終わったら今の定型文「大丈夫ですか。状況を説明してください」と 30 秒の録音（延長・聞き直し 2 回・無音なら録音だけ送る、は今のまま）。周りの音は問いの間も録り続ける（定型文と問いを読む間は今と同じく止める）。録音は 1 本のまま
4. **聞き取りメモ（Claude、Haiku）**: lib/classify の 1 回の呼び出しに欄を足す（別の呼び出しにしない。上限の回数を増やさない）。返事の形に memo を足す: いる場所・閉じ込め（何に）・体の訴え（本人の言葉のまま）・けがの部位・水・火とガス・機器・薬・そばにいる人・連絡手段・頼みたいこと、の各欄が { text: 文字起こしからそのまま写した 30 字まで | null }。決まり: 文字起こしに無い物は null、言い換えない、推し量らない、重さ・緊急度・診断を書かない（今の quote と同じ）。押した答えがある欄は Claude の値で上書きしない（人が押した物が先。AI は空いている欄を埋めるだけ）。欄は lib/labels.ts に 1 か所。メモは signals に JSON で持つ
5. **ケアマネの画面**: 担当一覧の行の詳細（RowDetail）に「聞き取り」の欄を足し、問いの答え（人が押した物、印なし）と Claude が埋めた欄（AI の印、ケアマネが直せる。直した物は人の値になり AI の印が外れる）を同じ表で出す。文字起こしと録音の「聞く」は今のまま。一覧の行の理由の 1 行は変えない（色と順は T48 のあとのルールの表のまま。メモは動かさない）
6. **家族・支援者のスマホ**: 「無事じゃない」のあとは本人と同じ問いの表（主語を「本人は」に。FamilyView の続柄の呼び方を使う）。声の流れは本人だけ（家族は押せる前提）
7. **訓練との接続**: 本人役（T18）の speech に場所・挟まれ・体の訴えが入っていれば、同じ Haiku の分類でメモが埋まる（本人役の指示の変更は T50 の担当。ここでは触らない）
8. **テスト**: 問いの表の枝が閉じている（どの答えも次の問いか終わりに着く）、どの画面にも 119 の 1 行、押すたびに送られる、声の一致（はい・いいえ・選択肢の言葉・無言）、メモの schema と「人の答えが先」の決まり、メモが色と順を動かさない（lib/triage の入力に memo が無いことを型で）、禁じる語（診断・判定・重症・緊急度）が問いと欄の言葉に無い

## 終わりの形

- 本人のスマホで赤を押すと、1 画面 1 問の問いが枝分かれで続き、押すたびに担当一覧の行の詳細に答えが増える。どの画面にも 119 の 1 行
- 20 秒押さないと問いが声になり、「はい・いいえ」で進む。終わると今の録音
- 録音の文字起こしから「聞き取り」の欄が AI の印つきで埋まり、ケアマネが直せる。色と順は変わらない
- `npm test`・`npm run typecheck`。docs/progress/t49.md に、問いの表の一覧（言葉はあとで設計の側が Gemini に通す）、変えた API、確かめた所、問い。PR を integrate/t11-t12 宛に
