# T123 評価の 2 回目で残った訓練の AI の問題を直す（72 時間で終わらない回・人ごとの筋・世界の部屋の代替と待ち）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。評価の 2 回目の訓練の分の報告（docs/progress/eval-r2-drill-findings.md・eval-drill-r2.md）と 1 回目の報告（eval-r1-findings.md）、訓練の時計と手の作り（docs/tasks/T110.md・T121.md とその進み）を読む。生の記録はリポジトリの外（評価の台の記録の置き場、run-NN.jsonl・summary.json）にあり、読むだけ。中の架空の人の台詞をリポジトリに写さない。

## 意図（なぜこの作業か）

評価の 2 回目（本物の Claude、訓練 10 回、T118・T121 の入った木）で、訓練の AI に次の問題が残った・新しく出た（findings の番号）。

- #1（新しく出た、いちばん重い）大雨・10 人の 1 回が 72 時間で止まり、終わらない。手（通話の往復）の所要でケアマネの時計が 72 時間に着いたのに区切りは 72 時間の手前のままで、そのあとの「進める」と手が全部「進める時刻が違う」で断られ、結末・点・講評が出ない。画面の「進める」も同じ入口を通るので、利用者も抜けられない
- #2 人ごとの筋がまだ崩れる。審査役の「人ごとの筋」が 3 回とも 2/5 のまま。通行止めの先に届け物・人が着く、話し手の続柄が途中で替わる、などが根拠に挙がる
- #3・#5 世界の部屋の代替が 2 → 5 に増え、10 分版（審査員の見せ場）の進める 1 回の待ちが 17.4 → 20.3 秒に伸びた

訓練は型にはめない。筋書きの表に行を足して多様さを作るのではなく、筋を通したまま自由にさせる。

## 作る物

1. **どの想定・進め方でも 72 時間で終わる**（#1）
   - 記録から再現し、終わりの条件（72 時間に着いたら終わり・採点・講評へ）が、T110 の手の分だけ進む時計・T121 の時刻を後ろに回す決まりと合わずに詰む所を直す
   - 72 時間を超える時刻の出来事・手の扱い（時計は 72 時間で止める、72 時間に着いた後の手は打てない理由を短く返す）と、最後の区切りの扱い（どの進め方でも 72 時間の区切りを作って終わる）
   - どの想定・進め方でも必ず終われることをテストで確かめる（10 分版・大雨・地震・仮想、30 分・1 時間・3 時間・次まで・手の分、手と通話の往復を 72 時間の手前で打つ形を含む）
2. **人ごとの筋**（#2）
   - T121 の世界の状態（変わった時刻・変わり方の決まり・話し手）が、どの道（本人役の刻み・まとめ呼び・監督・世界の部屋・世界の 1 回呼び・訪問・通話の最初の言葉・通話の続き）で効いていて、どの道で漏れているかを記録から数える
   - 漏れている道に同じ決まりを当てる（今の状態の文、話し手と本人の呼び方、合わない文を落とす所、届いた物・着いた人の扱い）
   - 審査役の根拠の文を種類ごとに数え、多い種類から潰す
3. **世界の部屋の代替と待ち**（#3・#5）
   - T121 の変更（並べて呼ぶ・部屋の送りの見直し・入力の文の長さ）と、代替の増加・10 分版の待ちの伸びの関係を記録で調べる
   - 代替の数と 10 分版の待ちを評価の 1 回目以下に戻す
4. **テスト**（偽の client）: 72 時間で終わる、漏れていた道に決まりが当たる、部屋の代替と待ち。直したあと、偽の client で `npm run eval:drill -- --runs 6` を回して前と比べる（本物は回さない。本物の 3 回目は評価専用の作業者が回す）

## 守ること

- 色と連絡順はルールの表（lib/triage）だけ。状態の決まりは色と順を動かさない
- 本人役の決まり（名前・住所・電話・病名・薬の量・医療の助言・「死亡」を言わない）は変えない。本人役の掃除（T118）を全部の道で通す
- Claude に渡す物は仮名化の門（lib/pseudonym → askJson）を通した物だけ
- 多様さは筋書きの表に行を足さず、自由さで
- 10 分版は短く終わる形を保つ。審査員の流れを壊さない
- 本物の API・本番の D1（--remote）に触らない。鍵を探さない。.dev.vars を読まない。履歴を書き換えない。他の worktree に触らない（評価の記録の置き場は読むだけ）
- 文書に作者の発言の引用・作業のやり取り・人の名前を書かない（公開のリポジトリ）。架空の人の台詞も写さない。作業者の一時ファイルは scratchpad の `t123/` の下
- PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす）。merge commit にも Co-Authored-By。migration は要らない見込み
