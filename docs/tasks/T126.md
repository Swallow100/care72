# T126 訓練の手の欄: できない手を薄く、分かった事・頼み事・時計から打てる手を出す（Opus、分岐）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。手の表（T91 の lib/drill/action-catalog.ts）、本人役の頼み事（T93 の world.asks と lib/drill/dialogue.ts の ASK_LABELS）、手の可否と所要の決まり（T110 の lib/drill/action-terms.ts）を取り込んだあとの物。

## 意図（なぜこの作業か）

訓練の対応の欄で、押せない手（「通話不可」など）と押せる手が同じ濃さに見え、見分けにくい。並びも手の表の順のままで、押せない手が押せる手の間に挟まる。

また、訪問や通話で本人の様子が分かり（酸素の電池が切れかけている・予備ボンベの残り・薬が別の階にある）、頼み事に「電源」「薬」の印が出ても、それに対してどの手を打てるかが画面から読めない。電話の手が全部押せない時は、どの別の道（訪問・職員に行ってもらう・近所に頼む・自由対応）が今打てるかも分からない。

選ぶのはケアマネで、画面は候補を短い印で並べるだけにする（押し付けない）。

## 作る物

### 1. できない手を薄く、できる手を先に（components/drill/ActionPanel.tsx）

- 押せない手（決まりの表の押せない理由・相手の連絡先が台帳に無い）は、字と面を弱くする（ボタンの地を外し、字とアイコンを薄く）。理由の 2〜4 字（「通話不可」「通行止」「相手なし」）は読める濃さのまま残す
- 区分の段の中で、押せる手を先、押せない手をあとに（手の表の順は保つ。何も押せない物が無ければ今の並びのまま）
- 本人を選ぶ前の「本人の要る手」は、押せない手と分けて今の見た目のまま（選べば押せるため）

### 2. 打てる手の候補（新しい lib/drill/action-hints.ts。表は 1 か所）

- 元: 未対応の頼み事（world.asks）、走っている本人の時計（台帳の時計の区分。酸素・呼吸器・吸引・透析・インスリン・栄養・薬）と未確認の頼り先、公表の事実（その人の透析施設の休止・訪問看護が来られない）
- 頼み事 → 手は、手の表の効き目（ask_done）から引き、足りない物だけ小さな表で足す（電源 → 電源手配・業者連絡、薬 → 薬手配、家族 → 連絡先電話）。時計の区分 → 手も同じファイルの表（酸素・呼吸器 → 119勧奨・病院受入・電源手配・業者連絡、透析 → 透析調整・病院受入、薬の区分 → 薬手配）
- 候補の並びは手の表の順。急ぐ順に並べ替えない（並べ替えは表の判断になる）。押せない候補は 1 と同じく薄く、理由つきであとに。向かっている人がいる・届いた・確認済の手は「手配済」
- 同じ手の並びになる元はまとめる（透析施設の休止と透析の時計 → 1 行）
- 電話の手（結果の決め方が電話型の手）が全部押せない時は「代替」の 1 行（訪問・訪問依頼・見守依頼・自由対応）。それぞれの可否は決まりの表の結果のまま（押せなければ薄く理由つき）
- 色と連絡順（lib/triage）には使わない。手の可否と所要は決まりの表（action-terms.ts の ActionTerm の minutes・block・targets）の結果を読むだけで、決まりの中身は変えない
- 医療の助言をしない。候補は手の名前だけで、何をすべきとは書かない

### 3. 画面

- 対応の欄: 本人を選ぶと、手の段の上に「候補」（元の印 → 手のボタン）。押せる候補を押すと、その手を選んだ形になる
- 本人の詳細（左の表の行の詳細）: 未対応の頼み事の下に同じ「候補」。押すと対応の欄でその本人とその手を選ぶ
- 進行中の今の区切りだけ（再生では出さない）。決まりを選ばなかった訓練は、相手の連絡先の有無だけで可否を出す
- 言葉は 2〜4 字の漢語（候補・代替・手配済・相手なし）。常設の説明文を置かない

### 4. テスト（新しい lib/drill/t126.test.ts）

- 表: 頼み事・時計の区分 → 候補、同じ並びのまとめ、手配済、未対応でない頼み事は出さない
- 電話の手が全部押せない時の代替の 1 行（ActionTerm を手で作り、決まりの表の中身に頼らない）
- 押せない手の見た目の class と理由、相手なし、押せる手が先
- 本人の詳細の候補、手元の D1 で大雨想定（連続の時計と決まり）を始めて画面の中身に候補が出る（10 分版を使わない）
- `npx vitest run --maxWorkers=3`・`npm run typecheck`。画面は 1920・1536・1280（PC が主）と 375（崩れないか）、ライトとダーク

## 守ること

- 色と連絡順はルールの表（lib/triage）だけ。候補の表は色と順に使わない
- 医療の助言をしない。候補は手の名前だけで、押し付けない（短い印）
- 本人役の決まり（名前・住所・電話を言わない、診断・判定・重症・病名・薬の量・助言を言わない、「死亡」の語を使わない）は変えない
- 本物の API・本番の D1（--remote）に触らない。鍵を探さない。.dev.vars を読まない。履歴を書き換えない。他の worktree に触らない
- 画面の言葉は 2〜4 字の漢語。見出しに読点・句点を付けない。CLAUDE.md の使わない型（ピル型・番号ラベル・等幅のラベル・グラデーション・字間・絵文字・`<details>` の黒い▼・真っ黒の塗りボタン・テーマ色の薄い下地）。押したときは灰色だけ
- 文書に作者の発言の引用・作業のやり取り・人の名前を書かない（公開のリポジトリ）。作業者の一時ファイルは scratchpad の `t126/` の下
- PR の前に origin/integrate/t11-t12 を取り込んで衝突を解く（両方を活かす。T124・T125 と同時に動く）。merge commit にも Co-Authored-By。migration は要らない
