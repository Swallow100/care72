# T41 ログインの守りと配信後の確かめ（T27 の残り）

## 目的

公開デモ（https://care72.app）が審査の 11/9〜10 まで安全に動くように、T27 の残り（docs/tasks/T27.md の「作る物（残り）」1〜4）を入れる。

## 読む物

docs/tasks/T27.md、lib/auth/（credential.ts、session）、app/api/auth/、app/api/health/、lib/claude/usage.ts（1 日の上限 AI_DAILY_LIMIT）、tools/deploy/rebuild-remote.sh（配信の手順と最後の確かめ）、README.md の「触り方」、docs/HANDOFF.md の「配信」「Secrets」。

## 作る物

1. ログインの回数の制限: 失敗を D1 に数える（表 login_attempts: ID・送信元〔CF-Connecting-IP〕・時刻・成否）。同じ ID か同じ送信元で 15 分に 10 回失敗したら、その後 15 分は 429 で止める（画面は「しばらく待つ」の短い 1 文、残りの分）。成功したら数を消す。古い行は 1 日で消す（ログインのついでに削除）。Cloudflare の rate limiting の規則は使わない（設定がリポジトリの外に出るため）。migration は新しい番号のファイルで（T22 が 0002 を足すかもしれないので、PR の前に origin/integrate/t11-t12 を見て重なっていれば番号を進める）
2. `/api/health` に配信中の commit（短い hash）と build の時刻を足す。build のときに `git rev-parse --short HEAD` を読んで lib/version.ts を作る prebuild（生成物は commit しない、.gitignore）。配信の確かめ（tools/deploy/rebuild-remote.sh の最後）で出した commit と一致するかを見る
3. 配信後の確かめの script `tools/deploy/check-remote.mjs`: /api/health の ok・ai・commit、ログインなしの `/` が `/login` へ、`/me`・`/office`・`/drill` がログインなしでは `/login` へ、workers.dev が閉じている（1042 か 404）、を数えて PASS/FAIL。ログインが要る確かめ（審査員ログイン → 役選択 → 担当一覧、訓練 10 分版 1 回、最初に戻す）は、環境変数 CHECK_LOGIN_ID・CHECK_LOGIN_PASSWORD があるときだけ行う（作者が自分の端末で流す。値はファイルに書かない。エージェントは流さない）
4. 1 日の上限とクレジット: 今の AI_DAILY_LIMIT の値、1 回の訓練（監督 Opus 1 回＋本人役 Haiku 10 体＋声）でおよそ何回使うか、審査の 2 日で足りるかを docs/PROGRESS.md に。足りなければ上限の値の案
5. README の「触り方」を今の形に（URL は care72.app。ID とパスワードは書かない。役の選び方、本人のスマホ、訓練 10 分版、印刷、最初に戻す）

## 終わりの形

- `npm test`・`npm run typecheck` が通り、回数制限のテスト（10 回で止まる・15 分で戻る・成功で消える）がある
- `/api/health` に commit が出る（手元の dev で確かめる）
- `node tools/deploy/check-remote.mjs` がログインなしの分で PASS（手元では dev の URL に向けて）
- docs/progress/t41.md に何を変えたか・未確認・作者への問い
