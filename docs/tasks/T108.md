# T108 訓練の AI の評価の台（何度も回して、壊れ方と単調さを数で見る）

このプロジェクトを知らないエージェントは、先に `docs/tasks/CONTEXT.md` → `CLAUDE.md` → `docs/tasks/README.md` を読む。T89〜T105 を取り込んだあとの物。訓練の作り（lib/drill の engine・persona・director・world-room・world-oneshot・scenarios・time-odds・talk・score・review）と docs/progress/t89〜t105 も読む。

## 意図（なぜこの作業か）

訓練は型にはめられない。回すたびに世界の流れも、本人役の反応も違う。だから 1 回回して目で見るだけでは、どこが壊れているのか、どこが毎回同じで単調なのかが分からない。

同じ命令で何度も回し、壊れ方（禁じた中身・形の失敗・仮名の漏れ・止まった刻み・食い違い）と単調さ（出来事の種類の偏り・並びの重なり・言葉の重なり・人ごとの反応の差）を数にし、前の回との差を 1 行で読めるようにする。直しの作業はこの数を見て進める。

固定の種だけで回すと、作り物の表（決まった筋）を測ってしまう。種は回ごとに変え、記録して同じ回を作り直せるようにする。

## 作る物

1. **回す台**（`tools/eval/drill/`、`npm run eval:drill -- --runs N`）
   - 画面を通さず、訓練の公開の入口（開始・進める・手・通話の往復・読み戻し。lib/drill の route が使う物）だけで回す。中の作り（engine の型の細部）に頼らない（同時に engine を直す作業〔T110〕があるため）
   - 毎回、種・想定（10 分版・仮想・大雨・地震）・規模（仮想だけ。大雨の警戒レベル 3〜5、地震の震度 5強〜7。大雨想定・地震想定・10 分版の規模は想定の表のまま）・参加する人の組（担当 10 人の部分集合）・進め方（30 分・1 時間・3 時間・次まで。10 分版は刻み）・ケアマネの手（表の手と自由文の手を混ぜる。通話の往復も）を変える。種と選んだ物は記録し、`--seed` で同じ回を作り直せる（本物の Claude の返事は同じにならない）
   - 既定は偽の client（Claude を呼ばない。返事は種から作る）。本物は `--real` と環境変数の鍵があるときだけ。作業者は本物を回さない。鍵のファイルを読まない・探さない
   - D1 は手元の物だけ（回ごとに migrations と種の 10 人を入れた新しい DB）。本番に触らない
2. **機械の検査**（全部の回）
   - 本人役の禁じる中身（名前・住所・電話・病名・薬の量・医療の助言・人の生き死にの語など。今の決まりの表〔lib/drill と lib/pseudonym の正規表現と鍵〕から）。モデルの生の返事と、画面に出た物を分けて数える
   - JSON の形の失敗・断られた・時間切れ・つながらない（ai_calls）と再試行
   - 刻みごとの時間、1 回の訓練の呼び出しの数と 1 訓練の上限（150）・1 日の上限（200）との比
   - 時間ごとの起きやすさ（lib/drill/time-odds.ts）との食い違い（差し込みの種類が帯の目安の外だった割合。合否にしない）
   - 矛盾（けがを言った人が、手も到着も無いまま次に「無事」になる、結末のあとに連絡がある、など）
   - 仮名の漏れ（Claude と世界の部屋に送った中身の全文に、台帳の名前・カナ・電話・町名・避難先の名前・電話の形が無いか）
   - 止まった・失敗した刻みの数（「停止」「代替」の印、要求の失敗）
3. **多様さ**（N 回をまとめて）: 出来事の種類の数と偏り、出来事の並びの重なり（Jaccard）、本人役の言葉の重なり（文字の n-gram）、人ごとの反応の差（同じ人が違う回でどれだけ違うか、違う人が同じ回でどれだけ違うか）
4. **審査役の採点**（見本の数回だけ）: Opus に 1 回の訓練の流れ（仮名化した物）を読ませ、本当らしさ・難しさ・多様さ・人ごとの筋の通り方・ケアマネが学べるか を 1〜5 で。用途は採点（scoring）を使い、新しい用途を足さない。偽の client では形だけ確かめる
5. **記録**
   - 回ごとに JSON Lines（リポジトリの外 `C:\Users\choco\dev\care72-qa\eval\drill\<回>\`。架空の人の台詞が入るため）: 刻みごとの世界の状態（時刻・出来事・本人ごとの状態・ケアマネの手と所要・職員の空き）、AI の呼び出し 1 つずつ（本人役・監督・世界の部屋・自由文の読み替え・講評・審査役のどれか、モデルと effort、仮名化したあとに送った中身の全文、返ってきた中身の全文、かかった時間、token と費用、失敗と再試行）、検査が引っかかった所とその根拠。あとから 1 回の訓練を最初から読み直せる順に並べる
   - 回のまとめは JSON（同じ場所）。前の回との差の表は `docs/progress/eval-drill-<日時>.md` に数だけ（台詞・名前を書かない）。費用は ai_calls と返事の token から見積もる
6. **テスト**（偽の client で数回の通し、検査と多様さの数え方の正しさ）

## 直し方の向き（このあとの直しの作業への注意）

多様さの数が悪いとき、筋書きの表（lib/drill/scenarios.ts）や出来事の表に行を足して数を良くしない。表に行を足すと、測っているのが表になり、訓練の自由さはかえって減る。世界（監督・世界の部屋）と本人役の作り方の自由さ（渡す事実の幅、人ごとの性格と暮らし、前の流れの覚え方、選べる種類の広さ）で直す。

偽の client の回の数（多様さ・時間・費用の見込み）は作り物。比べる基準にするのは本物の回だけにする。
