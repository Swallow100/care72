# T185 訓練の講評を人ごと・項目ごとに詳しく、訓練の間に作る

作者の指示（11/8 0 時台）: 講評を一人ごとに詳しくする。全体の講評も項目ごと（電話・行動など）に詳しく。良かった所も書く。待ちは、訓練を進めながら作れば解決するはず。急ぐ（朝の評価を待たずに出す）。

今の講評（lib/drill/review.ts、T141 で待ちを 56 秒から 24〜28 秒に縮めるために削った）: 指摘は最大 6 つ（REVIEW_LIMIT）・1 つ 70 字（FINDING_ASK）・要約 140 字（SUMMARY_ASK）、同じ種類は「代表の人と人数」に 1 つにまとめ（REVIEW_SYSTEM）、種類ごとの数が固定（KIND_ROOM）、通話の言葉は渡している（talkWordsSection）が聞き取り方・伝え方の種類が無い、良かった手の欄が無い。数字は lib/drill/score.ts が数える。

進みは docs/progress/t185.md。worktree care72-t185、branch task/t185（origin/integrate/t11-t12 から）。

## 作る物

1. 人ごとの講評: 訓練の参加者 1 人ずつに、その人への手（電話・訪問・手配・依頼）と結果（届いた時刻・時計・色の移り）を見た講評。良かった手と、次に試す事。数字は score.ts の機械の数え（作らせない）。人ごとに数文〜数行
2. 全体の講評を項目ごとに: 例 「連絡の順」「電話の聞き取りと伝え方」「訪問と手配」「報告（市・様式 9）」「時計と機器」「良かった所」。各項目に詳しい文。通話の言葉（talkWordsSection）から聞き取り方・伝え方を見る項目を足す
3. 訓練を進めながら作る: 人ごとの講評は、その人の流れが決まった所（その人の状態が落ち着いた刻み、または区切りごと）で、訓練の進みの裏で作って保存する（Workers の waitUntil など。進める操作の待ちを延ばさない）。最後の 72 時間のあとに作るのは全体の講評だけにし、人ごとの講評の要旨を入力に使って短く待てる形に。最後の待ちの目安は今（24〜28 秒）より短いか同じ
   - 途中で人の流れが変わったら（後の刻みで手が入った）、その人の講評を作り直す。作り直しの数に上限
   - 呼び出しの数（評価の r11 で 1 回 71、上限比 55.3%）と 1 日の上限（lib/claude/usage.ts）を確かめ、人ごとの講評で上限に当たらない形に（モデルは人ごとが軽い物、全体が Opus 5.5 など、設計の側の考えは自由。理由を記録に）
   - 鍵が無い・失敗のときは今と同じく AI の印なしの数字だけの講評に落ちる
4. 画面: 講評の画面（components/drill の講評・印刷）に、全体の項目と、人ごとの講評（人の名前ごとに開く・送る）。AI の印。紙に刷れる形（今の印刷を壊さない）
5. 終わった訓練の再生・前に保存した講評（今の形）も読めること

## 守ること

- 医療の助言をしない。「診断」「判定」「重症」「緊急度」「札」を使わない。講評は訓練の振り返りで、本人の医療の事を言い切らない（medical-reviewer の目で見る）
- 仮名化の決まり（Claude に渡す前）はそのまま。氏名・住所を渡さない
- 触らない所: lib/forms、lib/auth、lib/custody、訓練の開始の画面と参加者の選び方（T186 が触る。lib/drill/db.ts の開始の所・開始の画面）。engine.ts を触るときは最小に
- 本物の API は呼ばない（偽の AI で形を確かめる）。本物の確かめは設計の側が評価の作業者に頼む
