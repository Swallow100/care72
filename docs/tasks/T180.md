# T180 新規事業所の中で役を替えられるように

審査員の役変更には、デモの世界の 4 つの役（ケアマネ・医療班・本人・家族）と「新規事業所」（T115、lib/office/sandbox.ts）がある。新規事業所を選ぶと空の事業所の管理者（ケアマネ）になり、ケアマネ追加・利用者追加から始められる。ただ、そこで医療班・本人・家族を選ぶとデモの世界の役に戻り、自分で足した利用者の本人の画面・家族の画面・ほかのケアマネの画面・医療班の画面を見られない。

作者の指示（11/7 21 時）: 新規事業所は白紙から事業所・ケアマネ・利用者を足していき、足した利用者ごと・ケアマネごとの画面に替えられるようにする。デモの 4 つの役は今のまま互いにつながり、新規事業所の役は新規事業所の中だけでつながる（2 つの世界は混ざらない）。

進みは docs/progress/t180.md。worktree care72-t180、branch task/t180（origin/integrate/t11-t12 から）。

## やること

1. 役の一覧（components/ui/RoleMenu.tsx、lib/auth/choices.ts の roleChoicesFor）: 審査員がこのセッションの新規事業所を持っている（session の b がある）時、「新規事業所」の下に、その事業所の中の役を並べる
   - ケアマネ: 事業所のケアマネ全員（管理者と、足したケアマネ。judge_made の印のある物だけ）
   - 医療班: 新規事業所の医療班（受入の依頼は新規事業所から出た物だけが届く）
   - 本人: 足した利用者ごと（名前）
   - 家族: 利用者ごとの家族の連絡先（「〇〇さんの娘」のように）。家族の画面が出せる連絡先だけ
   - 人が多い時は、本人と家族を利用者ごとにまとめるなど、一覧が長くなりすぎない形に。今の役は今と同じ枠と太字
2. 役を替える所（/api/auth/role、lib/auth/session.ts の judge の形、lib/auth/wall.ts・scope.ts・principal.ts）: 新規事業所の中の役と、その相手（ケアマネのアカウント・利用者・連絡先の id）をセッションに持つ。サーバーで毎回、相手がこのセッションの b の事業所の中にあり、審査員が作った物かを確かめる（ほかの審査員の新規事業所・デモ・本物の事業所の物は選べない）。署名の中に入れる
3. 新規事業所の中の役で開く画面は、デモの役と同じ画面（本人のスマホ・家族のスマホ・医療班の受入一覧・ケアマネの担当一覧）を、新規事業所のデータで出す。本人が送った安否・家族の報告・ケアマネの受入依頼・医療班の受け取りが、新規事業所の中で互いに届く
4. デモの世界の 4 つの役は今のまま（新規事業所のデータが見えない。新規事業所の役からデモのデータも見えない）。山本（T95）の役変更は変えない
5. 毎朝 4 時の掃除（lib/seed/sandbox.ts）で新規事業所の物が全部消えることを保つ。足した表があれば SANDBOX_CLEAR に

## 守ること

- 壁を緩めない。審査員の壁（lib/auth/wall.ts）の外に出さない。本物の事業所のデータに届かない
- migration は足さない形で（要るなら docs/deploy/migrations.lock で 0040 を取ってから）
- 画面の決まり（CLAUDE.md）と言葉の決まり（ボタン・見出しは短い漢語、「札」「診断」「判定」「重症」「緊急度」を使わない）。新しい画面の言葉は記録に一覧で
- 触らない所: lib/drill、lib/forms、tools/eval

## 確かめ

- テスト: 役の一覧（新規事業所が無い時・ある時・人が増えた時）、役を替える所の確かめ（ほかの審査員の新規事業所の id、デモの人の id、本物の事業所の id は断る）、新規事業所の本人が送った安否がそこのケアマネの一覧に出てデモには出ない、医療班の受入一覧がそれぞれの世界の物だけ
- 手元の dev で通し: 審査員 → 新規事業所 → ケアマネ追加 → 利用者追加（家族の連絡先つき）→ 役変更で本人 → 安否を送る → 役変更でケアマネ → 一覧に出る → 受入依頼 → 役変更で医療班 → 受け取る → 役変更でデモのケアマネ → 新規事業所の物が無い。1280 と 375 の絵を見る
- 関係するテスト（lib/auth・lib/office・lib/custody・lib/seed、--maxWorkers=2）、`npm run -s typecheck`
