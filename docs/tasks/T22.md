# T22 採点とレビュー（Opus、訓練記録の紙面）

## 目的

訓練が終わると採点。関連死の条件に達した人、対応の順番の誤り、BCP（様式 9）の空欄、市役所への報告の遅れ、前回との比較。基準は lib/triage の表と出典の登録簿（T25）。同じレビューを本番の発災後にも出せる形にする。訓練記録を紙面にもする。評価の数字 2・3 はここから。

## 読む物

docs/SPEC.md の「訓練」（採点）、「評価」（数字 3 つ）、「医療の芯」（骨格と表）。lib/triage、lib/drill（T17〜T20）、lib/claude（T00）、T25 の登録簿。

## 作る物

- `lib/drill/score.ts`: 機械で数える部分（Claude を呼ばない）: 対応の順番の一致率（ケアマネが電話した順 と lib/triage の並び を比べる）、市役所への報告の遅れ（報告の手の時刻）、様式 9 の空欄、関連死の条件に達した人（時計を超えたまま手が無かった人。「条件に達した」と言い、「死亡」とは書かない）
- `lib/drill/review.ts`: Opus に講評を 1 回。入力は機械で数えた結果と手の履歴（仮名）。出力は `{ findings: [{ person, kind, text, basis }], summary }`。basis は登録簿（T25）の id だけ（登録簿に無い根拠は弾く）。「診断・用量・助言」を書かない system
- 訓練の右の欄に採点（数字 4 つと講評）。前回との比較（同じ事業所の前の訓練記録と並べる）
- 訓練記録の紙面（A4、印刷で PDF）: 筋書き、手の履歴、採点、講評。事業所の年 1 回の訓練の記録に使える
- 本番の発災後にも同じレビューを出す口（経過から手の履歴を作る）。余裕があれば
- テスト: 一致率の計算（10 人の筋で既知の順）、関連死の条件の判定、basis の検査、未設定で数字だけ出る

## 終わりの形

- 訓練（大雨）を終えると「順番の一致 7/10、報告の遅れ 2 時間、様式 9 の空欄 3、条件に達した人 1（田中: 透析先が決まらず 48 時間）」と講評が出て、紙面が印刷できる

## 触るファイル

lib/drill/score.ts、lib/drill/review.ts、components/drill/Score、app/drill/[id]/report/、docs/PROGRESS.md

## 守ること

数字は機械で、言葉は Opus で。講評に医療の助言を書かせない。「関連死」は「条件に達した」までの言い方。
