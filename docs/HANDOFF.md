### 5. 判断の仕方（docs/DECISIONS.md から）

- 審査基準の全項目で満点を狙う。テーマ 1（その世界に身を置いてきた人だからこそ見えた足りない物）。
- 簡素化しない。情報は多く出す（本人・家族のスマホだけ逆）。意味色をしっかり。画面の決まりは CLAUDE.md。AI っぽさ（書体・飾り・説明文・ピル型・グラデ）を出さない。
- 途中で足りない物は何でも足して、より使いやすく。起きるまで自走。
- 医療・法律は越えない線（CONTEXT.md の 2）に倒す。
- 言葉は 2〜4 字の漢語、「を・が・の」でつながない、「札」と書かない、「診断・判定・重症・緊急度」を書かない。画面の言葉は Gemini に一度通してから自分で採否。
- 文書は、プロジェクトを知らないエージェントに意図まで汲ませて漏れなく作業させるための物。作業の文書は「意図」と「渡す文」を持つ。
- 配信は Review 相当の確かめが通れば進める。止まるのは確かめの失敗と戻せない操作（本番の D1 の書き換え）だけ。本番の業務データは作者の許可があるときだけ書く。
- 動画: 青と白、本物の録画だけ、生成画像は図と象徴だけ、声は作者の声。

### 6. 危ない所

- 使用量の上限: 同じアカウントの Opus は全部で 1 つの枠。止まったら各 worktree の commit と docs/progress に途中の状態が残る。再開は同じ TNN.md と progress を読んで同じエージェントか新しいエージェントに。
- 2 つの Claude を同じ worktree に入れない。main の checkout は A の物。
- リポジトリの隣のフォルダは別のプロジェクト。開かない。
- Managed Agents（T50）はベータで Claude API だけ。審査の日に落ちても訓練が止まらないよう、1 回呼びへの自動の戻しを必ず残す。10 分版は部屋を使わない。
- 本番の D1 に `--file` の import を使わない（import の API で D1 が止まることがある）。書き込みは migration と seed の作り直しだけ。
- 実名・実在の町名・実在の利用者の記録を入れない（権利の無いデータは失格）。種の 10 人は架空。

## 進め方の決まり

- 計画と方向は設計の側（このファイルを書いた側）。品質に効かない所は Opus に分岐で自由にやらせてよい。多機能で情報を多く出す（本人・家族の画面は逆）。意味色をしっかり。簡素化しない。
- 1 作業 1 worktree + branch（`git worktree add ../care72-tNN -b task/tNN main`、`npm ci`、`npm run db:fresh`）、PR を作って merge commit で main へ。分岐の進みは `docs/progress/tNN.md` に書く（`docs/PROGRESS.md` は main の作業だけ。衝突を避けるため）。
- Opus の session limit に注意: 11/2 は 18:40〜20:30 に 5 つのエージェントが止まった。同時に動かすのは 3 つくらいまで。
- commit は日本語、末尾に Co-Authored-By（Opus なら `Claude Opus 5.5 <noreply@anthropic.com>`）。履歴を書き換えない。
- 実名・秘密・他のプロジェクトの名前をリポジトリに入れない。隣のフォルダを開かない。
- 言葉: 赤は「至急」、列は「優先」、「診断」「判定」「重症」を書かない。AI の出力には AI の印。最後に判断するのは人。
