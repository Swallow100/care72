# 審査基準と作品の対応（11/3 作成、11/4 朝に今の中身へ更新、提出まで更新）

審査基準の 4 つ（インパクト 30・デモ 25・Claude の活用 25・深さと実行力 20）を、作品のどこで満たすか・何が足りないかで並べる。満点を取るつもりで、足りない物は作業（docs/tasks）に落とす。「どこで」は 作品（動く物）・README・動画・提出書類 の 4 つ。本番は https://care72.app（`ee1dca9`、11/4 05:2x の配信）。

## 審査員の手順と、見られる所

審査員は提出書類の ID とパスワードでログインし、役を選び、見本の 10 人（デモ事業所。全員架空）で回す。手順の全文は README の「触り方」。下の表は、各手順で見られる物と、効く審査基準。

| 手順 | 見られる物 | 効く基準 |
| --- | --- | --- |
| ログイン → 役（ケアマネ・医療班・本人スマホ・家族スマホ） | 1 つのアカウントで 4 つの立場を行き来する。どの画面もログインが要る | デモ |
| ケアマネ → 平時の担当一覧 | デモ事業所は平時で始まる。計画の状態・医療の印、右の面に今週の見直しと未確認の多い人 | デモ・インパクト |
| 事業所 →「発災開始」 | 今の種の大雨の想定（警戒レベル 4・浸水 3 m の町で停電）と山田の赤が入り、同じ担当一覧が色と連絡順に並び替わる（先頭は至急の山田）。3 つのアカウントで共有、「平時」で戻る | デモ・Claude の活用（使う所と使わない所） |
| ケアマネ → 訓練 → 大雨想定 → 自動進行 | 10 人の本人役（Haiku）が赤緑を押し電話をかけ、監督（Opus）が出来事を差し込む。72 時間を次までで進め、自動進行は次までの繰り返し。上の棒に起きた事が種類の段で並ぶ。終わると機械の数と講評（Opus 1 回） | デモ・Claude の活用 |
| 訓練の「設定」 | 参加者・職員の数・夜間発災、AI の呼び出しの見込みと残り。手のメモ（AI に渡さない）と最後の 1 手の取消 | 深さと実行力 |
| 本人スマホ → 赤 → 1 画面 1 問 | AI の告知（声と文字）、119 の固定の 1 行、選択肢の灰の枠と左の帯（赤は表が至急にする答えだけ）、危ない答えのあとは録音へ、避難所と位置 | インパクト・デモ・深さ |
| ケアマネ → 担当一覧 | 色と連絡順の並び替えと理由の 1 行（ルールの表）。行の詳細に分類（AI）と録音のまとめ（AI の印、本人の言葉と並べる、直せる） | Claude の活用（使う所と使わない所） |
| 本人のページ → スマホ入口 → 別の端末で開く | ログインなしで本人の画面が開き、押した赤が担当一覧に入る。ログイン中の端末では黙って替えない | インパクト（ハッカソン後も使う形）・深さ |
| 担当一覧の「通話」 | 電話で聞いた安否がケアマネの入力として表に入る。本人の答えでけがのある人への「無事」は「無事 不可（本人が「けが」）」で断る。経過から撤回 | 深さ（人が最後に決める） |
| 絞込・検索・並びの向き、CSV出力・一括印刷 | 画面と同じ行と順で書き出す | 深さ |
| 事業所 → 担当の一括変更・アカウント・地域 | 見本のケアマネは山本 1 人で、審査員は管理者でないので見るだけ（山本と審査員のアカウントはサーバーが変更を断る） | 深さ（見られる範囲は狭い） |
| 事業所 → 気象庁の欄 | 本物の警報・注意報・地震を電文の名前と時刻のまま。災害モードは自動で切り替えず「切替」を勧めるだけ | インパクト・深さ |
| 通信を切って開き直す | 担当一覧・本人のページ・本人の 1 枚・本人のスマホの最後の写しと時刻、通話の記録の「保留 N」 | 深さ（災害の現場の条件） |
| 医療班 → 受入一覧 | QR・検索で受け入れ、状態の切替と人数、台帳に無い人の最小の記録、CSV | インパクト・デモ |
| 本人のページ → 入れる欄・編集・書類 | 文や写真を AI が台帳の項目に（伏せ字 N）、手で直す欄、松山市の計画書・本人の 1 枚・医療要約・様式 9 | デモ・Claude の活用 |

## Claude の活用 25

作品の側で 3 つに分けて整理した（作品の中で使う所、開発の中心に置いた所、用途ごとの使い分け）。

| 整理 | どこで満たすか | 足りない物 → 作業 |
| --- | --- | --- |
| Claude を作品の中で使う（核の部分で何をさせ、何をさせないか） | 10 体の Haiku が別々の人生を演じ Opus が監督する訓練、Managed Agents の世界の部屋が架空の街の 72 時間を持ち続ける仮想モード、Opus の文書の目で様式を読んで対応表を作る、型で縛った仮名化の門（文の中の電話・敬称つきの名前・住所の形も伏せる）、ルールの表＋Claude は分類と写しとまとめだけ（色と順に使わない。発災時に Claude を「使わない」設計も使い分け）、文書をコードから生成しテストで一致を守る（docs/TRIAGE.md・docs/SOURCES.md） | 本番の鍵で本物の応答を確かめる（入れる欄・分類・まとめ・本人役・監督・講評・世界の部屋）。docs/CLAUDE_CODE.md の「芯」の段を実物の画面と hash で裏付ける |
| Claude Code を開発の中心に置く（それで何が可能になったか） | docs/CLAUDE_CODE.md（分担、1 作業 1 brief、テスト先行、2 つのアカウントの並行、11/3 夜〜11/4 朝の並列の 3 波）、docs/tasks（T00〜T74 の brief）、README の「Claude Code で何が可能になったか」、docs/HANDOFF.md（セッションをまたぐ引き継ぎ）。commit・PR・テストの数は数え直し（`62ef6ee` の値は README） | 数を提出前に取り直す（同じ数え方で、数えた commit を替える）。動画で 10 秒 |
| 用途ごとにモデルと機能（Skills・サブエージェント・MCP・フック）を選んで使い分ける | 作品の中のモデル: Opus（様式・監督・講評・世界の部屋）/ Sonnet（台帳の入力）/ Haiku（本人役・分類・録音のまとめ）。effort は分類（low、録音のあと 30 秒に収めるため）のほか high。開発は Fable（設計）/ Opus（実装）。フック（ネットに出る wrangler・秘密・履歴の書き換えを止める、型の検査）。Skill（/task・/triage-rule・/care72-review）。サブエージェント（medical-reviewer・screen-checker・persona-tester）。MCP（care72-local: 手元の D1 を仮名で読む）。Managed Agents（仮想モードの世界の部屋だけ。道具のループと記憶が要る所。落ちたらその刻みだけ 1 回呼び。デモでない事業所では結末を決めない） | 本番の鍵で部屋が作れるか・1 刻みの待ち（high で 120 秒の枠）・費用を確かめる。サブエージェントと MCP を本当に使った記録（docs/CLAUDE_CODE.md に場面と日付） |
