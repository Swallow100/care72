# ケアマネ向けアンケート（現場の声）

協力してくれるケアマネ・包括支援センターの人（数人〜10 人）に、個別避難計画を作る負担と、計画の使われ方を聞く。誰が、どんな場面で、どれくらい困っているかを、現場の数と言葉で示す（docs/tasks/T34.md・T42.md・T65.md、README の「課題」）。結果は動画の最後の数字（docs/video/SCRIPT.md の N29）と、README の「現場の声」に使う。

| 物 | 場所 |
| --- | --- |
| 質問（9 問と属性 2 つ、ご意見、引用の確認 1 つ） | [QUESTIONS.md](QUESTIONS.md)（正は tools/survey/questions.ts） |
| 答えの頁（ログインなし、共有のリンク 1 本） | /survey/<token>（app/survey、lib/survey） |
| 答えの全部の写し（1 行 1 人、匿名。文の列も） | `answers.local.md`（手元だけ。.gitignore にあり commit しない） |
| 公開してよい写し（文の列を空にした物） | [answers.md](answers.md)（tools/survey/strip-answers.ts が作る） |
| 集計と、AI で分けた自由記述 | `summary.md`（tools/survey/summarize.ts が作る） |
| 紙（使わない。Web 版に移した） | [paper.html](paper.html) |

## 1　共有のリンクを作って配る（T65）

1. 山本（ケアマネの役）でログインし、事業所の画面（/office）の「アンケート」で「共有リンク作成」を押す。控えは配る先の呼び名（例 包括配布。本名を書かない）。
2. 出た URL の「コピー」と「QR保存」（PNG、白地に黒）。QR を Word の紙に貼って刷る。全員に同じ QR を配る。
3. 受付は **11 月 5 日（木）23:59 JST** まで、1 本のリンクで **30 件**まで（lib/survey/share.ts の定数）。過ぎると頁は「受付終了」、送信は断られる。
4. 同じ端末で 2 回は答えられない（送れたら端末に印。同じ端末で開くと「回答済」）。同じ職場の Wi-Fi で何人も答えるので、IP ごとの件数の上限は付けていない（送信元ごとに 1 時間 20 回のボットの守りだけ）。
5. 審査員が作ったリンクと答えは本物と分けて見え（審査員には審査員の物だけ）、毎朝 4 時に消える。

3 人以上の回答が集まれば、動画と README に使える。3 人に満たなければ使わない（集計も 3 人未満はそう書く）。

## 2　答えを写す

/office の「全員写し」（または 1 人分の「写し」）を、手元の `docs/survey/answers.local.md` の表の下に貼る（初めは `answers.md` を写して作る。このファイルは .gitignore にあり、commit しない。リポジトリは公開なので、文の列〔記入欄とその他の記入〕の入った写しを載せない）。番号は W001・W002…（送った順。審査員の試しは T001… で、全員写しには入らない）。答えの元（D1 の survey_responses の行）は **11 月末までに消す**（案内の文で約束した）。

### 表の列

`番号 | 役 | 役その他 | 経験 | 問1 | 問2 | 問3 | 問3その他 | 問4 | 問4その他 | 問5 | 問6 | 問6その他 | 問7 | 問8 | 問9 | 問9理由 | ご意見 | 引用`（見出しの行は answers.md にある。列の名前が同じなら並びは問わない）。

- 番号: W001… の通し番号。名前ではない。同じ番号を 2 度使わない。
- 選択の列: 並びの上から順に記号を付ける。いくつでも選べる問 4・問 6 だけ、`b,c,f` のように並べる（区切りは `,` `、` `・` 空白、なしでもよい）。
- 答えなしは空か `-`。
- 文の列（問5・問9理由・ご意見と、その他の記入）: 文をそのまま。`|` を入れない（写しは `、` に替えてある）。
- 引用: 空は「よくない」と同じに扱う。

| --- | --- |
| 役 | a ケアマネ　b 保健師・看護師　c 社会福祉士　d その他 |

例（作り物。answers.md には入れない）:

```
| W001 | a |  | c | b | d | b |  | b,c,f |  | 書く時間が取れない | a,b |  | c | b | a | 話すだけなら続けられる |  | a |
```

### 写す前に確かめる

- 名前・事業所名・利用者のこと（年齢や地区で人が分かる書き方も）・電話・メールが書いてあれば、その部分は写さない。伏せるなら「〇〇」にする。
- 引用が「よくない」か空の人は、文の列（記入欄もその他の記入も）を**写さない**（空にする。/office の写しは初めから空）。選択の問いは写してよい。この人の文は集計にも使わない。
- summarize.ts も見張る（名前らしい「〇〇さん」、電話・メール・リンクの並び、引用が「よい」でないのに写した文）。見つかった答えは AI に渡さず、`summary.md` の「要確認」に出る。見張りは読み落とすので、作者の確かめの代わりにはならない。

## 3　集計する

```
node tools/survey/summarize.ts --no-ai
node --env-file=.dev.vars tools/survey/summarize.ts
node tools/survey/strip-answers.ts
```

1. 先に `--no-ai`（鍵を使わない）。表が読めるか、要確認が無いかを見る。読めない所は行ごとに出るので、answers.local.md を直して流し直す。
2. 鍵は環境変数 `ANTHROPIC_API_KEY` で渡す（手元の `.dev.vars` に入っていれば、2 行目のように `--env-file` で読ませる。鍵をコマンドやチャットに書かない）。鍵が無いときは、AI の所だけ飛ばして数えた所を書く。
3. 結果は `docs/survey/summary.md`。数えた所は機械で、自由記述の型と引用候補は Claude（Sonnet）が分けた物で、「AI」の印が付く。AI に渡すのは自由記述の文だけ（番号と文。名前・事業所名は無い前提）。
4. 問 5 と問 9 の理由は 7 つの型（時間・様式・聞き取り・支援者・市町村・使われない・その他）の 1 つに分けられ、1 つの答えは 1 つの型に数える。引用候補は原文から 1 文をそのまま抜いた物で、固有名詞は「〇〇」に伏せられている。原文と合わない候補は自動で捨てられる。ご意見とその他の記入は AI に渡さず、引用が「よい」の人の物だけ原文を並べる。
5. AI の分けは間違う。**answers.local.md の原文と見比べて、採るかどうかを作者が決める。**
6. 良ければ `node tools/survey/strip-answers.ts` で、answers.local.md から文の列（役その他・問3その他・問4その他・問5・問6その他・問9理由・ご意見）を空にした写しを `answers.md` に作る。commit するのは、この `answers.md` と `summary.md` だけ。`answers.local.md` は commit しない（`git status` に出ないことを確かめる）。summary.md に載る文は、引用が「よい」の人の物だけ（候補は固有名詞を伏せた 1 文）。載せたくない文があれば summary.md から消してから commit する。

## 4　動画と README に出す

- 数字は「N 人中 M 人」。N はその問いに答えた人で、summary.md の表の形のまま使う。母数が小さいことを隠さない。割合（%）は主にしない。
- 取った所を添える: 「協力してくれた事業所のケアマネ・職員 N 人のアンケート」。全体を代表しないので、「現場の多くが」とは言わない。
- 動画: S8 の 2 つ目の数字と N29 の 1 文（docs/video/SCRIPT.md）。例（数は作り物）: 「個別避難計画の作成で『書く時間が無い』を挙げたのは、5 人中 4 人」。文字で出す。顔・声は出さない。
- README: 「現場の声」に 1 段。数字の表（問・N 人中 M 人）と、引用 1〜2 文。
- 引用: summary.md の候補から作者が採る。匿名で 1〜2 文。固有名詞を伏せる。使えるのは、最後の問い「引用」が「よい」の人の文だけ（そこで本人の了承を取ってある）。
- 問 2 は時間の幅の答え。動画の N28 の「ふだん［X 時間］」は協力ケアマネ本人の申告を使い、問 2 は別に「M 人中 N 人が 1 時間より長い」と出す（summary.md の合算の行。母数は、作ったことがある人）。
- 問 7 は「すぐ伝えられるか」の自己評価で、避難所の医療班の手元に情報がある割合を測った物ではない。「M 人中 N 人が『伝えられない』と答えた」と書く。SCRIPT の「医療班の手元の割合」にはしない。
- 言葉は CLAUDE.md の「守ること」のとおり。ケア72 の効果を言い切らない（問 9 は「作る気になるか」の答えで、使った結果ではない）。

## 5　守ること

- 名前・事業所名・利用者のことを集めない・書かない。回答の原本と、文の列の入った写し（answers.local.md）はリポジトリに入れない。commit する answers.md は文の列が空の物だけ（`npm test` が見る）。
- 引用に使うのは、最後の問いで了承を取った人の文だけ。
- 一人ひとりの元の答え（D1 の survey_responses）は 11 月末までに消す（案内の文の約束）。
- 質問や選択肢を変えるときは QUESTIONS.md・この表・answers.md の見出し・tools/survey/questions.ts を一緒に直す（`npm test` が言葉の一致を確かめる）。
