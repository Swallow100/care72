# ケアマネ向けアンケート（現場の声）

協力してくれる事業所のケアマネ・職員に、個別避難計画を作る負担を聞く。誰が、どんな場面で、どれくらい困っているかを、現場の数と言葉で示す（docs/tasks/T34.md、docs/JUDGING.md のインパクト）。結果は動画の最後の数字（docs/video/SCRIPT.md の N29）と、README の「現場の声」に使う。

| 物 | 場所 |
| --- | --- |
| 質問（7 問と属性 2 つ、引用の確認 1 つ） | [QUESTIONS.md](QUESTIONS.md) |
| 印刷する紙（A4 縦 1 枚） | [paper.html](paper.html) |
| 紙の答えの写し（1 行 1 人、匿名） | [answers.md](answers.md) |
| 集計と、AI で分けた自由記述 | `summary.md`（tools/survey/summarize.ts が作る） |

## 1　紙を作って渡す

1. Chrome か Edge で `docs/survey/paper.html` を開き、印刷する。用紙は A4・縦、倍率 100%、「ヘッダーとフッター」は外す（ページの余白は紙面の側で取ってあり、1 枚に収まる）。
2. 協力してくれる事業所のケアマネ・職員に渡す。言うのは「名前を書かずに 5 分で答えてください。結果は匿名で、作品の説明と動画に使います」だけ。
3. 回収は封筒か回収箱で。名前を書かせない。答えた人が分かる回収のしかた（その場で目の前で読む、など）にしない。
4. Google フォームで取るときも、項目と選択肢の並びは QUESTIONS.md のとおり。フォームのリンクはリポジトリに入れない。回答者のメールアドレスは集めない設定にし、回答のスプレッドシートはリポジトリに入れない。

3 人以上の回答が集まれば、動画と README に使える。3 人に満たなければ使わない（集計も 3 人未満はそう書く）。

## 2　答えを写す

紙を見ながら、`answers.md` の表に 1 行 1 人で写す。**紙の原本・写真・スキャンはリポジトリに入れない**（写しだけ）。原本は作者の手元に置き、写し終えたら事業所の決まりに従って片付ける。

### 表の列

`番号 | 役 | 経験 | 問1 | 問2 | 問3 | 問4 | 問5 | 問6 | 問7 | 問7理由 | 引用`（見出しの行は answers.md にある。列の名前が同じなら並びは問わない）。

- 番号: 回収した順の通し番号（001・002…）。名前ではない。同じ番号を 2 度使わない。
- 選択の列: 紙の並びの上から・左から、順に記号を付ける。いくつでも選べる問 3 だけ、`b,c,f` のように並べる（区切りは `,` `、` `・` 空白、なしでもよい）。
- 答えなしは空か `-`。
- 問 4・問 7 の理由: 紙の文をそのまま写す。`|` を入れない（`、` などに替える）。
- 引用: 紙の「引用」。空は「よくない」と同じに扱う。

| 列 | 記号と選択肢 |
| --- | --- |
| 役 | a ケアマネ　b その他の職員 |
| 経験 | a 5 年未満　b 5〜10 年　c 10 年以上 |
| 問1 | a できている人はいない　b 1〜3 割　c 4〜6 割　d 7 割以上 |
| 問2 | a 30 分以内　b 30 分〜1 時間　c 1 時間〜半日　d 半日より長い　e 作ったことがない |
| 問3 | a 様式が分かりにくい　b 書く時間が無い　c 本人や家族に聞きにくい　d 支援者が決まらない　e 市町村とのやり取り　f 作っても使われない　g その他 |
| 問4 | 文（問 4 の記入欄） |
| 問5 | a 渡せる　b 一部は渡せる　c 渡せない |
| 問6 | a 決まっている　b だいたい決まっている　c 決まっていない |
| 問7 | a なる　b 少しなる　c ならない |
| 問7理由 | 文（問 7 の理由の記入欄） |
| 引用 | a よい　b よくない |

例（作り物。answers.md には入れない）:

```
| 001 | a | c | b | d | b,c,f | 書く時間が取れない | c | b | a | 話すだけなら続けられる | a |
```

### 写す前に確かめる

- 名前・事業所名・利用者のこと（年齢や地区で人が分かる書き方も）・電話・メールが書いてあれば、その部分は写さない。伏せるなら「〇〇」にする。
- 紙で引用が「よくない」か空の人は、問 4・問 7 の理由の文を**写さない**（空にする）。選択の問いは写してよい。この人の文は集計にも使わない。
- summarize.ts も見張る（名前らしい「〇〇さん」、電話・メール・リンクの並び、引用が「よい」でないのに写した文）。見つかった答えは AI に渡さず、`summary.md` の「要確認」に出る。見張りは読み落とすので、作者の確かめの代わりにはならない。

## 3　集計する

```
node tools/survey/summarize.ts --no-ai
node --env-file=.dev.vars tools/survey/summarize.ts
```

1. 先に `--no-ai`（鍵を使わない）。表が読めるか、要確認が無いかを見る。読めない所は行ごとに出るので、answers.md を直して流し直す。
2. 鍵は環境変数 `ANTHROPIC_API_KEY` で渡す（手元の `.dev.vars` に入っていれば、2 行目のように `--env-file` で読ませる。鍵をコマンドやチャットに書かない）。鍵が無いときは、AI の所だけ飛ばして数えた所を書く。
3. 結果は `docs/survey/summary.md`。数えた所は機械で、自由記述の型と引用候補は Claude（Sonnet）が分けた物で、「AI」の印が付く。AI に渡すのは自由記述の文だけ（番号と文。名前・事業所名は無い前提）。
4. 自由記述は 7 つの型（時間・様式・聞き取り・支援者・市町村・使われない・その他）の 1 つに分けられ、1 つの答えは 1 つの型に数える。引用候補は原文から 1 文をそのまま抜いた物で、固有名詞は「〇〇」に伏せられている。原文と合わない候補は自動で捨てられる。
5. AI の分けは間違う。**answers.md の原文と見比べて、採るかどうかを作者が決める。**
6. 良ければ `answers.md` と `summary.md` を commit する。

## 4　動画と README に出す

- 数字は「N 人中 M 人」。N はその問いに答えた人で、summary.md の表の形のまま使う。母数が小さいことを隠さない。割合（%）は主にしない。
- 取った所を添える: 「協力してくれた事業所のケアマネ・職員 N 人のアンケート」。全体を代表しないので、「現場の多くが」とは言わない。
- 動画: S8 の 2 つ目の数字と N29 の 1 文（docs/video/SCRIPT.md）。例（数は作り物）: 「個別避難計画の作成で『書く時間が無い』を挙げたのは、5 人中 4 人」。文字で出す。顔・声は出さない。
- README: 「現場の声」に 1 段。数字の表（問・N 人中 M 人）と、引用 1〜2 文。
- 引用: summary.md の候補から作者が採る。匿名で 1〜2 文。固有名詞を伏せる。使えるのは、紙の「引用」が「よい」の人の文だけ（紙で本人の了承を取ってある）。
- 問 2 は時間の幅の答え。動画の N28 の「ふだん［X 時間］」は協力ケアマネ本人の申告を使い、問 2 は別に「M 人中 N 人が 1 時間より長い」と出す（summary.md の合算の行。母数は、作ったことがある人）。
- 問 5 は「すぐ渡せるか」の自己評価で、避難所の医療班の手元に情報がある割合を測った物ではない。「M 人中 N 人が『渡せない』と答えた」と書く。SCRIPT の「医療班の手元の割合」にはしない。
- 言葉は CLAUDE.md の「守ること」のとおり。ケア72 の効果を言い切らない（問 7 は「作る気になるか」の答えで、使った結果ではない）。

## 5　守ること

- 名前・事業所名・利用者のことを集めない・書かない。回答の原本はリポジトリに入れない。
- 引用に使うのは、紙で了承を取った人の文だけ。
- 訓練のことは聞かない（T34 の決め、11/3）。
- 質問や選択肢を変えるときは QUESTIONS.md・paper.html・この表・tools/survey/questions.ts を一緒に直す（`npm test` が言葉の一致を確かめる）。
