## Claude を使う所と使わない所

- 使う: 録音の文字起こしから聞き取りメモの欄に本人の言葉を写すだけ（分類と同じ Haiku の 1 回。仮名化の門 askJson を通る）
- 使わない: 問いの枝・声の答え（言葉の一致）・色と連絡の順・119 の 1 行

## いちばん大事な線（型とテスト）

- 聞き取りの答えもメモも、色・連絡の順・119 に渡さない。ルールの表の入力（`TriageSignal`・`SignalForTriage`）に answers・ai_memo・memo が無いことを型で（`lib/signals/questions.test.ts`）
- からだの訴え（息が くるしい・胸が いたい）の答えと Claude のメモ・直しを足しても、10 人とも色・行・組・理由・足す言葉が同じ（表の入力）。D1 を通して担当一覧の色・行・理由・並びも同じ（`lib/signals/hearing.test.ts`）
- 119 の 1 行は、どの問いの画面（声の問い・からだの訴えを押したあとも）に同じ文が 1 つ（`lib/signals/view.test.ts`・`family.test.ts`）
- 問い・選択肢・欄の言葉に「緊急度」「重症」「判定」「診断」「点数」「重さ」が無い。点数・重さを聞く問いは無い
- ルールの表が読むのは今の 4 問の列だけで、answers からの写しは `legacyColumnsOf` の 1 か所（はい・いいえだけ、わからない は null）

## 変えた API

## 決めた所

（タスクの文と違う 3 つは docs/DECISIONS.md「本人・家族のスマホと聞き取り」にも書いた）

- 声の問いで言葉が一致しなかったときは「わからない」を入れず、答えなしで次へ（本人が言っていない「わからない」をケアマネの画面に出さない）。本人が「わからない」と言えば わからない
- 声の問いは端末の読み上げ（speechSynthesis）で読む。Gemini TTS は今の定型文の 1 文だけ（問いごとの声を作ると R2 と上限の回数が増える）。読み上げの無い端末は声の問いを出さず、今まで通り 20 秒で定型文へ
- 声の問いの途中で押したら押した答えが先（文字を待つ間・マイクを待つ間に押しても、声の答えで上書きしない・古い問いを読み直さない。テストあり）
- 声の問いに入ったら終わりまで声で進む（押せばその答えも取る）。頼みごとは声の問いでは聞かず、そのまま定型文と録音へ
- 声の問いで聞き取れた文字（「はい」「うごけない」など）も録音の文字起こしに足す（本人の言葉。聞き取りメモの元）
- 「わからない」だけの欄は Claude の写しで埋める（事実が入っていない欄なので）。それ以外の押した答えがある欄は Claude の写しを出さない（ai_memo には残す）
- 家族の答えも今の 4 問の列に書く（ルールの表がもともと「本人・家族の 4 問の答え」で red_injury に当てる。AI の分類は色と組を動かさない、と同じ読み方。docs/DECISIONS.md「色と連絡順」）
- 家族には 連絡手段・頼みごと を聞かない（家族のスマホの話・録音は本人だけ）
- からだの訴えは 1 つだけ選ぶ（1 画面 1 問・押すたびに次へ。いくつもある人は録音で）
