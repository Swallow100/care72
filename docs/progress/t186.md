## 1. 今の決め方（調べた結果）

- 参加者の元は担当一覧の人（lib/drill/db.ts の caseloadRows: `people` の `care_manager_id`＝自分・`office_id`＝自分の事業所・一覧から外していない人、よみの順）。
- 開始の画面（app/drill/page.tsx → components/drill/StartButtons.tsx）は T59 から、畳んだ「設定」の中に参加者のチェックがある。既定は全員で、全員のままなら participants を送らない。
- サーバー（lib/drill/http.ts の parseStartOptions → lib/drill/db.ts の startDrill → pickParticipants）は、送られた id が担当一覧の中か・重なりが無いか・0 人でないかを見る。送られなければ担当一覧の全員。
- 人数の上限は無かった（parseStartOptions の id の数の上限 200 は形の守りで、人数の決まりではない）。
- 事業所（壁）の中かは caseloadRows の絞り（事業所と担当のケアマネ）で既に見ている。新規事業所（審査員の試用事業所）も drillScope → 同じ道。
- 参加者の数に頼る所（仮想の世界の部屋 lib/drill/world-room.ts の buildCast、本人役、見込み lib/drill/estimate.ts、一覧の listDrills の json_each($.participants)、採点 lib/drill/record.ts の computeScore、講評）は、どれも drills.world の participants（開始の時に選んだ人）を読む。担当一覧を読み直す所は無い。
