## 決めた所（docs/DECISIONS.md）

- 担当一覧の写しは ?open=<id> ごと、全部で 60。写しの無い URL は写しの URL へ 302
- 画面の中の移りは画面からの知らせで写す（頁を移るたびにサーバーの描きが 1 回増える。同じ URL は 60 秒に 1 回）
- 写しの時刻は head の meta
- 役の切替・スマホ入口のリンクでも写しを消す。要求を見た時点で消す（スマホ入口の GET はネットが応えたとき）
- 持ち主は layout が渡し、送り直しは頁に 1 つ。帯にも保留。4 秒で欄を閉じる
- AutoRefresh は通信なしの間は止める

## 問い（設計の側へ）→ 11/4 04:2x に答え（docs/DECISIONS.md、下の「続き」）

1. ログアウトでも端末に貯めた通話の記録は消していない（届いていない事実を捨てない。別の人がログインしても送らない・数えない）。共用の端末ではメモ（100 字）が端末に残る。ログアウトで消す・ログアウトの前に「保留 N」を出して止める、のどちらかにするか
2. 送り直しで届いた記録の経過の時刻は、サーバーが受けた時刻（app/api/caseload/call の now）。押した時刻は端末の貯めに at として持っているが送っていない（API は知らない欄を読まないので送っても害は無い）。API で受けて経過の時刻にするか（「最終連絡」と 連絡なしの時間 が押した時刻になる）
3. 届いたのに応答が失われた（電話の画面へ移って頁が落ちた・15 秒で切った）記録は、次に送り直して経過が 2 行になることがある。API に送る側の id（重ねない鍵）を受けるか
4. 頁の network-first に時間切れを足すか（例 8 秒で写しを出し、裏でネットを待つ）。発災の詰まった通信では効くが、遅いサーバーのときにネットがあっても写しが出る

## 続き（問いの答え、11/4 04:2x〜。2685337 の上）

1. ログアウトの前の保留（components/LogoutButton.tsx、AppHeader はボタンを差し替えただけ）: 保留があればアプリ内の窓（appChoice）に「保留 N」、「送信待ち」（時計のアイコン。ログアウトせず、その場で送り直す）・「破棄」（赤。自分の残りを消してからログアウト）・取消。保留が無ければ今のまま送る。CallQueue に flush・discard を足した（queue.ts の discard は持ち主の物だけ消す）
2. 押した時刻: 端末の貯めの at を送り、lib/list/calls.ts の callOccurredAt が経過と信号の時刻にする（未来・発災より前・24 時間より古い・読めない物は受けた時刻）。発災は事業所の disaster_state.started_at。受けた時刻は payload の receivedAt（毎回）、端末の id は clientId。行の詳細の電話・最終連絡は押した時刻で出る
3. 重ならない id: 端末の id（crypto.randomUUID、形は [A-Za-z0-9-]{8,40}）を API（lib/list/http.ts の callPost の id）が受け、経過の行を call-<id>、信号を call-<id>-s にする。先に同じ id を引いて有れば書かずに { ok: true, duplicate: true }（前に届いた物を今の表で断り直さない）。同時の 2 つは INSERT OR IGNORE と主キーで 1 行、遅れた方は duplicate。id も at も無い記録（ケアマネの役でないときの前の道）は今までどおり。migration なし
4. 頁の時間切れ（public/sw.js の page、sw-core.js の NETWORK_WAIT_MS 4 秒）: ネットが 4 秒応えなければ写しを返し、遅れて来た応答は裏で写す（画面は写しのまま、帯の「読み直す」で新しい物）。写しが無ければ待ち続ける
