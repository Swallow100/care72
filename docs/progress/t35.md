## 画面の決まり（実画面を見て決めた。CLAUDE.md への追記は設計の側）

1. PC の画面を横に送らない。表が収まらなければ字を小さく・列を詰めて縦だけで収める（1280px と 1440px で横送りなし。1024px は列の省略で）
2. 黒を混ぜた色（暗く濁った緑・赤・黄・青）を使わない。黒を混ぜてよいのは灰色と黒だけ。意味色はライトもダークも澄んだ色相のまま、ダークは明度を保ち、下地の面を暗くして差を出す
3. 印刷を簡単に: 紙面の画面に「印刷」を 1 つ（window.print）。本人のページの書類の行からも 1 押しで印刷
4. 「役変更」が反応しにくい件を直す。押したらすぐ役の一覧が開く形に。ヘッダーのほかのボタンも同じ基準
5. 手本の決まり: 地・面・面の中の 3 段、枠線は選択・注意・危険だけ、選んだ印は下地でなく枠・文字色・下線・灰色、2〜4 字の漢語、常設の説明文なし、戻るは左上に 1 つ、押したら灰色だけ、カードの下の縁や透ける濃淡なし、文字色はボタン以外では本文色と薄い本文色の 2 つ（テーマ色の文字を飾りに使わない）、意味色は CSS 変数、数字は等幅、幅は 1024px 以上で 768〜880px の本文の列・700〜1023px は 720px。これを components/ui の部品に
6. 画面の中のスクロールの箱をやめる。送るのは画面全体の縦 1 本だけ（要る見出し・操作は sticky）。例外は紙面の印刷プレビューと本当に長い表
7. ヘッダー: 左に切替（担当一覧・訓練・事業所・様式）、右に 事業所名 → 今の役 → 役変更（人のアイコン＋文字、押すと下に一覧、選ぶとすぐ切替、外を押すと閉じる）→ ログアウト
8. ログアウトは赤（出る・消す・外すは赤）と扉のアイコン。主の操作（保存・分ける・印刷・追加）は操作の色、それ以外は無色。アイコンは Heroicons（MIT）を文字と並べる（アイコンだけのボタンにしない。ISC の Lucide などは使わない）。印刷はプリンター、利用者追加・ケアマネ追加は人＋
9. 利用者追加とケアマネ追加・担当の割当は場所と見た目を揃え、押したら何が起きるか分かる形に
10. 分担: 紙面の見た目と印刷用 CSS は T36。T35 は印刷のボタン（画面側）と書類の行の印刷まで。components/forms/ の紙面の部品は変えない

## 書体

3 候補を、担当一覧（発災時）と本人のページに Google Fonts から当てて 1280px のライトで撮り（`fonts/`）、数字の幅を測った（`fonts/metrics.txt`、32px の「0000」と「1111」の幅、tabular-nums あり・なし）。

| 書体 | 数字（tnum あり） | 数字（なし） | 12〜13px | 漢字とかな | 既定の見た目から |
| --- | --- | --- | --- | --- | --- |
| IBM Plex Sans JP（前） | 80.6 / 80.6 | 80.6 / 80.6 | 読める | かなが細め | IBM の業務画面の顔 |
| **M PLUS 2** | **81 / 81** | **81 / 81** | 潰れない | 釣り合う | 離れる（丸みのある骨格、角の切り方） |
| Zen Kaku Gothic New | 64.5 / 49 | 64.5 / 49 | カタカナが細い | 400 が細く、かなの字間が広い | 離れる |
| LINE Seed JP | 92.8 / 59.7 | 92.8 / 59.7 | 太めで読める | かなが丸く強い | LINE の顔に寄る |

選んだ: **M PLUS 2**（OFL-1.1、next/font/google）。数字がもともと等幅で tabular-nums が要らず、表の時刻・残り・人数の縦が揃う。可変の太さで題・本文・小さな字を太さでも分けられる。漢字とかなの太さの釣り合いがよく、12〜13px の「要介護3」「人工呼吸器 内蔵電池」も潰れない。Zen Kaku Gothic New と LINE Seed JP は Google Fonts の配布で tabular-nums が効かず（数字の幅が揃わない）、表の縦がずれる（使うなら数字だけ別の書体を先に重ねる手間が要る）。LINE Seed JP は Google Fonts にあったので self-host は要らなかった。
本人・家族のスマホと本人の 1 枚は BIZ UDPGothic のまま。3 候補はどれも UD の書体でなく、大きな字とふりがなで読み違えにくい作りは BIZ UDPGothic の方が勝る。

## unslop の観点

`theclaymethod/unslop` と `woerndl/unsloppify` を読んだ。どちらも MIT（README の License の節と LICENSE）。どちらも文章の AI 臭さを取る skill で、画面の見た目の物ではない。本文はリポジトリに写さず、観点だけを自分の言葉で書き、画面の言葉と画面の形に当てた。画面の言葉は CLAUDE.md の決まり（2〜4 字の漢語、説明文なし、「札」と書かない）を先にする。

| 観点 | 画面の言葉に当てると | 見つけた物 |
| --- | --- | --- |
| 大げさな重みづけ | 「重要」「必ず」「すべて」を足していないか | なし |
| 作った劇 | 対比・自問・あおりの言い方 | なし |
| 見せる語彙 | 平らな言葉で足りるのに横文字・業界語 | なし（「様式対応」は決めた言葉） |
| 偽の正確さ | 出典の無い数字・言い切り | なし（根拠は出典の登録簿から） |
| 型の埋め | 決まった前置き・締め、見出しが中身を繰り返す | なし |
| 作業の跡 | 作りの言葉や会話の調子が画面に残る | 下の問い 4 の 3 つ |
| 均一なリズム | 同じ長さ・同じ形の繰り返し | 言葉にはなし。画面の形（同じ白い角丸のカードの並び）に当たり、棚卸しの 1・2 で直した |
