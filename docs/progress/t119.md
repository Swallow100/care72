# T119 市町村の様式の Excel・Word をそのまま取り込む（Opus）

T119 済み（Claude Opus 5.5、11/5 05:32〜06:4x）。worktree care72-t119、branch task/t119（origin/integrate/t11-t12 の 4b920bc から。途中で T107 の入った integrate を取り込んだ）。

Claude を使う所・使わない所: 新しく呼ぶ所は無い。Excel・Word はブラウザの中で頁の画像に描くだけで、Claude に渡すのは今までどおり黒塗りの画面を通した頁の画像（様式の読取の Opus 1 回）。

## 選んだ道と理由

ブラウザで描く（lib/ooxml）。Excel・Word を zip から開き、シートと文書の XML を読んで印刷の頁（mm の線・矩形・字）にし、canvas で頁の画像（長い辺 2000px の PNG）にする。あとは PDF の頁と同じ道（黒塗り → 読取 → 重ねる紙）。

- Workers の上では LibreOffice などの変換は動かない。外の変換の仕組みに送ると、記入例のシートの値が黒塗りの前に外へ出る。ブラウザで描けば今の門（黒塗り・仮名化）を迂回しない
- 既にある部品で足りる: zip は Web 標準の DecompressionStream、XML は fast-xml-parser（MIT、lib/jma で使っている）。依存を足していない
- 見送った部品: SheetJS の公開版（罫線などの書式を読まない、npm の版に既知の脆弱性）、ExcelJS（ISC の依存 saxes、印刷の頁を作らない）、docx-preview（HTML にするだけで頁に分けない）、mammoth（BSD-2、表の枠を持たない）

- 同じ様式の PDF と比べられた物（吹田・熊本・時津・浦安）は、罫線の中央値 0.1〜0.4mm、2mm 内 66〜100%。横の位置（列・表の格子）はほぼ合い、ずれは縦（行の高さ・段落の高さ）に出る
- 頁の数は、比べた 10 の様式のうち 7 で PDF と同じ。違うのは、PDF に無いシート（吹田）、記入例の PDF（徳島・永平寺。永平寺は表の食み出しで 1 頁多い）
- Excel の印刷は保存した端末とプリンターで変わる。列幅は「文字数 × 数字の幅」が時津・吹田・松本の PDF に合い（画面の画素の式は 2〜8% ずれた）、熊本は画面の画素の式の方が 0.5% 近かった。合わせる印刷の倍率は、保存した倍率（scale）を使うと熊本・西宮で悪くなったので、計算した倍率にした
- 古い形（福山市の .doc 2 つ、那覇市の .doc）は読まずに断る（「旧形式・PDF 保存で取込」）。どの市も PDF 版を配っている
- 双子の無い様式（札幌の Excel・Word、今治の Excel、名古屋の Word 7 つ）は描いて目で見た。罫線・結合・チェックボックス・図形の線・縦書きは出る

## 限界（近づけきれない所）

- Excel の印刷の寸法は Excel の版・保存した端末の画面の倍率・プリンターで変わる。列幅の式と自動の行の高さは双子の PDF から決めた値で、ずれは上の表の 0.1〜1mm（頁の下の方で 1〜2mm）
- Word の行の高さと折り返しは端末の書体で変わる。頁の切れ目は Word が保存した切れ目で合わせるが、表の行が伸びると頁の下で食み出す（永平寺で 1 頁多い）
- 描かない物: Excel のグラフ・条件付き書式・EMF・WMF の画像・図形の細かい形（吹き出しは丸か四角、矢印は四角）、Word の段組み・脚注・ふりがなの添え（親の字だけ）・図形の回転・ワードアート、ヘッダーの中の画像以外の図形
- 3 頁の上限（PDF と同じ）。頁の多い様式（松本の医療的ケア 9 頁）は、人が 3 頁を選ぶ
- 紙（重ねる紙）は A4 に収める（T86 のまま）。A3 の様式（吹田・今治）は位置を保って A4 に縮む

## 決めた所（docs/DECISIONS.md「書類」の案（T119））

- ブラウザで描く。依存を足さない
- 列幅は「文字数 × 数字の幅」、合わせる印刷の倍率は計算した値
- Word は保存した頁の切れ目を正に（本文の高さの 4% までの食み出しは送らない）
- 4 頁以上は人が 3 頁を選ぶ。既定は記入例・記載例のシートを外した頭の 3 頁
- Excel・Word を選んだときだけ「近似描画・PDF 保存で正確」。古い形は断る
- 対応表の元の形は pdf（表を作り直さない）
