## 使い方

```
# 1. 台を回す（今までどおり）。回のフォルダに findings.json も出る
npm run eval:drill -- --runs 2 --seed 6d83d034
npm run eval:forms
npm run eval:talk

# 2. 点数の表。同じ名前（r6）の回は 1 つの列に。名前が無ければ回のフォルダの名前
npm run eval:scorecard -- --runs r6=../care72-qa/eval/drill/<回> r6=../care72-qa/eval/forms/<回> r6=../care72-qa/eval/talk/<回>
#    種（r1〜r5）だけで作り直す: npm run eval:scorecard
#    書かずに見る: --print、種を並べない: --no-seed、書く先: --out <md>

# 3. 指摘から作業の下書き（既定は出すだけ。--out で 1 原因 1 ファイルと index.md）
npm run eval:drafts -- ../care72-qa/eval/drill/<回> ../care72-qa/eval/forms/<回> --min mid --out ../care72-qa/drafts/r6
```

- 点数の表の印: 「（悪）」は前の回（その項目に数のある、左の一番近い列）より悪い向き、「（外）」はしきい値か守りの外。r2 の列は r1 と、r6 は r5 と比べる
- 下書きは番号・意図・触らない所を足して docs/tasks に置く。下書きは根拠の抜き書きを写さないが、記録の行（run-01.jsonl seq 304 など）は書くので、置く前に回の名前と行だけかを見る
- 本物の回の findings.json は回のフォルダ（care72-qa）にあり、リポジトリに入れない。リポジトリに入れるのは点数の表と、人が直した下書きだけ

## 守りの足し方

1. 下書きの「受け入れの確かめ」の ```ts の 1 件を tools/eval/guards.ts の GUARDS に写す
2. id（台-何-どうなるか、英数字と -）・since（直したあとの最初の回）・task（直した作業）・label（守る事を短く。「〜しない」の形）を書く
3. value は直したあとの回の数（漏れ・画面の禁じた中身のような 0 のはずの物は 0）。項目は点数の表の id（tools/eval/scorecard-items.ts）か `count:<原因>`
4. 次の回から、外れたら回の findings.json に `guard:<id>`（重さ「重」）が出て、点数の表の行に「（外）」が付く。点数の表に無い項目の守りは findings.json だけに出る
5. 新しい項目が要るとき（数の JSON に数があるのに項目が無い）は scorecard-items.ts に 1 行足す。記録の jsonl の側にしか無い数は、先に台の summary・result に数を足す

見本の守り drill-cut-none は、評価の 4 回目の「本人役の言葉が 60 字で文の途中で切れた」27/164 を T139 で直し、5 回目で 0/65 になった物（docs/progress/eval-r5.md）。偽の client（ノイズなし）では 0 なので外れない。

## 種（r1〜r5）の写し方

写した元は docs/progress/eval-r5.md の「r1〜r5 の要約」の 2 つの表（「訓練」「書類」）だけ。行と項目の対応は tools/eval/scorecard-seed.ts の SEED_ROWS（表の行の名前 → 項目の id）。

- r4 は主の列の「r4」を写した。訓練の「r4 着信の回」と書類の「r4 同じ紙」は写していない（r5 と同じ選び方なのは r4 着信の回・同じ紙の方なので、r4 → r5 の「（悪）」は選び方の違いを含む。紙の 3 行と入力の当たりが r5 で「（悪）」になるのはこれ）
- 割合は 0〜1 の数、秒は秒のまま。表が「a/b」なら分子・分母を持つ
- 「56〜84」のような幅と「43・0・13」のような組は、比べられる物だけ数にした（講評の待ちは最長、r5 の訓練の 2 回の組は項目と同じ平均）。ほかは表の字のまま（数にしていないので印も付かない）
- 写さなかった行: 川崎市の頁・欄・置けず、浜松市、選択肢の AI の当て（様式ごとの説明で、回をまたぐ数にならない）
- 種だけの項目（「（種だけ）」）: 着信の往復の返事の切れ・言葉の長さの最大・講評の指摘の数と待ち・つながりにくい間と不通の間・AI の照合の種類・様式の読み取りの待ち。今の台の数の JSON に無い（記録の jsonl の側にある）ので、r6 からは空になる。数の JSON に足せば続けて並ぶ

## 残り・確かめていない物

- 指摘の「初めて出た回」は findings.json のある回（r6 から）で数える。r1〜r5 の指摘（docs/progress/eval-rN-findings.md）は findings.json にしていない
- 本物の回の findings.json は作っていない（本物の API を呼ばない）。原因の分け方（例えば帳面の決まりごと・想定の決まりごと）が本物の回で細かすぎる・粗すぎるかは、次の本物の回で見て表を直す
- 書類の指摘の場所は様式の id と記録のファイル（judgements.jsonl・steps.jsonl）の stage まで。欄ごとの行の番号は持っていない（記録の側に行の番号が無い）
