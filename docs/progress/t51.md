## 決めた所

- 待ち行列の次の窓は、`<dialog>` を閉じずに中身だけ替える（閉じて開き直すと焦点と overflow が一度戻ってしまう）
- 選ぶ部品の一覧は、下に入りきらず上の方が広く、**文書の上に一覧の高さの余地があるとき**だけ上に開く（76 項目のように上にも入りきらない一覧は、上に開くとボタンに重なるので下に開き、画面全体を送る）。開いたあとは検索で縮んでも向きを変えない
- 何も決めていない `<Select>`（value も defaultValue も無い）は、OS の select と同じく 1 つ目の選べる項目を選んだことにする。name の隠しの欄は 1 つ（選べない項目が選ばれていてもその値を送る。前の OS の select は送らなかった所。サーバーは空として扱う）
- キーの焦点の枠は `focus-visible`（マウスで開いたときは出さない、キーで動かしたら出す）。Tailwind 4 の `outline-none` は線の形を none にするので、`outline-solid` も当てた
- 検索は空白・全角半角・大文字小文字を無視して比べる（画面の言葉が「1 日 1 回」のように数の前後を空けるため）
- 一覧で打った字は、検索の欄がある一覧では欄へ、無い一覧では文字で飛ぶ。日本語の入力（IME）は焦点が一覧にある間は字を送らないので、日本語で絞るときは欄を押して打つ

## 問い

1. 待ちの言葉は文のまま（11/3 設計の答え 6）にしたが、screen-checker は 2〜4 字の漢語（聴取中・読取中・作成中）を挙げた。本人のスマホに使うときは `{聞|き}いています` の書き方と「AI」の印を呼ぶ側で添える要がある（今の WAIT_LABELS.listen はふりがな無し）
2. `<dialog>` は既定で高さの上限と内側の送りを持つ。choice の 4 択と長い details を低い画面で出すと窓の中が送れる箱になる。窓は例外として認めるか、details の行数に上限を決めるか
3. `lib/ui/labels.ts` は「WAIT_LABELS に足すだけ」の指示だったが、選ぶ部品の「該当なし」「件」などを置く所が要るので SELECT_LABELS を足した。よいか
4. ログインの欄（`components/login/field.ts` の `outline-none focus-visible:outline-2 focus-visible:outline-accent`）も、Tailwind 4 では焦点の枠が出ていないはず（同じ書き方の一覧の項目で `outline-style: none` を測った）。T51 の範囲の外なので直していない。`focus-visible:outline-solid` を足すか
5. `multiple` と `data-sub` は今の画面で使う所が無い（テストだけ）。使う画面を足すか
