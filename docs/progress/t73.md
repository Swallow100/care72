## 手元での確かめ（--local と node:sqlite だけ。本番には何も打っていない）

- migrate の migrations の段を --local に置き換えた写し（scratchpad）で: 新しい番号が無いと「No migrations」、試しの番号（0098、あとで消した）だけが当たって利用者 10・足した事業所が残る、壊れた SQL の番号（0099）は終了コード 1 で「migrations 失敗 停止」
- 守り（`node tools/deploy/guard-remote.mjs --local`）: 種だけなら「本物データなし」で 0、事業所と利用者を 1 つ足すと「本物データあり 停止」で 1、ALLOW_DATA_LOSS=1 で続行
- rebuild の守り〜seed を --local に置き換えた写しで: 本物の事業所とアンケートの共有リンク・答え 1 件を入れた D1 で、守りが止めて行は全部そのまま／ALLOW_DATA_LOSS=1 で前段 → drop → migrations → 種が通り、足した事業所は消え、アンケートのリンクと答えは残る／もう一度流すと「本物データなし」で通る
- new-office: SQL を `--local --command="$(cat …)"` で入れると事業所 1・管理者 1（regular・cao・care_manager・管理者）、同じ ID の 2 つ目は UNIQUE で落ちて事業所も入らない（1 つの取引）。そのあと守りが「アカウント 1・事業所 1」で止める
- テストで: SQL を node:sqlite（0001〜0021 と種）に流し、lib/auth/principal.ts の login で入れる（care_manager・管理者・regular）。平文は SQL のファイルと標準エラーに無い、ハッシュが verifyPassword で通る
- `bash -n` で migrate-remote.sh・rebuild-remote.sh の構文
