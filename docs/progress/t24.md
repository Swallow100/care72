## 決めた所

1. 範囲の型は 1 つ（ViewScope: items・timeline・documents・recordings・writes・provision）。本人のページ・/staff の表・書類の頁・録音の API・書き足しの API・受入の記録が同じ viewScope を呼ぶ。画面だけで判定しない（/staff の表も client に渡す前に空にする）
2. 住所の「本人の同意の範囲」は医療班への提供の同意の行の consents.scope に `{"address": true}` があるとき。読めない・形の違う JSON は範囲なし。種はみな null なので、デモでは住所は出ない
3. 人の一部: 緊急連絡先は名前・続柄・電話ごと（電話をかけるため）。支援者 1・2 は役割名（続柄か種類）だけ。緊急連絡先を兼ねる支援者（種の山田の娘・隣人）は緊急連絡先の行に名前が出る。家族・民生委員・みまもり員・夜間支援・関係先の欄は出さない
4. 上の段: 医療が範囲の外なら介護度・医療の印・時計・優先の理由と骨格の段を出さず、発災時の状態の色と言葉だけ出す。避難計画と未確認の数は医療班・行政に出さない（事業所の側の物）
5. 経過: 医療が見えるときは全部（同意の行を除く）。本人確認だけのときは医療班・行政の書いた行（書き足し・受入・搬送・退所・その場の登録）と提供の行だけ。同意の行は同意の区分が範囲の外なので医療班・行政に出さない
6. その場で登録した人（origin on_site、同意の行なし）は受け持つ人が本人から聞いた物なので、医療・避難・人の一部を見せる（根拠は生命保護。別のアカウントが受け入れたときの提供の記録もこの区分）。同意なしを記録した人は本人確認だけ。医療要約は医療班への提供の同意で作る書類（T07）なので、その場で登録した人には無い
7. 書類: 医療班・行政は医療要約だけ。範囲の外の書類は壁の外と同じ 404。録音は医療班・行政・家族の範囲に無いので 404（家族は前は API で開けた。家族のスマホの画面に再生は無い）
8. 支援者（家族のスマホ）の範囲は 避難・人と経過（仕様書の画面 5「本人の経過は支援者への提供の同意の範囲で見える」）。今の家族の画面の振る舞いは変えていない
9. 書き足しはケアマネ・医療班・行政。ケアマネは診察・配薬を書かない（安否確認・搬送・到着・記録）。欄は範囲を渡した単独の本人のページだけで、担当一覧の右の面には出さない（右の面には電話・優先変更がある）。書き足しの搬送・到着は記録だけで、ケアマネの一覧の状態は変えない（状態は受け持ちの解除の搬送から。決めた所 10）
10. 搬送の状態は custody の release_kind transported から（受入の「到着」と同じ作り）。TriageArrival に transported（時刻・行き先）を足し、表の中で搬送の時刻の緑として並べる。外へ出す TriageSignal は変えない。退所は「到着」のまま
11. /staff の表の医療の列と理由は範囲で空にし、色と並びの番号は全部の台帳から出す（連絡の順は生命保護のため）
12. 提供の行の本文は「本人確認」をほかの区分があれば言わない（「医療・避難・人の一部 同意」）。本人確認だけなら「本人確認 生命保護」。閉じた時刻（closed_at）の行は作らない（搬送・退所の行がある）
13. lib/labels.ts は触らず、新しい言葉は lib/consent/labels.ts。経過の種類の言葉（安否確認・診察・配薬・搬送・到着・記録）は lib/labels.ts の TIMELINE_KIND_LABELS を読む
