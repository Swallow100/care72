   - 検索・避難所の人（lib/custody/search.ts）、避難所の一覧と人数（listShelters は受け手を取る。app/staff/page.tsx）、受入（lib/custody/store.ts の receive。検索・避難所・QR 受入が通る 1 か所）、受入一覧（lib/custody/board.ts）、本人のページ（lib/auth/scope.ts の personInScope の受け持ちの枝）
   - ほかの事業所の人は id・QR を持っていても not_found。受け持ち・提供の記録・経過は書かない
   - 毎朝 4 時の戻し（lib/seed/reset.ts の closeJudgeCustodyStatements）: 審査員と印の人の開いた受け持ち（デモの人の分は消したあと残る、ほかの事業所の人の物）を退所で閉じ、提供の記録も閉じ、本人の経過に「退所」。何度流しても 1 回
3. 審査員が足したアカウントの印（高 2。migration 0025 の accounts.judge_made）
   - 審査員（と印の人）が足すと 1。ログインの Principal に judgeMade（judge は付けない）、壁は審査員と同じ
   - 審査員（と印の人）が改名・管理者・停止・再発行できるのは印の付いた人だけ（lib/office/staff.ts の outOfReach。ほかは「固定」と同じ断り）。事業所の画面でも印の無い行には操作を出さない（app/office/page.tsx の CareManagerList）
   - 印の人を管理者にしても事業所の地域は書けない（officeActor の placeEdit）
   - 0025 は前からある審査員の追加・再発行（事業所の経過）に印を付ける。印の人は毎朝の戻しで消える（前から: デモ事業所の種に無いアカウント）
4. アンケート（高 2・中 6）
   - 作るリンク: 壁の中の人は created_role judge（lib/survey/links.ts）
   - 見え方（lib/survey/store.ts の loadSurveyOverview。見る人は walled・admin・accountId）: 壁の中は試しだけ、壁の外の管理者は全部、管理者でないケアマネは自分の本物だけ。番号は全部で数えてから絞る。印の人が前に care_manager で作った物も試し（judgeShareSql）、毎朝消す
   - 1 日の本数: 事業所ごと・JST の日ごとに 5 本（lib/survey/share.ts の SURVEY_SHARES_PER_DAY）、試しと本物は別に数える。超えたら 429「本日上限」。数えと INSERT は 1 文
   - 開いた時刻の印は 2 時間（lib/survey/token.ts の STAMP_TTL_SEC・checkStamp）。切れたら 400 stale「期限切れ 再読込」
5. 所属なしの人の引受（中 3。lib/custody/takeover.ts）: 審査員とデモ事業所はデモの登録だけ、ほかの事業所はそれ以外だけ（一覧・引受とも）

## 問い

- 前の版のスマホのセッションで li が無い物は iat で比べる。リンクを開いた時刻がリンクの時刻より前（時計の差）だった物は通らなくなる（開き直せば通る）。気になるなら li の無い物は版だけで通す形に戻せる（戻しの生き返りは残る）
- 「ID 不可」でも、その ID が通らないことは分かる（login_id を全事業所で 1 つに保つ限り隠しきれない）。事業所ごとの ID にするなら、ログインの画面に事業所を選ぶ欄が要る
- 審査員の 1 日 5 本は審査員みんなで分ける。審査の日に審査員が多いと、昼に「本日上限」になりうる
