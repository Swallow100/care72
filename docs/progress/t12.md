## 部品の使い方（T13 へ）

担当一覧の行の詳細に置く。読み込みは `lib/classify/view.ts`（ブラウザでも読める）。`lib/classify/index.ts` はサーバーの物（store）も出すので、client の部品からは view・labels を直接 import する。

```tsx
import { Classification } from "@/components/list/Classification";
import { CLASSIFY_COLUMNS, classViewOf, type SignalClassFields } from "@/lib/classify/view";

// 信号を読む SELECT に CLASSIFY_COLUMNS を足す（transcript・recording_key・classes・classified_by・ai_*）
const row = await db.prepare(`SELECT id, ${CLASSIFY_COLUMNS} FROM signals WHERE id = ?1`).bind(id).first<SignalClassFields & { id: string }>();

<Classification
  signalId={row.id}
  view={classViewOf(row)}
  editable={principal.role === "care_manager"}   // 直す口（API もケアマネ以外は 403）
  inset                                           // 地が panel2 の区分の中に置くとき（ボタンを白に）
  onSaved={() => router.refresh()}                // 直すと lib/triage の理由と並びが変わるので一覧を読み直す
/>
```

- 1 つの信号ごとに 1 つ。どの信号を出すか（いちばん新しい赤、録音のある物）は T13 が決める。事業所の壁を通した 1 つを読むなら `loadClassView(db, officeId, signalId)`（lib/classify/store.ts、サーバー）
- 直しの API は `POST /api/signals/<信号の id>/classes`、本文 `{ "classes": ["injury"] }`、返りは `{ ok, changed, view }`

## 決めた所（見直してほしい）

- 信号の表に列を足した（`ai_*`）。経過の payload に埋めると、行の詳細を出すたびに経過を読むことになるため。配信前なので 0001 を直した（docs/DECISIONS.md「配信と守り」）。配信の D1 は作り直しが要る
- 呼ぶ所は `/api/recordings`（文字起こしはここで届く。`/api/signals` の信号は 4 問の答えだけで文が無い）。T12.md の「app/api/signals（分類の呼び出し）」と違う。直しの API は app/api/signals/ の下
- 本人のスマホへの応答を待たせず、`waitUntil` で走らせる。分類の待ちを 12 秒にした（再試行込みで 30 秒の内）
- 文字起こしが無い録音（音声だけ）は Haiku を呼ばずに「分類なし 文字なし」。Haiku は音を聞けず、黙っている・うめき声は不明と決めてあり（docs/DECISIONS.md「AI の使い所」）、1 日の上限を減らさない。ケアマネは聞いて人の分類を付けられる
- Haiku に渡すのは伏せた文字起こしと「答えと音」の文（「けが 未回答・自宅 未回答・動けない・薬 あり。録音 30 秒」の決まった言葉）だけ。台帳は鍵を作るためだけに読み、渡さない。答えの文も同じ `pseudonymizeText` を通す（印の無い物を作らない）
- 答えは文字起こしを読む助けで、文字起こしに手がかりの無い分類は選ばせない（指示の 5）。ボタンの「けが」「動けない」は lib/triage がそのまま使うので、分類で重ねなくても理由に出る
- 分類の値は英字の id（injury など。表・型と同じ）で返させ、指示に日本語の意味を添えた。zod は型だけ確かめ、確信の範囲と引用の長さはコードで直す（範囲の外の 1 つで呼び出し全部を失わないように）。5 つの外の値は形の違い（分類なし 形式相違）
- 引用は伏せた文のまま書く（（氏名）が入ることがある）。元の名前に戻すと元の文に無い言葉になるので戻さない。伏せた所の無い引用は元の言葉と同じ
- Claude が「不明」と答えた物は `classes` が `["unknown"]`・classified_by claude（分類した）。失敗・未設定・上限は `classes` が空で `ai_error`（分類なし）
- 直せるのはケアマネの役だけ（本人・家族は save を持つが 403、行政・医療班も 403）。同じ分類をもう一度付けても何も書かない
- Claude の分類の経過の行は kind note・payload の source classify・書き手は自動。本文に「録音の分類（AI）」と書いて印にした（lib/person.ts の経過の AI の印は入れる欄だけで、触らないため）。人の直しは kind note・source class_edit
- 言葉は lib/classify/labels.ts に置いた（lib/labels.ts は T13 が同時に触るので）。分類なしの理由は 文字なし・AI 未設定・上限到達・AI 不可・形式相違・AI 失敗・送信不可（入れる欄と同じ言葉）
