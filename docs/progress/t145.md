## 決めた所

- 区分は今のコードのまま組を作った（頼みの例は例として読んだ）。住まい（basic.housing.*）は台帳でも読む側でも避難の区分なので、基本でなく避難の「住居」。心身（介護度・歩行・感覚・認知）は基本の区分の中の組。氏名は面の上の段で、面の編集には無い
- 介護度・手帳・難病は「認定」の 1 組にした（要介護認定・障害者手帳・指定難病。介護度だけの見出しの下に手帳と難病を置くと見出しと中身がずれる）
- 夜間は組にしなかった。夜間に来られるかは連絡先ごとの欄（夜間 可・不可・未確認）で、組にすると同じ連絡先を 2 か所に出すことになる。読む側の「夜間支援」の行（people.night_supporter）の鍵は支援者の組に置いた
- 合わせた 1 行の「心身」（care）と、連絡先の部分の場所（contacts.<id>.<所>）は組に入れない（部分の欄と連絡先の種類で決まる）。テストはこの 2 つだけを外して、読む側の欄を全部覆うかを見る
- 「受診先」（かかりつけ・透析先）は読む側の医療の面の行だけの組。連絡先を直すのは関係者の面の「関係先」なので、面の編集の医療には出さない
- 見出しは 2〜4 字にしたが、薬（1 字）・ハザード（片仮名）は今の画面の言葉のままにした（読む側の行の名前と同じ）
- 目次は横に並べ、狭い幅でも同じ（折り返す）。組の数が多くても 1〜2 行
- 今の組は「入力の欄に入った組」と「目次で飛んだ組」。送っただけ（見えている組）では変えない（どこを直しているかを示すため）
- 面の下を灰色にするのに、面の余白（PersonView の SectionPanel の px-3 py-2.5）の分だけ外へ出した。PersonView は触っていない（余白を変えるときは SectionEdit の form の -mx-3 -mb-2.5 も直す。コメントに書いた）
- 送る変更（lib/intake/edit.ts の editChanges）・保存・取消・外す・戻す・値確認・確認・順番重複・本人重複・未入力の止め・競合・未確認の数は変えていない。並びと見た目だけ
