## Claude の使い所

## 手元での確かめ（--local だけ）

- `npm run db:fresh` の手元の D1 に new-office.ts の試しの事業所を `wrangler d1 execute DB --local --command="$(cat …)"` で入れ、`next dev`（port 3197）に管理者で入った。headless Chrome（リポジトリの node_modules の puppeteer-core）で撮った絵は作業者の一時のフォルダだけに置き、repo には入れていない
- /office を 375・768・1280、ライトと `<html data-theme="dark">` の 6 つ: 「準備 残り 3」に 地域 未設定・ケアマネ追加（後で）・利用者追加。どれも横のはみ出し 0。375 は行が見出しの下に折れる
- / を同じ 6 つ: 「なし」の横に「利用者追加」
- 1 つずつ済ませる: 地域を保存 → 地域の行が消える、「後で」を押す → ケアマネの行が消える（cookie を消すと戻る）、ケアマネ追加 → ケアマネの行が消える、利用者追加 → 欄ごと出ない。担当一覧は 1 人になり「なし」も出ない

## 決めた所

- ケアマネの行は「後で」で閉じる形にした（1 人で回す事業所でも、全部済めば欄ごと消えるように）。印は端末の cookie で、表に列を足さない。別の端末・ほかの事業所では出る
- 担当の行は、担当（care_manager_id）が無い人だけを数える。停止したケアマネが担当の人は担当の表に「（名前） 停止」と出るので数えない（利用者追加は担当が要るので、今の画面からは担当の無い人はふつうできない。行は来た時だけ出る）
- 利用者の行は事業所の一覧にいる人で数える（管理者自身の担当が 0 でも、事業所にほかの人の担当がいれば出さない）
- 見る人は principal の admin（ケアマネの役）。lib/office/scope.ts の officeActor.admin は審査員のケアマネの役にも真なので使わない
- 担当一覧の「利用者追加」は、絞る前の担当が 0 人のときだけ（絞込で 0 人は「なし」だけ）
- 触るファイルの外: lib/office/http-paths.ts に CARE_MANAGERS_ANCHOR の 1 行
