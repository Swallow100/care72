## 決めた所（docs/DECISIONS.md「本人・家族のスマホと聞き取り」）

## 問い（設計の側へ。1〜5 は 11/4 03:1x に答えをもらった）

1. リンクを開いた端末が前にケアマネでログインしていても、本人・家族のセッションに替える（今の cookie を上書き）。ケアマネが自分の端末で試しに開くとログアウトされた形になる。開く前に「今のログインを替える」確認を挟むか、このままでよいか
2. 一覧から外して戻したとき、前に渡したリンクがまた通る（版は変わらない）。外すときに版も上げる（全部無効にする）方がよいか。外す・戻すは lib/office/people.ts の setUnlisted で、この作業の区画の外なので触っていない
3. 無効の頁の「無効」の印は StateTag の md（本文の大きさ）。本人・家族の画面の大きな字の決まりに合わせて大きくするか
4. 同意の行の記録した人に、作った人（ケアマネ・医療班）を入れた。「未確認」の行に記録した人が付くのは画面には出ない（同意の区分は未確認のときに日付・人を出さない）が、表を読む人には「誰が作った人の未確認か」になる。recorded_by を NULL にする方がよいか
5. リンクのセッションでヘッダーのログアウトを押すと /login に落ち、本人・家族はリンクを開き直すしかない（ログインの無い役）。本人・家族の画面ではログアウトを隠すか、/login でなく無効の頁と同じ 1 画面に送るか。components/AppHeader.tsx と app/api/auth/logout は区画の外なので触っていない
