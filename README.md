# ケア72（Care72）

在宅の高齢者を災害のとき誰がどう助けるかを決める個別避難計画は、全国で 15.1% しかできていません。書けるのは利用者を知るケアマネジャーですが、書く時間がありません。

ケア72 は、ケアマネジャーが話す・打つ・書類の写真を入れるだけで計画を下書きし、災害後 72 時間をシミュレーションする訓練で試し、発災時には安否の色と連絡の順を出して、薬と介護の情報を避難所の医療班へ渡す道具です。

- 入口: https://care72.app 。PC（幅 1280 以上）で開いてください。Windows 11 の Chrome で動作を確かめています。ID とパスワードは提出フォームに書きました
- 利用者は全員架空です
- 安否の色と連絡の順はコードのルールの表（[docs/TRIAGE.md](docs/TRIAGE.md)）が出します。AI は決めません
- 病名を言い切らず、薬の量を言わず、医療の助言をしません

## 触り方

ログインのあとの手順は [docs/GUIDE.md](docs/GUIDE.md) にあります。

## 課題

- 作成率は全国 15.1%（対象 670万人）。市区町村 1,741 のうち 911 が 20% 以下（[共同通信 2026-10-04](https://kumanichi.com/articles/2042908)）
- 能登半島地震の死者 755 人のうち関連死が 527 人（[熊本日日新聞 2026-08](https://kumanichi.com/articles/2027266)）
- 輪島では避難所の薬の情報が手書きメモで用法用量が欠け、一包化して届けた薬に該当する患者がおらず返却された（[厚生労働省](https://www.mhlw.go.jp/content/001203369.pdf)）

### 誰のためか

- **作者**: 医学部で学ぶ学生です。家族がケアマネジャーで、その仕事を近くで見てきました。現場の内側にいるのは協力してくれるケアマネジャーで、作者ではありません
- **見えた足りないもの**: 利用者のことを市の様式に起こす時間と、避難所に着いた最初の 72 時間に薬と介護の情報を医療班へ届ける道
- **使い続ける人**: 居宅介護支援事業所のケアマネジャーと管理者が、平時に計画書を市へ出し、BCP の訓練の記録を残し、発災した日は同じ画面で担当の安否を整理します。避難所の医療班は受入・搬送・退所を残し、行政は本人のページに経過を書き足します

## Claude をどこに使い、どこに使わないか

| 所 | モデル | すること |
| --- | --- | --- |
| アプリ内情報入力 | Sonnet 5.5（写真・PDF は Opus 5.5） | アプリ内記録の項目に分け、空欄を問い返す。保存は人 |
| 様式の読み取り | Opus 5.5 | 市町村ごとの様式から欄の対応表を作る。人が確かめてから使う |
| 書類の整合性審査 | Sonnet 5.5 | 書類と入力された項目を見比べて、違う欄を挙げる |
| 訓練の本人役（20 人まで、デモは 10 人） | Haiku 5.5 | 1 人 1 体で、押す・話す・電話する |
| 訓練の個別講評 | Haiku 5.5 | 参加者 1 人ずつの講評を、訓練の間に作る（下書き） |
| 訓練の監督・自由対応・全体の講評 | Opus 5.5 | 出来事を差し込む。自由に書いた手の結果を決める。終わりに全体の講評 |
| 仮想の世界の部屋 | Opus 5.5（Managed Agents） | 72 時間の流れを 1 つの session で持ち続ける。道具のループと記憶が要るのはここだけ |
| 録音の分類・まとめ、声の聞き取り | Haiku 5.5 | 事実に分ける。本人の言葉と並べる。次に聞く 1 文を決める |
| **安否の色・連絡順・119 の案内・医療要約** | **使わない** | コードの表と定型。同じ入力で同じ物が出て、テストで確かめられる |
| 電話で聞いた安否・同意・気象庁の情報 | 使わない | 人の入力と、電文のまま |

AI の分類・まとめ・会話は、色と連絡順に使いません。理由は [docs/DECISIONS.md](docs/DECISIONS.md) の「色と連絡順」「AI の使い所」にあります。声は Gemini TTS です。effort まで含めた表は [docs/CLAUDE_CODE.md](docs/CLAUDE_CODE.md) にあります。

## この道具がしないこと

- 病名を言い切らない・薬の量を言わない・医療の助言をしない。症状を点数にしない。聞くのは事実だけです
- 連絡の順番を AI に決めさせない。条件を理由の 1 行で出し、最後に決めるのはケアマネジャーです
- 自動の電話・自動の 119・災害モードの自動の切替をしない

## 守り

- 氏名・住所・電話は Claude に渡す前に仮名にします（`lib/pseudonym`）。通らない物は型でも実行時でも渡せません
- 写真と PDF は、人が名前などを塗ってから送ります。Claude に渡す入口は `lib/claude/call.ts` の 1 か所です
- 同意は 5 種類で、AI 提供が「不同意」の人にはアプリ内情報入力の AI を使いません
- 開発の側も、ネットに出る wrangler・鍵のファイル・履歴の書き換えをフックで止めています

## Claude Code で何が可能になったか

コードと文書の行は Claude Code が書き、人（作者）は決めることを受け持ちました。

| 数字（`1b5a6b3a`、11/6 23 時台） | 値 |
| --- | --- |
| 期間の始まり → 最初のコードの commit | 11/2 12:30 → 13:08 |
| commit | 2,023（merge 467） |
| merge でない commit の書き手 | Opus 5.5 1,463・Fable 5.1 87・Sonnet 5.5 5・なし 1（GitHub の雛形） |
| PR | 作り直す前 114・作り直したあと 95 |

- **並列**: 1 作業 1 worktree で Opus の作業者を同時に何本も動かし、設計の側が取り込みます
- **別の目**: 書いた本人の文脈を持たない見直し役（`.claude/agents`）が、医療の言葉と画面の決まりを見ます
- **決まりをコードに**: 必ず守る物はフック、手順は Skill、本名を見ない MCP（`tools/mcp/care72-local`）。ルールの表の文書はコードから作ります
- **本物で測って直す**: 偽の返事のテストが通っても、本物では実在の PDF が 14 件中 12 件読めませんでした。ここから評価の台を作りました
- **人の目**: 紙の数字が 94% でも、作者が目で見ると埋まっていませんでした。数え方そのものを足しました（[docs/progress/t133.md](docs/progress/t133.md)）

Next.js・TypeScript・Tailwind、Cloudflare Workers（OpenNext）・D1・R2 で作りました。詳しくは [docs/PROCESS.md](docs/PROCESS.md) と [docs/CLAUDE_CODE.md](docs/CLAUDE_CODE.md)。

**履歴について**: 公開の文書に個人に関わる情報が含まれていたため、11/4 に一度だけ履歴を書き換え、同じ URL でリポジトリを作り直しました。commit の数・日時・順番とコードの変化は元のままです（[docs/PROCESS.md](docs/PROCESS.md) の「公開の履歴」）。キックオフ前の構想は 11/2 12:46 に `docs/SPEC.md` として写しましたが、構想はリポジトリの外に置く形に直し、11/7 に外しました（履歴には残っています）。

## 本運用で確かめること

大会のあと実際の人で使うときに確かめる事です（[docs/SOURCES.md](docs/SOURCES.md) の末にも同じ一覧）。

- 要配慮個人情報（薬・持病・機器。個人情報保護法 2 条 3 項）の同意の流れ: 平時の計画づくりの段階で、本人と家族に、台帳に入れること・発災時の録音・医療班と支援者への提供の範囲の同意を取る形にする
- 仮名化と対応表: Claude には仮名（A さん）と役割名で渡すが、対応表を持つ事業所の側では個人情報のまま（同法 2 条 1 項）。発災時の録音は本人が話すので名前や住所が混ざる。対応表の置き場所と消し方を決める
- 外国にある事業者への提供: Claude（Anthropic）と Gemini（Google）へ送る扱いを、同法 28 条（外国にある第三者への提供）と合わせて確かめる。委託契約・学習に使わない契約の確認も
- ルールの表（医療依存の段と色の行）の監修: 医師・訪問看護師に見てもらい、監修者と版を画面に出す（進めている所）
- 医療機器プログラムに当たらないか: 条件を事実にとどめ症状を点数にしない今の作りが、厚生労働省の医療機器プログラムの事例（問診票をそのまま電子化する物 197 など）の線の内か、相談窓口で確かめる（https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000179749_00004.html）
- 相談窓口: 個人情報は個人情報保護委員会、医療機器プログラムは厚生労働省の窓口。大会のあと実際の人で使う前に

本運用の条件（契約・アカウント・仮名化の限界など）は [docs/GUIDE.md](docs/GUIDE.md) にあります。
