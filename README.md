# ケア72（Care72）

在宅で介護を受ける高齢者を受け持つケアマネジャー（ケアマネ）の道具。災害の最初の 72 時間に、ケアマネが知っている利用者のことを、本人・家族・避難所の医療班に届ける。計画 → 訓練 → 発災時。
入口は https://care72.app 。どの画面もログインが要る。審査員の ID とパスワードは提出書類に書いた（ここには書かない）。
ログインしたら役を選ぶ: ケアマネ（担当一覧）・医療班（受入一覧）・本人スマホ（山田 ハナ）・家族スマホ（山田の娘）。選び直しは右上の「役変更」。
最初に見るなら、ケアマネの役で「訓練」→「10 分版」（4 刻みで 72 時間）と、本人スマホで赤「無事じゃない」を押してからケアマネの担当一覧に戻る流れ。
利用者は全員架空。この道具は診断・用量・医療助言をしない。安否の色と連絡の順番はコードに書いたルールの表（lib/triage、人が読める形は [docs/TRIAGE.md](docs/TRIAGE.md)）で出し、AI は決めない。

このリポジトリは Built with Claude: Japan 2026 の期間中（2026-11-02 12:30 JST 以降）に作った。設計はキックオフ前に文書で行い、[docs/SPEC.md](docs/SPEC.md) に写した。コードと文書の行は Claude Code が書き、人は決めることを受け持った（下の「Claude Code で何が可能になったか」）。

## 作者と、足りないもの

- 作者は医学部で学ぶ学生。家族がケアマネで、その仕事を近くで見てきた。現場の内側にいるのは協力してくれるケアマネで、作者ではない
- 作者の受け持ちは、速く作って出すことと、医療班に渡す要約の医学的な確かめ
- 見えた足りないもの: ケアマネは担当の利用者のことを全部知っているが、市の様式に起こす時間が無い。そして避難所に着いた最初の 72 時間に、薬と介護の情報が医療班の手元に無い

根拠（出典は [docs/KNOWN_UNKNOWN.md](docs/KNOWN_UNKNOWN.md) の Known）:

- 個別避難計画の作成率は全国 15.1%（対象 670万人）。市区町村 1,741 のうち 911 が 20% 以下（[共同通信 2026-10-04](https://kumanichi.com/articles/2042908)）
- 能登半島地震の死者 755 人のうち関連死 527 人。直接死 228 人の 2 倍以上（[熊本日日新聞 2026-08](https://kumanichi.com/articles/2027266)）
- 輪島では避難所の薬の情報が手書きメモで用法用量が欠け、一包化して届けた薬に該当する患者がおらず返却された（[厚生労働省](https://www.mhlw.go.jp/content/001203369.pdf)）
- ケアマネの参画は国の先進モデル。別府市・兵庫県では計画 1 件ごとに報酬を払う（[厚生労働省](https://www.mhlw.go.jp/content/12300000/000750360.pdf)）

誰が、どんな場面で使い続けるか: 居宅介護支援事業所のケアマネと管理者が、平時に台帳から計画書を作って市へ出し、事業所の BCP の訓練を回して記録を残し（訓練記録の紙面）、発災した日は同じ画面で担当の安否を整理する。避難所の医療班と行政は、本人のページを開いて経過を書き足す。

## 触り方

https://care72.app 。ID とパスワードは提出書類にある。利用者は架空の 10 人で、「デモ事業所」が開く。デモ事業所は大雨の最中（警戒レベル 4、浸水 3 m の町で停電）。担当一覧の先頭は至急の山田（録音の文字起こしと AI の分類つき）。

訓練に出る 10 人は AI が演じる架空の人で、元の記録も作った例（実在の利用者の記録は使っていない）。訓練の画面では名前のそばに「架空」の印が付く。

### 1. ログインと役

1. https://care72.app で ID とパスワードを入れて「ログイン」
2. 役を選ぶ: ケアマネ（山本の担当一覧）・医療班・本人スマホ（山田 ハナ）・家族スマホ（山田の娘）
3. 選び直しは右上の「役変更」

### 2. 本人のスマホ

1. 「役変更」→「本人スマホ」（大きな字と赤緑の 2 ボタン。スマホの幅で見るとそのまま）
2. 赤「無事じゃない」か緑「無事」を押す。赤のあとは 1 画面 1 問で事実を聞く（最初に「AI が聞いています」を声と文字で）。押せなければ同じ問いを声で読む。録音も送れる。赤のあとの画面にはいつも「命が危ないと感じたら、すぐ119番へ」
3. 「役変更」→「ケアマネ」で担当一覧に戻ると、押した色と答えが並びに入っている（家族スマホも同じ）

### 3. 訓練

1. ケアマネの役で上の「訓練」→「10 分版」（0・3・12・72 時間の 4 刻み）。ほかに「大雨の想定」「地震の想定」「仮想」
2. 「進める」か「早送り」。10 人の本人役が赤緑を押し、電話をかけてくる。着信に出ると、本人役が声で話す
3. 左の表の順に、電話・訪問などの手を打つ
4. 終わると、機械が数えた数字と、AI の講評が出る。終わった訓練は「再生」で刻みごとに見られ、訓練記録は紙面で印刷できる
5. 「仮想」は、AI が架空の街の出来事を自由に進める訓練（架空の人と街。画面の上にそう出る）

### 4. 計画と印刷

- 担当一覧で名前を押すと本人のページ。右の入れる欄に文字を書くか、写真・PDF を選ぶと、AI が台帳の項目に分け、空欄を 1 問ずつ聞く。写真・PDF は送る前に、写った名前・住所・電話を指で塗って隠す。保存するのは人
- 本人のページの書類の行の「印刷」で、計画書（松山市の様式）・本人の 1 枚・医療要約・QR がすぐ印刷の画面になる
- 上の「様式」で様式 9（災害時利用者一覧表）

### 5. 医療班

- 「役変更」→「医療班」で受入一覧。QR・検索で本人のページを開き、受け入れて経過を書き足す。台帳に無い人もその場で作れる

### 6. 最初に戻す

- 上の「事業所」→「最初に戻す」→ 確認の欄で「最初に戻す」。毎日 4:00 にも自動で戻る
- AI は 1 日の上限がある（デモ事業所の全員で数える）。超えた日の訓練は終わった記録の「再生」だけ
- ログインを 15 分に 10 回間違えると 15 分待つ

## できること

https://care72.app（d90de01）で動いている物だけを書いた。

### 計画（平時）

- 本人のページ（台帳）: 本人・薬・病気・機器・関係・行動・特記を区分ごとに。医療の印に時計の残りを添える（「酸素 2h」）。各欄は「編集」で手で直せる
- 入れる欄: 文字・写真・PDF・小さなマイクから、AI が台帳の項目に分け、空欄を問い返す。写真・PDF は送る前に人が塗って隠す
- 様式 2 つ: 松山市の計画書（欄の名前と順を元の様式と照らしてテストで固定）と内閣府の様式例（元の PDF とはまだ照らしていないので、画面の名前に「例・未照合」）。ほかの市町村の様式は写真・PDF を AI が読み、ケアマネが確かめた対応表で差し込む
- 本人の 1 枚（やさしい日本語とふりがな、裏に医療要約と QR）、医療要約（災害診療記録2018 の順に並べ替えるだけ。医師が書く欄は空欄）、様式 9（BCP の災害時利用者一覧表と市町村への報告の下書き）、医療班が読む期限つきの QR

### 訓練

- 10 分版（4 刻み）・大雨の想定・地震の想定（12 刻みで 72 時間）・仮想モード（AI の世界の部屋が架空の街の出来事を進める）
- 本人役 10 人を AI が演じ、赤緑を押し、電話をかけてくる。着信は声で鳴る。監督の AI が停電・道路の寸断などを差し込む
- ケアマネは発災時と同じ表で手を打つ（電話・訪問・訪問依頼・受入依頼・行政報告ほか）。表の色は発災時と同じルールの表で付く
- 終わると機械が数える（順番の一致・条件に達した人・様式 9 の空欄・報告の遅れ）。講評は AI が 1 回だけ書く。訓練記録の紙面

### 発災時

- 災害モードの切替と、災害の情報（停電の地区など）の入力
- 本人・家族のスマホ: 赤緑の 2 ボタン → 1 画面 1 問の聞き取り（押せなければ声で）→ 録音。119 の固定の 1 行
- 担当一覧: 色（緑 無事・赤 至急・黄 要確認・灰 不明）と連絡順に並び、理由の 1 行が付く。行の詳細に録音・文字起こし・聞き取りの欄（AI が本人の言葉を写した物に AI の印）。電話番号を出し、かけるのはケアマネ
- 医療班・行政の受入一覧: QR・検索・避難所に来た人の受入、台帳に無い人の最小の記録、経過の書き足し
- 右の面の地図（国土地理院のタイルとハザード、全画面と拡大）。雨雲・震度のデモの絵はデモ事業所だけ
- 事業所の画面に気象庁の警報・注意報と地震（防災情報 XML を Workers が 5 分ごとに 1 か所で取って写す。市町村・正式な名前・発表時刻のまま、住所の市が同じ利用者の数。災害モードは自動で切り替えず「切替」を勧めるだけ）。本物の事業所の地図には気象庁の雨雲を加工せず重ねられる（旗 JMA_NOWCAST、既定は off）

## Claude をどこに使い、どこに使わないか

| 所 | Claude | すること |
| --- | --- | --- |
| 入れる欄（文字・写真・PDF → 台帳の項目、問い返し） | Sonnet 5.5 | 項目に分けて変更点を出す。保存は人。画面に AI の印 |
| 様式の読み取り（写真・PDF → 欄の対応表） | Opus 5.5 | 欄の対応表を作る。ケアマネが確かめてから使う |
| 録音の分類と聞き取りの欄 | Haiku 5.5 | 「けが・動けない・水が来た・機器が止まった・不明」に分け、本人の言葉を欄にそのまま写す。色と連絡順には使わない |
| 訓練の本人役 10 人 | Haiku 5.5 | 1 人 1 体、刻みごとに押す・話す・電話する |
| 訓練の監督・講評 | Opus 5.5 | 出来事の差し込み。終わりに講評を 1 回 |
| 仮想モードの世界の部屋 | Opus 5.5（Managed Agents） | 1 訓練 1 session で架空の街の 72 時間を持ち続ける。落ちたらその刻みだけ 1 回呼びに戻る |
| 着信の声 | Gemini TTS | 着信の本人役の言葉を声にする |
| 安否の色・連絡順・119 の案内・医療要約・様式 | 使わない | コードの表と定型。同じ入力で同じ物が出て、テストで確かめられる |
| 気象庁の警報・地震・雨雲 | 使わない | 電文の名前・市町村・時刻のまま並べ、画像は加工しない。色と連絡順の入力にもしない |

Messages API を呼ぶ所は lib/claude/call.ts の askJson の 1 か所で、仮名化した物（型 `ForClaude`）しか渡せない。返事は形を検査し、画面に AI の印を付ける。世界の部屋にも仮名化した文だけを送り、同じ 1 日の上限で数える。

## この道具がしないこと

- 診断・用量・医療助言をしない。症状を点数にしない。聞くのは事実だけ（人工呼吸器・停電・水が来た・挟まれている）
- 連絡の順番を AI に決めさせない。色と連絡順はルールの表で出し、どの条件で決まったかを理由の 1 行で出す。最後に決めるのはケアマネ
- 自動の電話・自動の 119 はしない。電話は番号を出すまでで、かけるのはケアマネ。119 の案内は AI の出力や話の中身で出し分けない固定の文
- 本物の人のデータを使わない。利用者は全員架空

## 守り

- 鍵は .dev.vars（手元。.dev.vars.example は項目だけ）と Cloudflare の secret だけ。.env・.dev.vars は commit しない。GitHub の secret scanning と Push protection を入れている
- 個人の情報は Claude に渡す前に仮名化する（lib/pseudonym。A さん・支援者 1）。仮名化を通らない物は型でも実行時でも Claude に渡せない。写真・PDF は送る前に人が塗って隠す
- AI（Claude と Gemini TTS）の呼び出しは事業所ごとに 1 日の上限（既定 200 回）。超えたらその日は呼ばない
- どの画面もログインが要る。ログインを 15 分に 10 回間違えると 15 分待つ
- 入れる欄のマイクは Web Speech で、ブラウザが音声を外部の認識サービスに送る物。本運用で使うかは事業所の判断
- 開発の側も、ネットに出る wrangler・鍵のファイル・履歴の書き換えをフックで止めている（docs/CLAUDE_CODE.md）

### 本運用で確かめること

大会のあと実際の人で使うときに確かめる事（アドバイザーの返事。docs/SOURCES.md の末にも同じ一覧）。

- 要配慮個人情報（薬・持病・機器。個人情報保護法 2 条 3 項）の同意の流れ: 平時の計画づくりの段階で、本人と家族に、台帳に入れること・発災時の録音・医療班と支援者への提供の範囲の同意を取る形にする
- 仮名化と対応表: Claude には仮名（A さん）と役割名で渡すが、対応表を持つ事業所の側では個人情報のまま（同法 2 条 1 項）。発災時の録音は本人が話すので名前や住所が混ざる。対応表の置き場所と消し方を決める
- 外国にある事業者への提供: Claude（Anthropic）と Gemini（Google）へ送る扱いを、同法 28 条（外国にある第三者への提供）と合わせて確かめる。委託契約・学習に使わない契約の確認も
- ルールの表（医療依存の段と色の行）の監修: 医師・訪問看護師に見てもらい、監修者と版を画面に出す（11/3 16:0x 確定。進めている所）
- 医療機器プログラムに当たらないか: 条件を事実にとどめ症状を点数にしない今の作りが、厚生労働省の医療機器プログラムの事例（問診票をそのまま電子化する物 197 など）の線の内か、相談窓口で確かめる（https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/0000179749_00004.html）
- 相談窓口: 個人情報は個人情報保護委員会、医療機器プログラムは厚生労働省の窓口。大会のあと実際の人で使う前に

## 本運用の条件

大会のあと実際の利用者で使うときに満たす物。

- 事業所との委託契約（事業所から AI の提供者へ渡すのは委託。委託先の監督と安全管理が要る）
- API の入力を学習に使わない契約と、データ保持なし
- 事業所内の利用ルール
- 電気通信事業法の届出が要るかの確認（総務省の電気通信事業参入マニュアル追補版で。届出の義務は運営する人に掛かる）
- 本人・家族の入口はケアマネが出すリンク（期限 180 日、再発行で前の物は全部無効）。リンクを持つ人は本人・家族として安否を送れるので、渡す相手と渡し方は事業所が決める
- 上の「本運用で確かめること」の同意・仮名化・外国の事業者・表の監修
- 端末の写し: 通信なしで開く担当一覧・本人のページ・本人の 1 枚・本人と家族のスマホの最後の写し（名前・連絡先が入る）と、送れなかった通話の記録は、その端末のブラウザの中だけに残り外に送らない。写しはログアウト・ログイン・役の切替・スマホ入口のリンクで消える。送れていない記録があるときのログアウトは送信待ちか破棄かを選ぶ。共用の端末やなくした端末の扱いを事業所のルールに入れる

## 使った資料と方法

使った物だけ書く。

- 仕様の言語化（セッション①「Known / Unknown」）: 分かっていること・分かっていないこと・決めて進むこと・確かめ方を [docs/KNOWN_UNKNOWN.md](docs/KNOWN_UNKNOWN.md) に、仕様書の未決と期間中の判断に対応させた
- Claude Code: 設計（Fable）と実装（Opus のサブエージェント）の分担、作業ごとの brief、テスト先行、フックで守りを強制、Skill で手順を固定、読むだけの見直し役（.claude/agents）、手元の D1 を仮名で読む MCP。CLAUDE.md に守ること・画面の決まり。数字と commit の hash は [docs/CLAUDE_CODE.md](docs/CLAUDE_CODE.md)
- [Claude Code のベストプラクティス](https://code.claude.com/docs/en/best-practices): 「Deterministic and non-deterministic instructions」「Enforce steps with hooks」→ 必ず守る物（ネットに出る wrangler・鍵のファイル・履歴の書き換え）はフック（tools/hooks）、目安は CLAUDE.md。「Put team procedures in skills」→ .claude/skills。「Give Claude a check to run」→ テストを先に書き、.ts を書いたらフックが型の検査。「Know what subagents cost」→ 見直し役は読むだけの道具で、ペルソナの確かめは haiku。「Connect the tools Claude needs」→ MCP の care72-local。「Run sessions in parallel」→ worktree と branch で 2 つのアカウント
- [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents): 「Workflow: Routing」→ 用途ごとのモデル（分類は Haiku、様式の読み取りは Opus。lib/claude/models.ts）と、Skill の care72-review が変えたファイルで見直し役を選ぶ形。「Workflow: Parallelization」の sectioning → 3 つの見直し役を並べて走らせる。「Workflow: Orchestrator-workers」→ 訓練の Opus の監督と 10 体の Haiku の本人役。「Agents」の人の確認 → 発災時は Claude を分類と写すだけにし、色と連絡の順番はルールの表とケアマネ。「Appendix 2: Prompt engineering your tools」の poka-yoke → 仮名化を通らない物は型で Claude に渡せない（lib/pseudonym の ForClaude）
- [Effective Context Engineering for AI Agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): 「Sub-agent architectures」→ 見直し役は自分の文脈で読み、表だけを返す。「Structured note-taking」→ docs/tasks の brief と進みの記録（docs/PROGRESS.md・docs/progress）でセッションをまたぐ。「Context retrieval and agentic search」の just in time → MCP は一覧で仮名と id だけを返し、台帳は person で 1 人ずつ読む
- Managed Agents: 仮想モードの世界の部屋だけに使う（lib/drill/world-room.ts）。道具のループと前の刻みの記憶が要るのは世界だけだから。録音の分類・本人役・固定の想定の監督・講評は、1 回の入力で答えが決まるので Messages API の 1 回呼び（askJson）のまま。部屋が使えないときは、その刻みだけ 1 回呼びに戻る
- 出典の登録簿: 根拠は lib/sources の一覧だけから引く（[docs/SOURCES.md](docs/SOURCES.md)。コードから作り、テストで一致を守る）
- 気象庁の情報（利用条件は [docs/progress/jma-terms-20261104.md](docs/progress/jma-terms-20261104.md)）: 出典：気象庁ホームページ（https://www.jma.go.jp/bosai/warning/）、気象庁防災情報XML。雨雲：気象庁ホームページ（https://www.jma.go.jp/bosai/nowc/）／背景：地理院タイル。気象庁の情報をもとにケア72が編集して表示しています（事業所と利用者の市町村の物だけを選んで並べる）。編集の責任はケア72にあります。最新の情報は気象庁ホームページで確認してください
